## 0. 结论

没有发现 P0（未授权即可利用的数据泄露）。**有 2 个 P1 必须在 M6 之前修**，另有 16 个 P2、若干 P3。
整体判断：核心不变量（门控隐藏正文单点读取、可见性在取数前过滤、积分只经 `applyPoints`、令牌只存哈希、SQL 全参数化、路径穿越双重守卫）经得起审查；
问题集中在三类——**约定与实现之间有缝**（时区、`NOW()`）、**M5.5 只做了读侧，写侧未到的假设**（附件、首帖状态、楼层分页、改价），以及**约定没有守卫测试**（硬约定 9、`gateConditions`）。

## 1. P1：M6 之前必须修

### P1-1　数据库会话时区是 UTC，`NOW()` 与「库内一律北京墙面时间」约定矛盾【实测】

- **位置**：`packages/db/src/client.ts`（`timezone: "+08:00"` 只影响客户端序列化，不会 `SET time_zone`）、`docker/qysub-next/compose.yaml`（未配 `TZ` 或 `--default-time-zone`）；
  受影响的 SQL：`authz/restrictions.ts:8`、`authz/subject.ts:32`、`authz/service.ts:104`、`gates/unlock.ts:160`、`points/apply.ts:140`、`audit.ts:46`、`auth/session.ts`、`auth/tokens.ts` 等全部 `NOW()` 用法。
- **实测**：用应用同一套连接配置查询，`SELECT NOW()` 返回 `05:09:55`，同一时刻北京时间是 `13:09:55`；`@@session.time_zone=SYSTEM`，`@@system_time_zone=UTC`。
  `restrictions.ts:5` 的注释断言「NOW() 与之同口径」，这个假设是错的。
- **后果**：
  - 封禁 / 禁言 / 角色过期的比较一侧是北京时间（迁移与管理端写入），另一侧是 UTC 的 `NOW()`：到期时间晚 8 小时才失效；`starts_at=北京现在` 的新限制要等 8 小时才生效。版主角色同理多活 8 小时。
  - 台账、解锁时间、审计、`last_login_at` 写入的是 UTC，页面按 +08:00 解析后显示早 8 小时（`gate-block.tsx` 直接显示原串）。
  - 同一个库里 `event_log`、`module_state` 用 `nowBeijingWallTime()`，等于有两套时间。
- **为什么没被测试发现**：测试在同一台 MySQL 上自洽（两侧都用 `NOW()`）；E2E 的封禁夹具用远古日期。
- **修法**：连接池 `connection` 事件里执行 `SET time_zone='+08:00'`（这是唯一能同时覆盖本地 compose 和 GitHub Actions 服务容器的做法，服务容器不能传 `--default-time-zone`）；compose 另加 `--default-time-zone=+08:00`；
  `db:verify` 增加会话时区断言；补一条「`SELECT NOW()` 与 `nowBeijingWallTime()` 差 < 2s」的集成测试。**现在上线前修，无需数据订正**（站点尚未运行）；开发库里已写入的 UTC 时间戳可以丢弃。

### P1-2　付费 / 回复可见门控的附件不受门控保护【读码 + 真实数据核实】

- **位置**：`queries/posts.ts:116`（`getAttachments` 只按 `post_id` 取，不看 `has_gate`）、`t/[tid]/page.tsx:70,79-107`、`file-serving.ts:78`（附件鉴权只看帖子可见 + `attachment.download`）。
- **场景**：门控只拆分了 `hidden_md`。任何持有 `attachment.download` 的会员都能看到并下载门控帖的全部附件；图片类附件连这个权限都不需要。
- **规模**：迁移库里 **63 个门控帖共带 130 个附件**，是青翼真实内容上的实际影响（字幕组的付费内容常以附件形式提供）。
- **设计缺口**：`DESIGN-MODEL.md` §5 和 `GATES.md` 都没有定义「附件与门控的关系」。这是设计遗漏，不只是实现问题。
- **修法（需要先定设计）**：二选一——(a) 附件挂在门控上：`attachments` 增加可空 `gate_id`，列表与 `/files` 都复用 `evaluateGate`；(b) 门控帖的所有附件整体受该帖「任一门控开放」约束。建议 (a)，粒度更细，M6 上传时让作者选择附件放进哪个门控。

## 3. 设计与抽象层面的观察

这些不是缺陷，是 M6 开始前值得定下来的点。

1. **Server Action 缺统一骨架**。现在每个 action 自己写：`import "@/modules"`、取当前主体、频控、手写 `Number(formData.get(...))`、错误到 `redirect` 的映射。`admin/actions.ts` 的 `requireAdmin` 与 `gates.ts` 的内联登录检查是两套写法，没有输入校验库。
   M6 会一次加入发帖、回帖、编辑、上传、审核等十几个 action，建议先定一个薄的 `defineAction`（强制求值模块注册表、统一取主体 / 登录要求、统一频控策略表、统一输入校验与错误映射），把第 2.1 节的 #5 一并解决。
2. **页面承载了鉴权决定**。`t/[tid]/page.tsx` 里 `canDownload`、附件渲染、门控批量解析都在页面里组装，`app/` 共 2195 行零单测，只靠 E2E 覆盖。建议把「主题页数据装配」抽成 `lib/queries` 下的一个可测函数，页面只负责渲染。
3. **分层干净**：`lib` 不反向依赖 `app`；`modules` 只依赖 `lib/datetime` 和 `lib/audit`；守卫测试有 `hidden-md-guard`、`no-direct-points-write`、`dev-only-guard` 三条。缺口是上面说的硬约定 9 与时区。
4. **权限评估器不拦 `kind=section` 与 `isArchived` 的写入**：`forum.write` 在分区或归档版块上返回允许。M6 发帖路径必须另行校验，或把它收进评估器。
5. **`forum.moderate` 的全局授权不含 `restricted` 版块的读权**，所以 `moderatedForumIds` 不是 `readableForumIds` 的子集。查询侧用 AND，安全，但语义反直觉，建议在 `AUTHZ.md` 写明。
6. **用户名只做 trim + 小写**，没有同形字符 / 零宽字符 / RTL 控制符的限制。论坛里「冒充管理员」是现实威胁，M6 之前的注册校验应加上。
7. **`view_count` 目前没有任何写入路径**（页面不递增）。属于 M6 范围，记录在此避免遗漏。
8. **文档漂移**：`POINTS.md` 说积分名默认「青翼币」，代码与测试默认是「积分」；`GATES.md` §7.1 里「开发库 `content_md` 存在截断」已过期；`AUTHZ.md` §6 仍描述 v1 的 `legacy_key`，与 §8 并存易误导。

## 4. P3（摘要）

- **门控 `any` 模式可重复收费**：`unlockGate` 不判断门控是否已因 `reply` 条件开放，脚本直接提交 `gateId` 即可扣款（`unlock.ts`）。扣款前应复用 `evaluateGate`。【待证】
- **积分边界无业务错误**：`delta` 无范围校验，`balance + delta` 越界时是 MySQL 1264 原始错误，到用户那里是 500；作者账户接近上限时 `earn.gate_sale` 失败会让整笔购买一直失败。【待证】
- **手续费浮点误差**：`floor(price * rate)`，`100 × 0.29 = 28.999…`，向下取整得 28，手续费少收 1。费率应改为万分比整数。【实测】
- **会话「滑动续期」只更新 `last_seen_at`，不延长 `expires_at`**（`session.ts:64-72`），实际是固定 30 天，注释与行为不符。【读码】
- **`loadEnablement` 读库失败时 fail-open**（`state.ts:25-28`）：全部模块视为启用，且被请求级缓存。【待证】
- **DDL 未固定字符集与排序规则**：依赖服务器默认值。默认 `_ai_ci` 下 `post_gates.gate_key` 的 `A1` 与 `a1` 在库里冲突，而 `splitSource` 的 `usedKeys` 区分大小写，M6 保存可能撞唯一键报 500。【待证】
- **`bootstrap` 基线授权只在「角色无任何授权行」时写入**：管理员把某内置角色授权清空后重跑会恢复默认；新版本新增的基线权限也不会下发给已部署站点。【待证】
- **`grantRolePermission` 先查后插**：并发重复会抛 `ER_DUP_ENTRY` 而不是 `AdminError`。【待证】
- **`admin.roles` 持有者可给任意角色（含自己）授予任意权限**，与 admin 等价。只有 admin 能授予 `admin.roles`，所以不是外部入口，属于委派提权，建议只允许 admin 授予特权权限点。【读码】
- **`isDevEnv` 是 fail-open**：`NODE_ENV` 不等于 `production` 时 `/api/dev/*` 全开。生产构建实测 404，但部署若漏设环境变量会暴露。
- 登录时不销毁旧会话；`/verify` 用 GET 消费令牌，会被邮件扫描器消耗；`EMAIL_RE` 允许逗号，可借此把验证邮件发到第三方；`?error=` / `?message=` 文案可被伪造；cookie 的 `Secure` 取决于 `APP_URL` 写的是不是 https。
- 游客访问 `/admin` 返回 302 到 `/login`，暴露后台存在；个人页公开封禁理由、积分与统计（统计含受限版块的数据）；`demo-checkin` 槽位向游客暴露最近登录活动；外链图片可泄露观众 IP。

## 5. 已核查且确认没有问题

- **SQL**：运行时代码没有 `sql.raw`，全部参数化。
- **路径穿越**：`/files` 有 `KEY_RE` 与 `resolveStaticPath` 双重守卫；响应头 `nosniff` + `sandbox` CSP；mime 取自数据库；扩展名白名单。
- **XSS**：`dangerouslySetInnerHTML` 只在 `RichContent` 一处且走净化；子代理对 `javascript:`、svg、math、noscript、style 的 mXSS 变体实测均无效（`class` 一项见 P2 #8）。
- **可见性**：首页、版块、主题、回帖、`generateMetadata`、`/files`、门控在取数前过滤，处处一致；越权对外表现为 404 成立。
- **门控**：`hidden_md` 只在 `service.ts` 一处读取，且只有判定开放的门控才取正文；不可见帖子里的门控 `locateGate` 返回 null；失败即封闭（空条件、非法价格、未知类型）。
- **积分**：账户行锁 + 幂等键，余额在锁内校验，未发现双花或负余额；锁序固定；事务内不借第二条连接；事件在提交后派发且重试不重复派发；`IdempotencyConflict` 同时比对用户、渠道、金额。
- **令牌**：邮件令牌与会话令牌均为 256 位随机，库内只存 SHA-256，邮件令牌原子单次消费。
- **重定向**：全部是服务端常量或 `APP_URL`，无开放重定向。
- **Server Action**：均校验身份，Next 默认校验 Origin；后台写操作有 `requireAdmin`。
- **`/api/dev/*`、`/design`**：生产构建返回 404（实测，且有守卫测试）。
- **IP 提取**：取 `X-Forwarded-For` 右数第 N 项，正确。
