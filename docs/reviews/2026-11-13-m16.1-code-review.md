## 二、P1 与整改

### 安全架构路

**A-P1-1 正文插图粘贴上传无并发闸，单一进度契约在真实入口上不成立**
`editor-shell.tsx` 的 `onPasteCapture` 只判 `forumId`，上传期间编辑器仍可交互——**连贴两张截图即并发**：
第二个上传的 reset 清掉第一个进度、两路 onprogress 交错使百分比来回跳、uploadNotice 互相覆盖。
不丢数据但 Step 1 的核心卖点在该路径上失准。
**整改**：`if (imagePending > 0) return;`（与 ImagePicker 的 disabled 同口径串行；服务端并发闸本就 ≤3）。

**A-P1-2 「卸载后不再响应滚动」是永真断言**
`back-to-top.test.tsx` 断言卸载后 className 不变——React 对已卸载组件 setState 本就是 no-op，
**删掉 `removeEventListener` 用例照样绿**，测的是 React 语义而非组件清理。
**整改**：改为 spy `addEventListener`/`removeEventListener`，断言卸载时以**同一函数引用**成对调用。
**已注入回归验证**：临时删掉 cleanup → 该用例变红。

**A-P1-3 「同一容器再次扫描不重复挂监听」同为永真断言**
原用例「移除类后 dispatch load，断言类被加回」——挂 1 个还是 N 个监听结果都一样，区分不了重复挂载。
**整改**：spy `img.addEventListener`，断言两次挂载全程 load/error 各只注册一次。
**已注入回归验证**：删掉**两层**幂等守卫（容器标记 + 图片标记）→ 用例变红；
只删一层仍绿属正确行为（另一层仍守住），据此确认断言钉的是行为而非某一行实现。

**A-P1-4 `lib/pwa/build-version.ts` 零测试 + 「dev」回落静默使版本化失效**
该文件在覆盖率 include（`src/lib/**`）分母内却无任何单测；读不到 BUILD_ID 时静默回落 `dev`，
会让所有部署共用 `?v=dev` → 浏览器不再重装 SW → 离线壳永久停旧，**正是本机制要消灭的故障模式无声复活**。
**整改**：补 5 例单测（读到 trim / 按 distDir 定位 / ENOENT 回落 / 空文件回落 / 回落也缓存）；
两条回落路径统一走告警分支并 `console.warn`，让运维可见。
