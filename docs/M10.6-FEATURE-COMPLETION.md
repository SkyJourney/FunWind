# M10.6 · M11 前功能补全审查（2026-10-27）

> 背景：M10.5 收尾时站长点名两项缺口——**后台没有板块管理（含板块可见性）**、**站点管理没有基础站点配置菜单**；
> 并要求在进入 M11 前全面审查前后台需补充的功能。本文是审查结论与建议排期，**范围以站长裁决为准**。
> 审查口径：以 schema / 路由 / site_settings 实际代码为准（证据随手标注），不把旧站功能默认当作应做。

## 一、结论摘要

- **数据模型普遍先行于管理界面**：forums 策略字段、inviteCodes、notificationPreferences、site_settings 各键都已就位，
  缺的主要是「有表无界面 / 有键无菜单」，不需要动底层模型（少数除外，逐条标注）。
- 建议以 **M10.6（功能补全）** 作为 M11 前置里程碑，切四个批次：**a 板块管理 → b 站点配置+邀请码 → c 账号设置+双轨密码+通知偏好 → d 打磨清账（M10.5 未完成项全量并入，站长指示）**。
- M11 主题选择依赖「全站默认主题」配置项，落点正是本审查的站点配置菜单——先补配置菜单，M11 顺畅。

## 二、站长点名（P0）

### P0-1 板块管理 `/admin/forums`（含可见性）

现状：`forums` 表字段齐备（packages/db/src/schema.ts:199）——`kind`(section/forum)、树形 `parentId/path/depth`、
`sortOrder`、`readPolicy`(inherit/public/members/restricted)、`writePolicy`、`reviewPolicy`、`isListed`（是否上目录）、
`isArchived`；另有 `forumPrefixes` 前缀表。前台读取方（/boards、/f、home feed）已按这些字段过滤。
**缺的是全部管理界面**：现在板块只能靠 seed/SQL 产生；后台仅有版块作用域授权页 `/admin/authz/forum/[fid]`。

范围（建议）：
1. 板块树管理页：分区/版块两级展示，新建（kind、父级、名称、描述、icon、排序）；
2. 编辑：**可见性 readPolicy**、writePolicy、reviewPolicy（inherit 语义页内解释）、isListed 开关、isArchived 归档；
3. 拖拽或数字排序；父级变更需环检测 + path/depth 重算（现成工具函数应复用 tree 加载器）；
4. 前缀管理（forumPrefixes 的增删排）；
5. 删除仅允许空版块（threadCount=0 且无子级），否则引导先迁移主题——避免级联误删；
6. 审计：所有变更写 auditLog（复用 setSetting/writeAudit 通道风格）；门禁复用 `site.admin`（与 LOGO 管理同判例，不新增词汇表）。
7. 保存后失效版块树缓存（authz snapshot / site-chrome 同口径）。

### P0-2 基础站点配置 `/admin/settings`

现状：site_settings KV（schema.ts:181）+ `setSetting`（带前后值审计，lib/auth/settings.ts）已就绪；
但除 nav/links/footer（公告页内）、site.logo、points.* 外，**以下键只能改数据库**，且站点名称/描述**硬编码**
（layout.tsx:20、site-header.tsx:62 等）。

范围（建议，M12 安装向导接管初装值，这里是运行期编辑）：
1. 站点身份：站点名称、副标题/描述（替换硬编码；header/metadata/公告条统一读取）；
2. 注册策略 `register.mode`（invite/open，代码已读但无 UI，lib/auth/settings.ts:11）；开放注册时叠加邮箱验证开关；
3. 全站默认主题（M11 消费；本期先留键位与 UI）；
4. 发帖频控 `limits` 的可视化编辑（lib/limits/load.ts 只读回落默认；当前改库唯一入口）；
5. 每项变更走 setSetting（自带审计）；页面门禁 `site.admin`。

## 五、建议排期（2026-10-27 站长指示：M10.5 未完成项一并并入 M10.6 清理）

1. **M10.6a 板块管理**：量最大（树 UI + 策略表单 + 环检测 + 缓存失效 + E2E），先做——站长点名且 M11 主题走查需要稳定的板块结构。
2. **M10.6b 站点配置 + 邀请码**：配置菜单骨架（分组表单 + setSetting）+ register.mode + limits 编辑 + 邀请码列表/发码/停用。
3. **M10.6c 账号设置 + 双轨密码 + 通知偏好（含认领/登录交互完整化，站长 2026-10-27 点名"合入 M10.6 一起做完整"）**：/settings 收拢为设置中心（密码/邮箱/资料/通知偏好）；**双轨密码按 docs/PASSWORD-DUAL-TRACK.md 实施清单落地**（老账号旧密码可登录→强制换新密；当前全部迁移账号无密码，只能走认领/重置邮件）。认领域已实测通过的基线：`/forgot`→`/claim` 全链路 OK（30 天令牌、argon2id 落库、防枚举中性视图、频控齐全）。待补的交互完整性：①认领按钮文案「认领并登录」但实际只跳 `/login?message=…` 要求再输一遍——改为认领成功直接建立会话进入站点（或文案改准+带 message 的登录页高亮）；②认领/重置成功页缺"下一步"引导（现只有一行横幅）；③无改密页使认领后想改密只能再走 /forgot（并入账号设置三件套解决）；④auth 页密码可见性切换（与批次 d 共享实现）。
4. **M10.6d 打磨清账（原 M10.5 未完成项，全部并入）**：后台危险操作无 JS 回退（GET 确认页）、统一就地 toast、原生控件清扫与 EmptyState 收尾、auth 密码可见性切换、HoverCard 悬浮名片/积分规则卡/关注管理筛选、跨路由 View Transition 慢导航与前进后退专项验收、dotenv 17 横幅日志静音（`packages/db/src/env.ts` 加 `quiet: true`）、屏幕阅读器/Safari 抽查验收。
5. 完成后进 **M11**（主题包与 PWA）；robots/sitemap 顺手在 M10.6b 或 M11 的 manifest 工作里一并落。

## 六、边界与红线（实施时适用）

- 不改权限语义：readPolicy/writePolicy/reviewPolicy 的判定引擎照旧，本里程碑只做「编辑入口」；
- 板块结构性变更（删除/移动父级）必须环检测 + path/depth 重算 + 版块树缓存失效，E2E 覆盖越权（restricted 版块不可见/不可写）回归；
- 一切配置写入走 setSetting（自带前后值审计），禁止绕过直写；
- 新页面遵守 admin-entry-guard（入口首 await requireAdmin）与安全红线（404 能力路由禁 loading 边界等）。
