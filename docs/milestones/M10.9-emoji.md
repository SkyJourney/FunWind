## 2. 设计

### 2.1 数据模型（schema v2.2，+2 表）

```
emoji_groups                     emojis
  id            自增主键           id             自增主键（旧 50 枚以显式 id 120–169 插入，自增自然接续）
  name          varchar(50) 唯一   group_id       → emoji_groups.id，非空
  sort          int               name           varchar(50)：展示名（面板提示与正文 alt）
  enabled       bool 默认 true     keywords       varchar(200)：搜索关键词（空串 = 无）
  created_at / updated_at          ext            varchar(8)：gif / png / webp（URL 里的扩展名）
                                   storage_key    可空：空 = 迁移期的静态资源（public/emoji/{id}.gif）；
                                                  非空 = 内容寻址存储（后台上传的新表情）
                                   width/height   smallint unsigned 可空（面板可用来占位）
                                   sort           int（组内排序）
                                   enabled        bool 默认 true：**只影响面板，不影响渲染**（已发布正文里的引用永远不碎）
                                   created_at / updated_at
```

- **硬约定自查**：无 `legacy_*` 列（旧 id 只是数据，不是公式，2a ✔）；唯一键只有 `emoji_groups.name`（非空唯一，不依赖 NULL 去重，3a ✔）；`storage_key` 可空是普通列、不是唯一键（3a 不适用）。`schema-rules` 断言随 `db:verify` 跑。
- **零数据路径**：bootstrap **不种子**任何表情——Unicode 页签永远可用，社区表情页签空着；后台可建。**迁移路径**：导入旧 50 枚（见 §2.4）。
- id 保留 120–169：`/emoji/{id}.gif` 是 URL 冻结约定（硬约定 8），旧帖引用不能变。

### 2.2 提供路由（新表情）

- 旧 50 枚：`public/emoji/{id}.gif` 静态文件**原样保留**，Next 的静态资源优先于路由，零改动。
- 新表情：新增 `app/emoji/[file]/route.ts`，路径形如 `/emoji/171.png`：
  1. 解析 `id` 与 `ext`（正则 `^(\d+)\.(gif|png|webp)$`，不合式 404）；
  2. 查 `emojis`：不存在、或 `ext` 与库内 `ext` 不一致 → 404；**`enabled=false` 照常 200**（停用只影响面板，已发布正文不能碎）；
  3. 经文件出口读 `storage_key` 对应内容（复用 `/files` 的读取与安全响应头：`default-src 'none'; sandbox` + `Cache-Control: public, max-age=…, immutable`——内容寻址不可变）。
- 不走 `/files/<storage_key>`：URL 冻结约定表情是 `/emoji/{id}.{ext}`，与正文里既有的写法同形。

### 2.3 上传与处理（后台）

- 复用 `lib/uploads` 管线：嗅探不信扩展名、去元数据；**接受 png / gif / webp**（表情需要透明与动画；jpeg 拒收并提示）；GIF 沿用现有「不重编码、只去注释与非动画扩展块」。
- 限制（常量，写在代码里、后台界面提示）：**≤ 200×200 px、≤ 200 KB**；超限拒绝并给出可读提示。内容寻址落盘，同内容文件天然去重（可复用 storage_key 建多个名字）。
- 上传走后台 Server Action（`defineAction`），不上开放 API；同一时刻进行中的上传 ≤ 3 个沿用现有约束。

### 2.4 迁移器（导入旧 50 枚元数据）

- 旧库 `nw_common_emotion`（50 行，120–169，7 个分类）→ `emoji_groups` 7 行 + `emojis` 50 行：
  - **id 显式写 120–169**，`storage_key` 留空（文件已在 public 静态目录）；
  - 名称：旧库若有名称 / 描述列则取用（**Step 1 核实旧库列结构**），否则占位「旧表情 {id}」，站长之后在后台改；
  - 分类 → `emoji_groups`（sort 按旧站顺序）。
- **幂等**：`emojis` 不是迁移独占表（后台也会写），导入按 id 幂等插入（已存在则跳过 / 校准关键字段），**不删除**后台已建的行。
- `verify:migration` 新增对账项：id 120–169 恰好 50 行、分属 7 组、`storage_key` 全空。临时库演练沿用 `NEW_DB_NAME=… e2e-reset` 流程。

### 2.5 后台表情管理（`/admin/emojis`）

- 门禁：`auth: { admin: … }`（权限点见 §6 待决项 1）；**所有变更写 `audit_log`**（与 `/admin/settings` 一致）。
- 页面结构：
  - 分组列表：名称、排序（数字可改 / 上下移）、启停、成员数；新建 / 改名；**删除分组要求组内无表情**（先迁移或先删表情——与板块「有内容仅归档」同一保护思路）。
  - 分组详情：表情网格（缩略图、名称、关键词、组内排序、启停开关）；「上传表情」（选分组，可多选文件）；改名 / 关键词编辑。
  - **停用而非物理删除**：停用后从面板消失，已发布正文照常渲染；提供「删除」仅对「从未被任何正文引用」的表情开放（查询 `body_md` 引用成本高，改为：删除仅允许 admin 且二次确认，渲染侧对 404 的容错是 alt 文本——**默认只做停用，不做物理删除**，简化并绝对安全）。
- 排序变更即保存（Server Action），面板按 `(group.sort, emoji.sort, id)` 排序输出。

### 2.6 编辑器面板接入（第 ②③ 层合一页签）

- 数据源：`GET /api/emojis`（**公开只读**，与登录无关；`enabled=true`；带分组与排序；一次全量返回，数量级几百、体积小；`Cache-Control` 短缓存 + `ETag`）。返回精简 JSON：`[{id, name, keywords, url, group}]`。
- 面板：在 Unicode 页签旁新增「社区表情」页签（分组以小标题分段平铺，见 §6 待决项 3）；**搜索框合并搜索**（Unicode 关键词 + 社区表情名称 / 关键词，结果分两组显示）；点击插入**行内图片节点** `![名称](/emoji/{id}.{ext})`，Shift 连续插入沿用；空格键上屏不重要。
- **最近使用扩展**：现列表存的是 Unicode 字符串；图片表情插入的是节点。`recent.ts` 的条目改为带类型的记录（`{t:"c", v:"😀"}` / `{t:"i", v:"/emoji/171.png"}`），**读取时兼容旧格式**（纯字符串视为 Unicode 字符），存储结构一次性迁移（读到旧格式即按旧格式解释，写回新格式）。
- 面板数据为空（零数据站点）时社区页签不显示，只有 Unicode——零数据路径不受影响。

## 3. 任务清单（每步结束停下汇报）

1. **核实与基线**：旧库 `nw_common_emotion` 列结构（有无名称 / 描述）；`schema-rules` 对新表断言的预演；现有 `/emoji/` 静态请求在生产构建下的行为（路由与静态的优先级实测）。
2. **schema v2.2**：两表 + 迁移 SQL + `db:verify` 通过；bootstrap 不种子。
3. **提供路由**：`/emoji/[file]` + 单测（合式 / 不合式、ext 不匹配、停用仍 200、安全响应头、缓存头）。
4. **迁移器导入**：50 枚元数据 + `verify:migration` 对账项 + 临时库演练。
5. **后台 `/admin/emojis`**：分组与表情管理、上传（管线与限制）、停用、审计；E2E（admin 视角 + 越权 404）。
6. **面板接入**：API、社区页签、合并搜索、最近使用扩展、插入行内图片；E2E（插入 → 发布 → 渲染；停用后面板消失但旧帖不碎；零数据站点只有 Unicode）。
7. **全量门禁**：`pnpm verify:all`、`pnpm test:e2e`、`pnpm verify:migration`（本地，含新对账项）。
8. **收口**：§2.7 文档修订、CHANGELOG、站长真机清单。
