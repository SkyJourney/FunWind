# M8 · 互动套件与检索

- 阶段：二·核心 ｜ 覆盖模块：M05 / M06 ｜ 依赖：M6（M5.5 已迁入点赞/关注/标签数据）
- 状态：⬜ 未开始

## 目标

社区互动的下半套：点赞、关注、标签、通知收件箱，加上站内搜索。完成后论坛具备日常活跃的完整互动回路。

## 范围（做什么）

1. **点赞**（`reactions`）：主题首帖/回帖点赞 UI + 点赞列表弹层 + 通知事件；旧 1,649 条明细已于 M5.5 迁入，计数以明细为准。
2. **关注**（`follows`）：关注用户/版块；旧 4,390 条（过滤无效用户后）已迁入；关注动态聚合页只聚合新版行为（旧动态流表不迁）。
3. **标签**：主题标签（`tags`/`thread_tags`，12 个旧标签作种子）+ 版块标签云 + 按标签筛选；用户兴趣标签不做。
4. **通知收件箱**（`notifications`，新表，**旧通知数据不迁**——旧 32,572 条 89% 为任务/勋章/欢迎语噪音）：
   回复 / 点赞 / @提及 / 关注 / **门控收益**（消费 `gate.unlocked`）五类 + 已读/未读 + 顶栏入口；不做通知偏好设置。
5. **搜索**：MySQL FULLTEXT ngram（`threads.title`、`posts.body_md`）+ 搜索页（分页/版块过滤/时间排序）+ 空结果引导。
   **可见性硬约束**：结果经 `ForumTree` + 权限过滤；`state ≠ visible`、受限版块不可读、`is_listed=0` 不进聚合；
   索引只含 `body_md`（门控隐藏内容天然不在其中）。

## 边界（明确不做什么）

- 不做 Meilisearch（ngram 不敷使用时再立项）；不做私信（M10）。
- 不做推荐流/热搜（无真实需求前不建）；不做搜索记录功能（旧记录仅可作为 E2E 测试词表）。
- 不做多种表情回应（先只做点赞）。

## 测试规则

- 单测：通知聚合去重、关注计数一致性、ngram 查询构造器、搜索可见性过滤器。
- E2E：点赞→对方收到通知；关注版块→动态页出现新帖；打标签→标签页筛选命中；
  搜索「刀剣乱舞」「青翼」「字幕组」命中（中日文用例集，词表取自旧搜索记录）；
  门控收益通知到达作者。
- 数据边界：spam/软删/受限版块/未解锁隐藏内容不出现在任何搜索与动态结果（专项 E2E，用 fid 121 受限版块夹具）。
