## 目标

1. **上传从「疑似卡死」到「可见进度」**：50MB 附件在慢网下现在只有禁用按钮，无百分比、无占位行，
   用户无法区分「在传」「卡死」「服务端在处理」。
2. **编辑器与反馈的最后一批零成本缺口**：M16-D5 只修了源码模式加载死白，富文本初始占位仍死白；
   预览结果瞬现；`uploadNotice` 把信息提示渲染成红色错误（正确性问题，非纯动效）。
3. **离线体验低成本深化**：SW 缓存版本手改易忘、更新静默无提示、离线壳只有手动 reload 按钮。
4. **M16 残值测试补齐**：三个组件（BackToTop / SmoothAnchors / GateReveal）**无任何单测**，
   ContentImageFade 亦无测试——M16 审查报告曾失实声称「已覆盖」，本专项据实补齐。

## 3. 边界（明确不做什么）

- **模式切换 crossfade**：与 `key++` 重挂架构冲突（E6），M16 已拍板默认不做。

- **分片 / 断点续传**：需新端点 + 配额/限流/并发闸重设计 + 新依赖，独立里程碑量级。
- **预览本地化渲染**：动摇服务端权威渲染与往返保护前提，超出反馈范畴。
- **社区表情小图显影**：M16 明确豁免（装饰性、可见性无碍）。
- **Web Push**：M18 独立立项（P8）。
- **离线收藏 / 缓存页面内容**：突破 `sw.js:3-4` 隐私红线，需站长单独拍板，本专项不做。
