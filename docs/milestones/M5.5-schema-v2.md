## 背景与动机

M0–M5 的数据线是「忠实搬运」：旧表一对一进新库，旧结构渗进了新模型。2026-10-23 的深度审查同时发现迁移数据错误、
门控内容变公开、权限泄露、门禁虚绿。M5.5 因此立项：在进入 M6（写路径）之前把地基重做对。

首轮 v2（S2/S3）修掉了上述缺陷，但评审发现一个更根本的问题：**设计仍是从旧结构出发的**——
运行时 schema 里出现了 `permissions.legacy_key`、`author_name_legacy`、`postId×16+seq` 这类 id 公式、`source='migrated'` 标记、
`migration_state` 表、直指旧站目录布局的附件路径、随零数据安装下发的青翼团队角色。

站长方针（2026-10-23）：**以新系统设计为原则，旧版设计和数据向它靠拢；设计阶段最多考虑「旧数据值不值得迁」。**
于是改为「设计先行」：先定目标模型（[DESIGN-MODEL.md](../DESIGN-MODEL.md)），再让 schema 与迁移适配层向它靠拢。

## 设计原则

完整原则与 43 张表的目标设计见 **[DESIGN-MODEL.md](../DESIGN-MODEL.md)**。要点：

1. 运行时 schema 不认识旧站（无 `legacy_*`、无迁移标记、无迁移 id 公式）；迁移知识只在 `migration/`。
2. 引用诚实：作者引用一律指向真实用户行（已注销 = 占位账号）。
3. 状态最小；内容状态机 `visible / pending / rejected / hidden / deleted`；限制统一走 `user_restrictions`。
4. 所有文件进 `files` 注册表（内容寻址），`/files` 路由取代公开的 `/attachment/**`。
5. 只保留 URL 必须稳定的旧 id（uid/fid/tid/pid），其余自增。
6. 唯一键不得依赖 NULL 去重（`scope_id = 0` 哨兵）。
7. 扩展点前置抽象：积分渠道、门控解锁条件、通知类型与投递渠道（模块内核十类注册边界）。
8. 内容只有 Markdown（内联样式降级）。
9. 迁移分层：extract → transform（纯函数）→ load → verify；对账期望值用独立 SQL 推导；报告确定性、入库、脱敏。

## 目标模型的主要变化（v2 首轮 → v2.1）

| 域 | 变化 |
|----|------|
| 身份 | `users.state` 改 `active\|deleted`；已注销作者建占位账号；删 `author_name_legacy`；`avatar_key` → `avatar_file_id` |
| 内容 | 状态增 `pending/rejected`，去 `spam`；`topped` → `pin_level`，`digest` → `is_featured`；门控占位改 `gate_key`；`gate_unlocks` 去 `source`；新增 `content_reviews` |
| 文件 | 新增 `files`（sha256 唯一）；`attachments` 改 `post_id + file_id`；`/files` 路由（图片公开，非图片附件按版块读权限校验） |
| 版块 | 新增 `review_policy`（继承规则同读/写策略） |
| 通知 | 新增 `notifications`、`notification_preferences`、`announcements`、`announcement_reads`（见 [NOTIFICATIONS.md](../NOTIFICATIONS.md)） |
| 权限（微调） | `permissions` 去 `legacy_key`/`condition_params`；内置角色仅 guest/member/admin，团队角色改为站点数据（由迁移创建） |
| 平台 | 删除 `migration_state` |
| 内核 | 注册边界 八类 → 十类（+`notificationTypes`、`notificationChannels`） |

表数量 38 → **43**。

## 迁移适配层规则（旧数据向新模型靠拢）

旧数据按「新系统有没有天然归宿、迁过来有没有价值」分级，详见 DESIGN-MODEL.md §7。

| 对象 | 处理 |
|------|------|
| **不迁（旧库即归档）** | spam 空壳主题（3,033）、旧回收站与屏蔽内容、私信（1,462 条）、系统消息、旧通知（32,572）、旧公告（10）、任务/银行/抽奖/草稿/日志等已取消功能、`pw_*` 遗留表 |
| 首帖/回帖 | 首帖 = `floor 1`（自增 id，在保留 pid 的回帖之后分配）；回帖保留旧 pid 作 `#p{pid}` 锚点；楼层按 `(created_at, pid)` 稳定分配；`rpid` → `reply_to_post_id`，`posts_reply` 丢弃，`topost` 旧链接改写为 `#p{pid}` |
| 已注销作者 | 为被引用但已不存在的 uid 建占位账号（`state=deleted`，用户名「已注销用户#id」） |
| 门控 | `[sell=N]` → points（≥ 9999 重置为免费）；`[post]`/`[hide]` → reply；`gate_key` 按帖内顺序生成；旧购买按帖展开为解锁记录，回复解锁由实际回帖派生不迁；未闭合失败即封闭、门控优先、表格内门控提升 |
| 文件 | 附件（406）、头像（7,333）、正文引用的旧站图片、勋章图：计算 SHA-256，复制进 `STORAGE_DIR`，写入 `files`；正文 URL 重写为 `/files/…`；孤儿文件不复制 |
| 正文 | UBB → Markdown；内联样式（color/size/backcolor/align）降级剥除；表情 `[s:N]` → `/emoji/{id}.gif`，遗留表情码删除；表格 → Markdown 表格 |
| 用户 | 归一化键、重复/非法邮箱置空并入清单（完整邮箱清单写入 gitignore 的私有报告）、头像 → `files`、`regdate=0` 修复；密码一律不迁 |
| 限制 | 旧封禁 typeid 1/2/4 → 禁言/禁头像/禁签名，禁止发言组 → 永久禁言；已过期不迁 |
| 权限 | 旧 gid/旧权限键/条件键的映射表放在 `migration/src/mapping/`；团队角色及其版块授权由迁移创建；会员取最宽并集；版块白名单 → `read_policy`/`write_policy` + 团队角色作用域授权；旧 `operate_thread` 不翻译（是设置而非开关） |
| 积分 | 期初余额 = 旧 credit1（负数按 0）+ 银行存款本金；不迁旧流水 |
| 签到 | 每人只取「截至最近一次的连续签到段」，保住连签状态 |
| 勋章 | 旧勋章（仅有效持有）+ 团队徽章；勋章图 → `files` |
| 社交 | 关注（含加入版块）、点赞、投票（以实际投票记录重算计数）、标签（12） |
| 计数 | 回复数/最后回复/版块与用户统计全部由明细重算 |

### 首轮 v2 记录（S1–S3，已完成；作为 R2/R3 的复用资产与教训）

可复用资产：`packages/content`（门控语法、UBB 转换器、泄露不变量性质测试）、迁移四层框架与 PHP 序列化解析器、确定性报告构建器、

首轮拦截的缺陷（教训保留，回归测试随重做保留）：

- **提权缺陷**：旧 `operate_thread` 对普通会员只是设置数组（`up_time: 72`），真值判断误判为开启 → 全体会员获得版主权。
  三层护栏：词汇表不映射、翻译器对数组值只接受白名单开关键、对账「非 admin 无全局管理/版主权」。
- **门控泄露向量**：标签交叉嵌套使门控被弹出栈（改为门控优先）；未闭合 `[sell]` 去壳公开会泄露已售内容（失败即封闭）；
  表格内门控被渲染两次（提升到表格之后）；`[attachment=N]` 等无闭合标签吞掉后文（v1 数据丢失缺陷）。
- **幂等缺陷**：UPSERT 在转换逻辑变化后残留陈旧行 → 迁移独占表整体替换式加载 + 线上数据保险（`MIGRATION_FORCE=1`）。
- **PII 入库**：报告里出现完整邮箱 → 公开报告脱敏，完整清单写入 gitignore 目录。
- 其它：旧 gid 23/38（实习组/策划组）映射反；旧「购买」表同时记录了回复解锁；uid 1 是旧站已删除的虚拟账号，uid 0 才是系统发信人。

首轮数字（v2，将被 v2.1 的精简范围取代）：用户 10,701、帖子 36,630、门控 664、解锁 2,943、积分账户 6,660（期初余额合计 528,473）、
签到 72,914、私信 1,462、对账 83/83。

## 测试规则

- **单测**：`packages/content` 往返无损、泄露不变量；transform 纯函数全覆盖；评估器对词汇表每个权限点至少 1 例，`read/write/review_policy` 各取值与级联各 ≥ 3 例。
- **集成（DB）**：`applyPoints` 余额不为负 / 幂等 / 并发；`unlockGate` 并发双击只扣一次；`ForumTree` 失效；注册事务；文件去重（同哈希只存一份）。
- **迁移**：清空后重导两次，导入/对账报告逐字节一致；对账期望值用独立 SQL 推导；含「门控零泄露」「文本保留率」「文件哈希可重算」。
- **E2E（S5）**：游客首页不出现受限版块任何信息；门控多视角；`pending/rejected` 仅作者与版主可见；`/files` 对受限版块非图片附件鉴权；管理动作出审计。
