## 背景与动机

M0–M5 的数据线是「忠实搬运」：旧表一对一进新库，旧结构（四级版块枚举、首帖/回帖分表、`credits` JSON、`groups` 等级阈值、
`raw JSON` 归档、双份表情表）渗进了新模型。2026-10-23 的 M0–M5 深度审查（见 CHANGELOG）同时发现
**迁移数据错误**（权限翻译不幂等：`user_roles` 重复 5 倍、`role_grants` 含脏键）、**门控内容变公开**（`[post]` 306 帖未处理）、
**权限泄露**（首页绕过 guard）、**门禁虚绿**（`pnpm test` 覆盖率门槛为红、M5 勾选的审计并不存在）。

站长方针（2026-10-23）：旧系统是 20 年前的产物，应以现代论坛视角裁剪无用子系统，按现代设计重做库表与功能，
**最终只是把旧数据映射进新模型**。项目仍在从 0 开发阶段，任何破坏性变更均接受（重新迁移即可）。
因此在进入 M6（写路径）之前插入本里程碑：先把地基重做对，再往上盖。

## 设计原则

1. **业务库只放新模型**：旧结构不渗入。未被新模型使用的旧表一律丢弃，**不建归档库**；旧库本身保持原样（只读）直至 M13 上线签字，即事实上的归档。
2. **保留旧主键**（uid/tid/pid/fid/aid）以保证 URL 冻结与附件路径；新记录走自增（起点 = 旧最大值 + 1）。
3. **唯一键不含可空列**：全局作用域用 `scope_id = 0` 哨兵（根因：MySQL 唯一索引不去重 NULL，已造成 5 倍重复行）。
4. **状态是一等属性**，不靠「有没有记录」推断（版块可见性、限制、软删均如此）。
5. **内容一律 Markdown**；门控内容在迁移期拆出，从构造上杜绝泄露（见 [GATES.md](../GATES.md)）。
6. **迁移分层**：extract → transform（纯函数，可单测）→ load（幂等）→ verify（对账）；对账报告入库，不再 gitignore。
7. **扩展点前置抽象**：积分渠道（[POINTS.md](../POINTS.md)）与门控解锁条件（[GATES.md](../GATES.md)）进入模块内核注册边界。

### 版块层级与权限（用户最关心的一环）

- **模型**：邻接表 `parent_id` + 物化路径 `path`（如 `/98/130/129/53/`）+ `depth`。深度不设上限（旧站实际最深 4 层）。
- **内存树 `ForumTree`**：应用启动加载整棵树（43 行量级），版块写操作触发失效。作用域链、子树、祖先查询均为零 SQL 内存操作；
  首页目录、最新动态、搜索结果的可见性过滤全部基于它。
- **`read_policy` 一等属性**：`inherit`（默认，取最近的非 inherit 祖先；全无则公开）｜`public`｜`members`（任意登录用户）｜`restricted`（需 `forum.read` 授权）。
  修复 v1「删光读授权，受限版块悄悄变公开」的结构性缺陷；保持「就近层显式优先、不回退父级」的既有语义。
- **写/管理权限**：`forum.write`、`forum.moderate` 沿父链**级联合并**（子版块自动带父版块版主）。
- **派生版主**：持有 `forum.moderate`（而非 `forum.write`）授权的用户，由查询派生；修复 v1 把整个团队角色派生成版主的错误。
- **`is_listed`**：控制是否出现在首页目录/最新动态（旧 `isshow=0`，6 个版块），不影响直达访问与权限判定。
- **回收站版块（旧 fid 129）**：迁移为普通受限版块并标记 `is_archived`，不做特殊机制。
- **旧白名单翻译**：旧 `allow_read` 白名单 → 若含游客组则 `public`；若含全部会员组则 `members`；否则 `restricted` + 逐角色 `role_grants`。43 个版块全部配置，无「空 = 不限制」边界。

### 权限模型修正（AUTHZ v2，详见 [AUTHZ.md](../AUTHZ.md) §8）

- `role_grants(role_key, permission_key, scope_id)`、`user_roles(user_id, role_key, scope_id, expires_at, …)`：`scope_id = 0` 为全局，`> 0` 为版块；删 `scope_type`。
- 禁言/封禁统一进 `user_restrictions`；评估器只读这一处（取代 muted 角色 + user_bans + 旧 status 位三套）。
- `checkPermission` 签名重做：显式 `subject`（用户 id 或 guest），不再隐式读取「当前请求用户」；请求级 `can(key, ctx)` 作为当前用户的便捷封装。
- 开放注册模式下「邮箱未验证」作为限制：写类权限拒绝（M4 遗留承诺在此兑现）。

### 积分与门控（新抽象）

- 积分：`point_accounts` 余额快照 + `point_ledger` 台账 + 渠道注册（`pointChannels`），单一入口 `applyPoints()`。详见 [POINTS.md](../POINTS.md)。
- 门控：内容容器 + 可插拔解锁条件（`gateConditions`），`post_gates.conditions` JSON 数组 + `match`。详见 [GATES.md](../GATES.md)。
- 模块内核注册边界由六类扩为**八类**（新增 `pointChannels`、`gateConditions`）；事件 `credit.changed` 改名 `points.changed`，新增 `gate.unlocked`。

## 迁移 v2

```
旧库(只读) → extract → transform(纯函数) → load(幂等) → 新库 → verify → 对账报告(入库)
                          └─ packages/content（门控解析/拆分，与线上保存共用）
```

关键转换规则：

| 对象 | 规则 |
|------|------|
| 首帖 | `threads_content` → `posts.floor=1`；5 个无正文主题补空首帖；回帖 floor 整体 +1；31 个 pid 序与时间序不一致的主题按 `(created_at, pid)` 稳定排序 |
| 回帖指针 | `rpid` → `reply_to_post_id`；丢弃 `posts_reply`（与 `rpid` 逐行重复）；`job.php?action=topost` 旧链接改写为 `#p{pid}`；跨主题的 6 条坏指针置空 |
| 表情 | 50 枚 `[s:N]` 展开为静态资源引用（gif 随迁移拷入 `apps/web/public/emoji/`）；映射外遗留码 147 行：尝试用旧目录 `03`（`51.gif`–`61.gif`）对应，对不上的降级为纯文本 |
| 门控 | `[sell=N,…]` → `unlock="points"`（N ≥ 9999 一律改为免费，原价写入对账报告）；`[post]` → `unlock="reply"`；`[hide=N]` → `unlock="reply"`（S3 核对语义）；`threads_buy` 6,984 行 → `gate_unlocks`（旧购买按帖子计，一帖多门控时展开为多条） |
| 图片 | `p_w_picpath/…`（338 帖）、`p_w_upload/…`（92 帖）相对路径重写为 `/attachment/…`；悬空 `[attachment=N]`（12 次）降级为文本 |
| 附件 | 以 `nw_attachs_thread` 为准（`nw_attachs` 为其逐行子集，丢弃）；9 条挂在不存在主题上的孤儿附件丢弃；51 条未被正文引用的附件挂到所属 post 末尾 |
| 作者 | 已不存在的 80 个 uid（550 帖/42 主题）：`author_id` 保留原值，`author_name_legacy` 写入旧 `created_username`；渲染「已注销」 |
| 用户 | 删 QQ/MSN/旺旺/支付宝/地址等低填写率字段；`status` 位标志：32（签名 UBB）丢弃，12（禁头像+禁签名）→ `user_restrictions`，16（后台登录）→ admin 角色；`regdate=0` 的 2 位管理员修正为最早活动时间；`regreason`/`punch` 不迁（签到另提取） |
| 邮箱 | 小写归一化唯一；6 组重复邮箱（均为小号）保留最早注册者，其余置空并写入报告待人工处理；3 个非法邮箱置空 |
| 角色 | `user_belong` + 主组 → `user_roles`（`scope_id=0`）；gid 19/20/24/26/27/35 等已删除组成员**不恢复**（站长决策：丢弃） |
| 积分 | 取 `nw_user_data.credit1`（8,350 人非零，合计 459,556）→ 每人一条 `opening` 分录；银行定期/活期（30 账户，合计 96,650）结算计入余额；`credit2/3` 丢弃；其余 `credit4–8` 全为 0 |
| 签到 | 自 `credit_log.logtype='punch'`（约 72,992 条）提取日期 → `checkins`；连签由日期重算 |
| 勋章 | `medal_info`(25) → `badges`；持有关系以 `medal_user` 为准（口径与 `medal_log` 差异在 S3 核对） |
| 私信 | 真实用户私信（约 1,492 条）按用户对合并为 `conversations`；`from_uid ∈ {0,1}` 的系统消息（2,268 条）丢弃 |
| 关注/点赞 | `nw_attention`（过滤引用不存在用户的 711 行）→ `follows`；`like_log` → `reactions`，计数以明细重算 |
| 投票 | 以 `poll_voters` 实际记录重算计数；13 条指向不存在主题的 `poll_thread`、1 个无帖投票丢弃；5 组重复投票去重 |
| 标签 | 12 个主题标签作为种子；`user_tag`（兴趣标签）丢弃 |
| 丢弃清单 | 全部 `pw_*`（311 张）、任务系统、银行/抽奖流水、草稿、搜索记录、日志、动态流、通知（含 32,572 条旧提醒）、导航/友链/公告（改配置，见 M9）、`nw_user_register_check` 等未用表 |

## 边界（明确不做什么）

- 不实现编辑器与门控创作（M6）；不实现发帖/回帖奖励规则与签到动作（M7）；不做通知（M8）。

## 测试规则

- **单测**：`packages/content`（拆分/还原往返无损、嵌套非法、属性校验、XSS）覆盖率 ≥ 90%；transform 纯函数全覆盖；
  评估器对**词汇表每个权限点至少 1 例**，`read_policy` 四种取值、级联合并、就近层、restriction 优先各 ≥ 3 例。
- **集成（DB）**：`applyPoints` 余额不为负 / 幂等键 / 并发；`unlockGate` 并发双击只扣一次、作者收益入账、价格 0 不动台账、作者本人免购；
  `ForumTree` 失效；注册事务（邀请码与用户同成同败）。
- **迁移**：连跑两次，各表行数与内容校验和完全一致；空库 `bootstrap` + `seed` 与导入两种路径均通过。
- **E2E**：游客首页不出现受限版块任何信息（fid 121 名称/标题/计数）；门控四视角（游客/已购买/作者/版主）；
  `read_policy` 四取值版块的游客/会员/授权角色访问矩阵；管理动作出审计；开放注册未验证用户写入被拒。
