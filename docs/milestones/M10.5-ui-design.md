# M10.5 · UI 设计与视觉打磨（前台 + 管理后台）

- 阶段：三·完善 ｜ 覆盖模块：跨模块（全站界面） ｜ 依赖：M9（后台页面成形）+ M10（私信/投票页面并入走查）；先行于 M11（主题包以打磨后的界面为基准）
- 状态：⬜ 未开始（2026-10-25 插入，站长决定）

## 目标

在主题包（M11）落地之前，对全站界面做一次**专门的视觉设计与打磨**：前台与管理后台两部分，
让视觉更优雅、更一致。这是纯前端面的收口里程碑——**不动任何底层能力**（服务层、数据层、权限、
路由与交互逻辑全部保持），只对渲染层与样式做设计级的整理与提升。

> 背景与定位（2026-10-25 站长决定）：M1–M10 的功能里程碑各自「能用优先」，视觉一致性没有专门过一遍。
> 三层令牌架构（[FRONTEND-DESIGN.md](../FRONTEND-DESIGN.md) §2）与两套布局 shell（前台内容优先 /
> `/admin` 高密度）是既有决策，本期不重新设计体系，而是在体系内把执行质量拉齐。
> M11 的主题包与暗色打磨以本期的产出为基准，因此本期必须先行于 M11（不再与 M6–M10 并行）。

## 范围（做什么）

1. **设计令牌收口**：盘点 primitives / semantic 两层（间距、圆角、阴影、字阶、动效时长），
   消除 M1 骨架期与 M6–M10 各页面就地取值造成的漂移；shadcn/ui 模式组件的变体规范统一
   （Button / Card / Badge / Table / Dialog 等的尺寸与态）。
2. **前台逐页视觉打磨**：首页版块目录、版块页、帖子页（楼层/嵌套回复/锚点/门控块）、编辑器、
   用户资料页、积分台账/签到/徽章页（M7）、通知中心/顶栏铃铛/检索（M8）、私信与投票（M10）；
   空状态 / 加载态 / 错误态的统一规范与落地。
3. **管理后台视觉打磨**：`/admin` 全部页面（审核队列、举报、用户管理、公告、站点框架、审计日志、
   积分配置、数据看板）——高密度令牌下的表格与表单规范、操作反馈一致性。
4. **响应式与移动端走查**：375 / 768 / 1280 三档逐页过；移动端无横向滚动；触控目标尺寸；
   编辑器移动端体验（M6.3 基础上只做视觉层）。
5. **视觉稳定性（CLS）**：承接 [M6-carryover](M6-carryover.md) 的 **M-cdn** 项——正文图片渲染携带
   尺寸属性（宽高取上传时已记录值，按 `files` 行查得后补，不改写 Markdown 源码），评估列表页缩略图。
6. **视觉基线交接**：为 M11 建立现代浅色主题关键页面截图基线（Playwright screenshot 入库），
   主题包与暗色走查在此基线上扩展三主题对比。

## 边界（明确不做什么）

- 不改信息架构、路由、交互逻辑与页面骨架；现有 E2E 行为断言必须保持绿
  （个别断言因视觉微调需要同步时，须在改动记录中逐条说明）。
- 不动服务层 / 数据层 / 权限——「不影响已做的底层能力」是本期成立前提。
- 不做主题包、暗色模式与用户主题选择（M11）；但本期新增样式一律走 semantic 令牌层，
  禁止裸色值，保证暗色与主题包在 M11 可无损覆盖。
- 不做大型动效与微交互体系（过渡/时长收口进令牌即可，不另起体系）。
- 页面骨架级重构需求 → 单独立项，不在本期夹带。

## 测试规则

- **视觉回归基线**：关键页面（前台核心页 + `/admin` 代表页）截图入库为浅色基线；
  M11 的三主题对比以此为准扩展。
- 现有 E2E 全绿（UI 打磨不得破坏任何行为断言）；375px 无横向滚动逐页走查清单。
- 性能不回退：`perf:lcp` 基线（64–128ms）不劣化；`perf:posting` 不受影响。
- 样式纪律审查：新增/改动样式零裸色值（全走 semantic 层）。

- 若打磨期间发现需要骨架级改动的页面 → 记录到本节并单独立项，不夹带实现。
