## 3. 门控创作收尾

### 3.1 已购买门控改价提示

编辑页读取本帖门控的解锁人数（`gate_unlocks` 计数，只读）。有人解锁的门控，在对应的门控块旁显示提示：「已有 N 人解锁。改价只影响之后的购买，已购买者不退差价。」保存行为不变（服务端已允许改价、拦截换方式 / 删除）。

### 3.2 「内容更新于」标记

- 隐藏正文（`hidden_md`）变更时，记录 `content_updated_at`（D1）。改价、改标题不更新它。
- 已解锁的读者（含已购买）看到门控内容时，若 `unlocked_at < content_updated_at`，在门控内容上方显示「内容更新于 YYYY-MM-DD HH:MM」。未解锁者看到的锁卡片同样显示该标记（只是时间，不含内容）。
- 更新写入位于 `lib/gates/write.ts` 的同一事务内（与 `hidden_md` 的比较逻辑一起守护，见 `write.int.test.ts`）。

### 3.3 「回复可见」的「去回复」引导

锁卡片文案改为「回复本帖后可见」+ 链接，指向本帖所在主题页的回复框锚点 `#reply`。主题页若因锁定 / 归档 / 游客而没有回复框，链接仍指向锚点，页面上的既有说明负责解释原因（不新增分支）。

## 5. 事件、浏览量与演示消费方

### 5.1 `view_count`

- **写入方式（D2）**：客户端 `useEffect` 在主题页挂载后发送一次信标 `POST /api/views`（body：`{tid}`），不在 RSC 渲染路径里写库（预取与 RSC 子请求都会触发渲染，不能计数）。
- 路由同源检查 → 限流（每个 IP 每分钟 120 次；拿不到可信 IP 的请求共用一个桶；登录用户另有按账号 120 次/分钟的限额）→ 进程内去重：同一访客（登录用户取 userId，游客取可信 IP 的哈希；拿不到可信 IP 时统一为同一个游客身份，**不使用 User-Agent**）同一主题 30 分钟计一次（D3）。身份规则见审查整改记录 V-1→ 进程内累加 → 每 10 秒批量 `UPDATE threads SET view_count = view_count + n`（单实例语义，M13 换共享计数）。
- 作者本人访问不计入（D3）。被隐藏 / 删除的主题不计入（写入前用 `visiblePredicate` 判定，与读取同一规则）。
- 信标在页面卸载时可能丢失：可接受（浏览量是估计值，不是账目）。

### 5.2 `attachment.uploaded` 派发

`registerPostFiles` 在保存事务**提交后**，为每条新建的下载附件派发 `attachment.uploaded`（载荷 `{attachmentId, fileId, uploaderId}`，无文件名与正文）。与 `thread.created` 相同的派发机制（`dispatch`，提交后、逐消费者隔离）。内核事件清单不变（已声明）。

### 5.3 演示消费方

`demo-checkin` 增加对 `thread.created`、`thread.replied`、`attachment.uploaded` 的订阅：每次收到真实事件就在模块的内存计数器里 +1，并在演示页面（新增或复用现有的演示页面）显示「最近 N 条业务事件」。纯演示，不改变业务数据。验收：E2E 发帖 / 回帖 / 上传后，演示页计数变化。

## 6. 性能基准

- 方法（D7）：服务层基准脚本 `pnpm --filter @funwind/web perf:posting`，在 e2e 库上顺序执行 N=200 次 `createReply`，输出 p50 / p95 / p99。Server Action 只能经 Next 运行时调用，HTTP 层基准留到 M13 部署环境。
- 阈值：p95 < 300ms 为失败线（脚本非零退出）。结果写入本文档 §14（实测数字）。
- 脚本不入 `verify:all`（耗时与机器相关），由 `pnpm test:e2e` 之后的人工执行，记录结果。

## 14. 实测记录

### 14.1 发帖性能基准（`pnpm --filter @funwind/web perf:posting`，M6.5d）

- 环境：Apple M4（10 核）/ 32 GB / macOS 27.0.1 · Node v24.15.0 · MySQL 8.4.13（本机容器 33621）· 库 `qysub_next_e2e`（e2e 库，脚本拒绝其它库名）。
- 方法：会员身份，单个临时主题上顺序执行 `createReply`，预热 5 次不计入，样本 N = 200；间隔限制在脚本内临时放宽并还原。
- 结果（两次独立运行，单位 ms）：

| 运行 | p50 | p95 | p99 | mean | min | max |
|---|---|---|---|---|---|---|
| 第 1 次 | 6.5 | 10.0 | 11.4 | 7.0 | 5.8 | 15.1 |
| 第 2 次 | 6.2 | 10.0 | 12.0 | 6.7 | 5.5 | 13.7 |

- 判定：p95 远低于 300 ms 失败线（约为失败线的 3%），通过。
- 局限：仅服务层，不含 HTTP、Next 运行时与浏览器；样本在单台开发机、单线程顺序执行，不代表并发下的表现。HTTP 层与并发基准留到 M13 的部署环境。

### 14.2 频控 E2E（M6.5d）

- 间隔：会员 alice 首条回帖成功，收紧间隔为 3600 秒后第二条被拦下，回显「发帖太频繁，请稍后再试。」（`?reply=too_frequent`）。
- 每日主题：额度 = 当日已发数 + 1，第一条发布成功，第二条回显「今日发主题次数已达上限，明天再来吧。」（`?error=quota_exceeded`）。
- 每日上传：额度 = 当日已上传数 + 1，第一个附件成功，第二个回显「今天的上传次数已用完。」，附件列表只剩一行。
- 三条都经 `site_settings.limits` 临时覆盖会员角色，`finally` 中还原；用例串行执行，不影响并行用例。
