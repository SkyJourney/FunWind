# M22 · RSS/Atom 订阅输出

- 阶段：四·运营与演进。状态：实现与本地隔离验收通过，待站长验收。
- 依赖：现有游客权限评估、主题与首帖查询、站点身份和正文净化。M21 暂缓，M22 可独立交付。

## 1. 目标

读者能从首页和公开版块页发现 RSS 2.0 与 Atom 1.0 订阅，把两类主题订阅加入阅读器，并持续收到游客可见的新主题。

## 2. 范围边界

- 首版范围为匿名订阅全站或单版块的新主题。主题回复订阅留待以后，避免把回复更新与主题发布混在一个源里。
- 条目采用公开摘要与原帖链接，完整阅读通过论坛页面完成。会员、受限版块及门控正文遵守现有访问规则。
- 发现入口位于页面 `<head>`，由阅读器读取。订阅交付采用公开 HTTP 拉取。

## 4. 交付物与接口契约

- [x] `/feeds/latest` 聚合有效读策略为 `public`、游客可读且已列入目录的版块。`/feeds/forum/[fid]` 只取本版，公开但未列目录的版块支持直达。分区、非法或不存在的版块、会员及受限版块统一 404。空公开版块输出有效的空订阅源。
- [x] 默认 RSS 2.0，显式 `?format=rss` 等价，媒体类型 `application/rss+xml`。`?format=atom` 选择 Atom 1.0，媒体类型 `application/atom+xml`。正文使用 UTF-8。非法格式参数返回 400。
- [x] 查询在限量前核对有效版块权限、主题和首帖均为 `visible`、首帖属于该主题且楼层为 1。按主题发布时间、ID 依次倒序，最多 50 条。条目包含标题、主题链接、公开作者、时间和最多 120 个 Unicode 码点的公开首帖摘要。
- [x] 摘要先跳过门控占位，从共用 Markdown 净化后的首个非空正文段取纯文本，再由 XML 构建器编码。RSS 与 Atom 共用稳定的主题标识，绝对 URL 来自经验证的站点配置。
- [x] GET、HEAD 和 304 共用当前表示的 ETag。先读新鲜权限和内容，再判定 304。成功响应使用 `public, no-cache`。400、404 和 503 使用 `no-store`，失败响应仅返回通用提示。
- [x] 首页和公开版块的原始 HTML `<head>` 都有对应的 RSS 和 Atom 发现链接。版块链接遵循订阅端点相同的游客资格。

## 5. 数据模型

版块、主题和首帖表保持现有结构。订阅读取当前数据，无新表、字段或迁移。

## 8. 风险

- 权限变动后仍可能存在已经下载到阅读器的副本。源站以只读一致性视图读取最新授权，HTTP 缓存每次复用前重新验证。
- XML 实体与 RSS 阅读器可能解释的 HTML 使用各自的编码规则。用 XML 解析后的字段和值进行断言。
- 每次重验证需要读数据库。单请求固定上限与确定性排序，使用生产构建实测页面发现和订阅响应。

## 10. M22.1 页内入口与继承链校验
