# M9 · 管理后台与站点框架

- 阶段：三·完善 ｜ 覆盖模块：M10 / M11 / M13 ｜ 依赖：M5（+ M7/M8 的审计数据）
- 状态：⬜ 未开始

## 目标

运营能力：`/admin` 管理后台（审核/用户/权限/日志）+ 站点框架配置（公告/导航/友链）。
完成后社区可自治运转，不再依赖开发者操作数据库。

## 范围（做什么）

1. `/admin` shell：侧边导航、高密度令牌、admin/moderator 视角差异（权限复用 M5）。
2. **内容审核**：新帖队列（post_check 语义）、is_spam 复核（批量标记/恢复）、回收站（M6 软删的恢复/彻底删除）。
3. **用户管理**：搜索/详情（积分流水/勋章/登录记录）、封禁与解封、角色调整（写 user_roles 审计）。
4. **站点框架**：公告条/公告页（nw_announce 语义）、导航配置（nw_common_nav 语义）、友链管理、页脚配置。
5. **审计日志中心**：event_log + 权限变更 + 管理操作的统一查询页（筛选/导出 CSV）。
6. 数据看板（轻量）：注册/发帖/活跃趋势（SQL 聚合 + 简单图表，不引重库）。

## 边界（明确不做什么）

- 不做主题可视化装修器（M11 方案是令牌主题包，非设计引擎——旧 nw_design_* 明确不复活）。
- 不做多管理员细粒度后台权限拆分（admin/moderator 两级起步，够用后再拆）。
- 图表不引入重型 BI 库。

## 测试规则

- E2E 越权矩阵：moderator 访问全站管理页 → 403；moderator 仅能操作所辖版块内容；
  非登录访问 → 登录跳转。
- 审核流 E2E：垃圾帖→标记 spam→列表消失→恢复→重新可见（与 migration 的 is_spam 同一状态机）。
- 审计完整性：任何后台操作后审计日志新增一条（断言性 E2E 覆盖每类操作）。

## 验收门禁

- [ ] 越权矩阵 E2E 全绿；后台全部操作出审计
- [ ] 审核三态（正常/spam/回收站）状态机 E2E 全绿
- [ ] 站点框架改动即时生效（公告/导航缓存失效验证）
- [ ] 移动端管理可用性手工清单（至少审核与封禁两个高频操作）
