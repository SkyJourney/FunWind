## 遗留事项（明确不在本里程碑内，已记入对应位置）

- **CSP 仍是 Report-Only**，且 `script-src` 含 `'unsafe-inline'`（Next 的 RSC 载荷是内联脚本）：不防内联脚本注入，那一层靠 sanitize 白名单。转强制的步骤写在 CHANGELOG（S4）；用 nonce 去掉 `unsafe-inline` 需要中间件，留待后续。
- **`TRUSTED_PROXY_HOPS` 生产必须显式设置且 ≥ 1**：直连（0）时 IP 恒为 null，IP 桶全部不生效，只剩全局桶与账号桶；`forgot` 的全局桶只对真实账号计数，邀请码的全局桶可被一个客户端占满（取舍见 M4 文档）。
- **进程内频控 / 权限快照是单实例语义**：多实例前换 Redis 或共享失效通道（M13）。
- **HTTP 层的真实时序没有做统计检验**：登录与找回只证明了「恒做一次校验」「响应前不发信」，没有对响应时间做显著性检验。
- **`remark-cjk-friendly` 评估后未采用**（带入误判）；强调边界改由转换器输出 HTML 标签解决。
- **令牌上限取 6（评审时定的是 3）**：见 CHANGELOG S3 的理由，常量 `MAX_LIVE_TOKENS`。
- **会话是 30 天绝对过期**，不做真正的滑动续期（需要中间件刷新 cookie）。
- **登录时不销毁旧会话**（`loginAction` 只签发新会话并换 cookie，旧会话行到期前仍有效；已核实，尚未修）；审查报告 §4 末尾 P3 摘要里的其余项（`?error=` 文案可被伪造、`/admin` 对游客 302 暴露后台存在、个人页公开封禁理由与统计、外链图片泄露观众 IP 等）也未在 M5.6 处理，逐项状态以报告为准，按归属并入 M6 / M9。
- **`post_modify_time` 的原始语义无法从旧源码确认**（旧源码里搜不到该键的字面量）：旧库实测全为空 / 0 = 旧站没设过编辑时限；新站编辑时限做成可配置项，默认不限。
- **M6 起要先做的事**（来自审查与复查，已在 M6 计划里排期）：`defineAction` 骨架、基线授权版本机制、评估器上下文（分区 / 归档 / 锁定 / 所有权）、注册用户名校验、`locatePost` 取代 `pageOfFloor`、`db:recount` 与孤儿对账。
