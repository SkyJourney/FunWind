# M20.1 · 管理 API 在线文档页（M20 增补）

- 阶段：四·运营与演进 ｜ 依赖：M20（已收口部署）｜
  状态：🚧 开工（2026-11-18 立项即开工——范围清晰、单页面 + 数据模块）
- 立项动因：站长 2026-11-18——MANAGE-API.md 是仓库内手写文档，管理员在线不可见；
  需要一套**管理员权限下的在线文档页面**承载全部管理 API 的文档。

## 1. 目标与范围

1. 新页面 `/admin/api-docs`：管理 API 在线文档，**管理员可见**（门禁与 API 令牌页同口径：
   `requireAdmin("site.admin")` + 站点管理员不变量校验，不满足 notFound）。
2. 完整页面架构（参考 Stripe / ReadMe 等高认可度 API 文档形态）：
   - **左侧 sticky 锚点导航**（功能域 → 接口两级；<lg 折叠为顶部横向滚动 chips）
   - **右侧内容流**：①总述（API 面是什么、与契约文档/分层纪律的关系）②鉴权模式（AT 如何传递、
     Bearer curl 样例、签发入口链接、资格语义与 401/403 边界）③统一信封与错误码（六码表，
     渲染自 `MANAGE_ERROR_CODES` 单一事实源）④分功能域 × 分接口
   - **每个接口**：方法 + 路径徽标行、权限徽标、描述、**入参表**（名称/类型/必填/默认/说明）、
     **出参说明 + JSON 返回示例**（代码块 + CopyCode 一键复制）、curl 示例（含复制）
3. 入口：API 令牌页底部主动链接（「接口在线文档 →」）；页面本身为二级页
   （admin-nav-guard `SECONDARY_PAGES` 登记，不进菜单）。
4. 路由形态：**单页锚点滚动**（v1 9 端点量级下单页 + 锚点最贴合阅读动线；端点增长后可拆域页，
   数据模块结构已按域分组预留）。

## 2. 数据源设计（单一事实源）

新建 `apps/web/src/lib/manage/api-docs.ts`：端点元数据模块（域 → 接口 → 参数表/示例），
**页面渲染的唯一数据源**；错误码表直接 import `MANAGE_ERROR_CODES` 渲染（码↔文案永不失同步）。
`docs/MANAGE-API.md` 保持人读契约版（新增端点时两处同步的责任写进两文件头注释）；
未来端点增多可由该模块生成 md（不在本期）。

## 3. 门禁与守卫

- 页面首位 `requireAdmin("site.admin")` + `isEffectiveSiteAdminOf` 不变量校验（同 api-tokens）。
- admin-entry-guard（首位守卫）/ admin-nav-guard（SECONDARY_PAGES 登记 + label/title 无菜单项豁免）
  自动覆盖；metadata title「管理 API 文档」。

## 4. 边界

- 不做 OpenAPI/Swagger 规范生成与交互式 try-it-out（v1 静态文档；写端点进入后随 M21 评估）。
- 不做在线 md 渲染 docs/MANAGE-API.md（页面与 md 是两种受众：在线页面向管理员，md 向开发者）。
- 页面不新增任何 API 能力——纯文档呈现，数据与实现解耦（实现变更须同步 api-docs.ts）。

## 5. 门禁基线

verify:all；页面渲染测试（总述/鉴权/错误码/域接口节渲染 + 未登录/版主 404）；E2E 补一条
「管理员可见文档页、会员 404」；浏览器实测截图呈站长验收。
