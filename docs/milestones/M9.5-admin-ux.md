## 1. 定位与边界

- **只做体验 + 板块图（含一处 schema 升级）**：不动权限模型（28 权限点）、不改任何 Server Action 的鉴权与审计语义；**唯一 schema 变更 = v2.4 板块图位规范化（§3.4.2：forums 增 `icon_key`、删空置旧列 `icon`，迁移 0015）**；新增的查询能力（分页/筛选/搜索）只加服务层查询函数；新增 action 仅限 §4 明列的少量补功能（公告编辑、投票重开、徽章收回、批量审核、批量撤销邀请码、板块图上传）。
- **前台零影响，唯一例外 = 板块图卡片**：全部改动限定在 `/admin/*`、`components/admin/*`、各域 admin 服务层；唯一触碰前台的是站长明示的 `ForumDirectory` 板块卡片插槽（§3.4.4），首页与 `/boards` 共用该组件、一处改动两处生效。
- **PC 优先**：每个菜单先把桌面端管理交互做对；平板（768）/手机（375）以「不溢出、可操作、信息可达」为底线做专项巡检（§3.6）。
- **M11 插槽思路**：板块卡片皮肤做成**参数化插槽**——遮罩的方向、斜率、透明度、是否遮罩全部收敛为 CSS 变量令牌，主题包按元素类型自由组合（换方向 / 斜切梯形 / 只压透明度 / 不遮罩等），多样性个性化由参数组合表达；本里程碑先立变量骨架与定稿默认档。

### 2.4 逐页缺陷清单（16 页，行号为开工销账线索）

> 「缺陷」指明确的行为问题；「改进」指体验提升。共性项（C1–C9）不重复罗列。

**用户与权限域**

- **users（用户管理）**：缺陷——默认空页；`limit(20)` 无分页。改进——列表增加注册时间/主题帖数展示（已有数据）；支持按 uid 精确直达；结果含状态徽章供辨识。
- **users/[uid]（用户详情）**：缺陷——台账取回 20 条只渲染 5 条，卡片标题却写「最近 20 条」（:256,261）；台账固定第 1 页无翻页（:41）；限制过期判断用字符串比较（:140-141）；授角色裸填板块 ID（:217-224）。改进——台账完整分页；板块作用域改下拉；页头统计（注册时长/发帖量）。
- **authz（角色列表）**：缺陷——删除自定义角色无确认（C3，级联删除却最危险）；删除前看不到影响面（授权数/持有人数服务端算了只进审计，authz/admin.ts:226-229）。
- **authz/[roleKey]（授权矩阵）**：缺陷——授权在主矩阵、撤销在页底另一张表，入口分裂（:115-122 vs :131-154）；已授权再点只是幂等重复授权；每权限点一次提交整页刷新；撤销无确认（C3）。
- **authz/forum/[fid]（板块视角）**：缺陷——table 无 overflow-x-auto（§2.2 溢出实锤）；纯只读却无「去修改」出口，两个视角页互无链接；无板块切换器，只能拼 URL。

**内容治理域**

- **review（内容审核）**：缺陷——队列 `limit 50` 静默截断无分页；无按板块/类型筛选；无批量通过/驳回。改进——卡片加内容摘要行（高频页按大本营标准重做）。
- **reports（举报处理）**：缺陷——`reportQueue(tab)` 无分页无上限防护；无板块筛选；无批量忽略。改进——被举报内容摘要行。
- **poll（投票管理）**：缺陷——N+1（C9）；`limit 50` 不可见旧投票；关闭后无重开入口（误关只能动库，admin.ts:16 注释自认）；删除是不可逆三表删除但确认弹窗无影响面提示。
- **pm（私信管理）**：缺陷——uid 筛选是内存过滤，语义系统性遗漏（C2 最严重实例）；筛选只认数字 uid；统计双全表 COUNT（C9）。改进——空态区分「无消息」与「该用户最近无消息」。
- **announcements（公告）**：缺陷——**公告无编辑能力**，改错别字只能下线重发（page.tsx:52-106 只有创建+下线）；`limit 20` 写死历史不可达；导航/友链是裸 textarea 逗号分隔，无校验无条目化；时间原样输出 DB 字符串，与 invites 的 fmtDate 口径不一（:129）。

**运营域**

- **invites（邀请码）**：缺陷——无状态 tab（可用/已用/过期混排）、无批次筛选、`limit 100` 后旧码不可管理；生成成功后新码不高亮不置顶无一键复制。
- **badges（徽章）**：缺陷——字典空时页面静默空白（C5）；授予无确认且**不可撤销**（无收回徽章能力，服务层也没有）；无授予记录列表。
- **points（积分管理）**：缺陷——手工调整（可负）无确认（C3）；调整后无最近调整记录展示，无法在本页核对台账；用户名手输（C7）。
- **logs（审计日志）**：后台标杆页（唯一分页+筛选+CSV）。改进——分页换页码组件；详情 JSON 列加展开查看（现在 `max-w-md truncate` 一行）；移动端隐藏次要列。

**系统与站点域**

- **settings（站点配置）**：缺陷——单页 7 表单 400 行无锚点无分签；SMTP env 未配置时显示默认 `smtp://127.0.0.1:1025`，管理员无法区分「没配」和「配了本机」（page.tsx:41,89）；频控只展示 member/admin 两角色，其他角色配置「保存时原样保留」但不可见（:389）；秒数单位无换算辅助（editWindowSec 默认一年=31536000）。
- **logo（LOGO 管理）**：缺陷——上传链路断裂：超 512KB 让管理员线下跑 `scripts/logo-resize.py`（page.tsx:15,44）；上传成功新项无高亮；无客户端预校验。
- **forums（板块管理）**：缺陷——双全表查询可合一（C9）；错误横幅 `?err=` 刷新复活；父级下拉全角空格缩进层级不可读；**无板块图管理**（§3.4）。
- **forums/[fid]（编辑板块）**：缺陷——无「未保存更改」保护；前缀空态违反 EmptyState 约定（C5）；无板块图管理。
- **emojis（表情管理）**：缺陷——组内表情查询无上限，500 枚 ≈ 2500 个 form 节点 DOM 失控；排序逐位 ↑↓ 整页刷新（C6 最痛实例）；批量上传失败只有单条错误无逐文件明细；空态手写灰字（C5）。
- **dashboard（看板）**：缺陷——3 全表 COUNT 实时执行（C9）；柱状图单日值仅 hover title 移动端不可触达、无峰值标注；全表 COUNT 无缓存；无环比。

## 3. 设计基线

### 3.1 后台布局壳（Step 1）

`AdminShell` 重做为经典后台骨架，脱离前台 `max-w-6xl` 容器：

- **PC（≥lg）**：左侧固定侧栏（`lg:fixed lg:inset-y-0 lg:left-0 lg:w-56`，`bg-card` 底 + `border-r`，独立滚动），站点名「清风社区 · 后台管理」置顶；内容区 `lg:pl-56`，内部 `max-w-5xl` 控制行宽。侧栏不再依赖前台 header 的 `sticky top-20`。
- **平板（md）**：走抽屉（已拍板 §8-1），与手机同构。
- **手机（<md）**：保留汉堡 + Sheet 抽屉，抽屉内导航分组视觉与 PC 侧栏一致；顶栏加当前页标题。
- 导航激活态增强：左侧 2px 主色竖线 + `bg-accent`；二级页（users/[uid]、forums/[fid]、authz/*）父项同步高亮。
- 二级页统一页头模板：`← 返回xxx` + 标题 + 关键统计 + 主操作右置。

### 3.2 列表基建（Step 2）

- **分页**：服务层统一约定 `listXxxPage(filters, page) → { items, total }`（**后台默认 PER_PAGE=20，logs 维持 50**，已拍板 §8-3）；页脚统一 `共 N 条 · ` + 复用 `content/pagination.tsx`（basePath 携带现有 query）。天然小集合（板块树、角色列表、徽章字典、LOGO 池、表情分组）不做分页。
- **筛选栏**：统一 `AdminFilterBar`（服务端组件）：GET 表单 + 关键词输入 + select 筛项 + 「筛选/重置」；筛选状态持久在 URL；各页筛项按 §4 明细执行。
- **空态**：巡检全部违反 EmptyState 约定的手写灰字，统一换 `EmptyState`。
- **Flash 反馈**：统一 `AdminFlash` 组件（读取约定 searchParams 渲染，`role="alert"`/`role="status"`，成功条带关闭按钮；URL 回显模式保留）。新增写入类操作通过高亮参数定位新项（§4.15 invites 等）。
- **UserPicker**：原生 `<datalist>` 方案（零 JS）：输入用户名 → datalist 供「用户名 (uid)」选项，提交仍传用户名由服务端解析。替换 badges/points/pm/users 四处手输。
- **ForumSelect**：服务端组件 `<select>`（按权限过滤，层级缩进用 `&nbsp;`），替换 users/[uid] 裸板块 ID、forums 父级下拉、review/reports 板块筛选、authz/forum 板块切换器。

### 3.3 交互基线

- **确认保护矩阵**（收口时写进 CLAUDE.md）：删除/级联删除/撤销授权/收回角色/**积分调整（含正负）**/施加或解除用户限制/**收回徽章** → 必须 `ConfirmSubmit`，文案带影响面摘要；开关/排序/低风险保存 → 直接提交。本次补齐 4 处缺失：角色删除、授权撤销、积分手工调整、徽章授予。
- **排序范式统一**：emojis 的逐位 ↑↓ 改为「sortOrder 数字输入 + 单条保存」（与 forums 范式一致），分组与表情统一；不做拖拽。
- **批量操作**：只做两处——审核队列「批量通过/驳回」（§4.2）与邀请码「按批次撤销」（§4.15）。
- **时间格式**：抽 `lib/admin/format.ts`（Intl 封装，invites 的 fmtDate 上移），后台全部时间列统一口径。

### 3.4 板块图：旧图复原 + 现代底纹渐变卡片（Step 7，站长 2026-10-29 追加）

#### 3.4.1 旧库考古（2026-10-29 实探）

| 事项 | 结论 |

#### 3.4.4 前台板块卡片（唯一前台改动点，形态已定稿）

`ForumDirectory` 卡片（现 `rounded-xl border bg-card p-4`，forum-directory.tsx:20）加「底纹渐变」视觉层。**站长 2026-10-29 定稿形态**：

- **左侧图区 + 右向渐隐 + 文本右移**：卡片左端为板块图展示区（底纹渐变上铺板块图），遮罩**向右渐隐**融入卡片底色；文本区整体略微右移，让出图区展示空间。结构：卡片内 grid（图区列 + 文本列），图区 `object-cover` 铺满列高，右缘由遮罩渐隐，文本列起点落在渐隐终点之外（天然无重叠、对比度稳）。
- **遮罩斜率（梯形底纹）**：渐隐边界支持**斜率**——垂直边界（90deg）是矩形图区；斜切角度（如 105–115deg）让图区右缘呈斜线，卡片呈现**梯形底纹**。实现走 `linear-gradient` 角度参数，角度即令牌变量，纯 CSS 零 JS。
- **无图板块**：纯渐变底纹（同参数形态）+ 板块名首字符低透明大字水印，图区不空版。
- **约束**：文本对比度过 M10.5 基线；`prefers-reduced-motion` 不加动画；暗色主题语义色自动适配；图仅装饰（`alt=""`，板块名另有文本）。

**遮罩插槽参数集（M11 主题插槽骨架；本里程碑立变量 + 定稿默认档，另做一档备用档验证参数生效）**：

| CSS 变量 | 语义 | 默认（定稿档） |
|---|---|---|
| `--band-width` | 图区列宽 | `7rem` |
| `--band-angle` | **遮罩渐变角度 = 方向 + 斜率**：90deg 垂直边界；>90deg 斜切梯形；180/270deg 换成上下遮罩 | `105deg` |
| `--band-fade` | 渐隐过渡宽度（渐变 stop 区间占比） | `38%` |
| `--band-mask-color` | 遮罩终点色 | `var(--card)` |
| `--band-mask-mode` | 遮罩模式：`fade` 渐隐 / `none` 不遮罩（硬边界全展示）/ `dim` 只整体压透明度 | `fade` |
| `--band-dim-opacity` | `dim` 模式的整体透明度 | `0.85` |
| `--band-img-fit` / `--band-img-position` | 图片适配方式/焦点 | `cover` / `center` |

主题包（M11）切换板块卡片皮肤时**只改这组变量**：遮罩方向（左右上下）、斜率（直角/梯形/斜切）、透明度、完全不遮罩即可任意组合——即站长要求的「按元素类型定遮罩方向、或不遮罩、或只遮透明度、支持斜率」的多样性个性化插槽设计。

## 4. 各菜单功能设计（逐菜单目标态，2026-10-29 打磨稿）

### 4.0 布局与导航（壳）

见 §3.1。补充：侧栏底部固定「返回社区」+ 当前登录身份行；`/admin` 根路径重定向到 `/admin/dashboard`（现为独立入口页，二选一——实现时按现状评估，倾向保留入口页作 404 兜底）。

### 4.1 看板 dashboard

- **定位**：站长每天打开的第一屏，只读。
- **信息架构**：总量行（注册/主题/帖子/今日登录）+ 三趋势卡（注册/主题/回帖，30 天柱图）。

## 9. 内容治理体系（站长 2026-10-29 追加批次，设计稿待确认）

> 站长原话要点：主题/回帖的治理放前台还是后台；版主/管理员现有的主题屏蔽/禁用/删除、回帖删除/屏蔽能力盘点；被禁用/注销用户在各处的展示（帖在人没了）；用户举报能力；参考现代系统，主题状态分「完全禁用（不可编辑不可再审核）」与「下架打回审核（可编辑可重新申请上架）」两类。

### 9.1 现状盘点（2026-10-29 探查，证据带行号）

**状态机**：五态 `visible/pending/rejected/hidden/deleted`（schema.ts:41-42），读取侧不变量「主题与首帖任一不可见即 404」（DESIGN-MODEL §4）。关键结论：

| 站长要的语义 | 现状 | 结论 |
|---|---|---|
| 下架打回审核，**可编辑可重新申请上架** | **已有且完整**：`rejected` 态作者可见+可见驳回理由+编辑保存自动转 pending 重提（rules.ts:78、mutate.ts:518-537、t 页 destructive 横幅） | 保留，无需改 |
| **完全禁用**，不可编辑不可再审核 | **缺失**。最接近的 `hidden` 版主可恢复、`deleted` 版主可恢复——都是可逆的；没有「不可编辑、不可重审、不可恢复」的终态 | **补第六态 `disabled`（内容封禁）**，§9.2-B |
| 主题屏蔽/禁用/删除 | 屏蔽（visible→hidden）、软删（→deleted）、恢复均有（前台帖子页按钮 + 后台回收站） | 基本完备 |
| 回帖删除/屏蔽 | 与主题完全同构（每层楼同一套 per-post 操作，t/[tid]/page.tsx:376） | 完备 |

**入口分工现状**：前台帖子页已有就地治理（编辑/删除/屏蔽/恢复/举报，post-actions 每层楼渲染）；后台是队列形态（/admin/review 审核+回收站）。**缺口**：

1. **后台无「内容管理」定位页**：版主拿到一个老帖 URL/关键词，后台无处搜索定位并治理（只能去前台找帖子页）。
2. **后台无屏蔽入口**（hidePost 的页面入口只在前台帖子页）；**前台无通过/驳回**（pending 帖在帖子页版主不能就地过审，必须去后台队列）。
3. **主题锁定 `threads.is_locked` 读侧完备、全仓库无写入口**（回帖拦截/徽标/`thread.replyLocked` 豁免权限点都在，就是没人能锁定）；**置顶 pinLevel、精华 isFeatured 同样只有读侧**。
4. **`admin.recycle` 权限点空转**：类型与注释都在，无任何页面真正 require；回收站实际门禁是 requireModerator。
5. `transitionContent` 无 from→to 白名单（约束分散在各调用方业务检查），状态机没有中央定义。

**用户侧现状**：

- **注销**：展示体系完备（UserBadge「已注销」/ 不渲染个人链接 / 个人页 404 / 迁移占位账号「已注销用户#uid」），但**自助注销功能不存在**（state=deleted 仅迁移管线写入）。
- **封禁**：`ban` 用户的内容/头像/名字在公开页**照常显示、无任何标记**（仅个人页有「已封禁」徽标）；会话惰性失效（每请求查全局 ban，效果等同踢出，sessions 行未删）。
- **举报**：链路完整（前台按钮+Dialog+无 JS 确认页+后台处理+通知举报人）；小瑕疵：不排除举报自己的帖子。

### 9.2 设计（前台/后台分工原则 + 六项改造）

**分工原则**：**前台 = 就地治理**（上下文内的单条操作，版主在帖子页直接处理）；**后台 = 定位与队列**（跨内容搜索定位、批量、审计、回收站）。现代系统（Discourse/Reddit/B 站创作者侧）均为双入口并存。据此：

- **A. 后台新增「内容管理」页 `/admin/contents`**（菜单「内容」组）：标题关键词搜索 + 板块筛选 + 五态（含 disabled 六态）筛选 + 类型（主题/回帖）筛选 + 分页；行内操作与前台同 action 同权限（通过/驳回/屏蔽/封禁/删除/恢复/锁定/置顶/精华）；回收站（removed）并入为状态筛选之一，「已删隐内容」tab 保留原链接兼容。门禁：`forum.moderate` 作用域（服务层过滤所辖版块）**或 `admin.recycle`（可看全站 hidden/deleted/disabled）**——`admin.recycle` 从空转落地为「全站回收站视角」。
- **B. 状态机补 `disabled`（内容封禁，终态）**：schema `CONTENT_STATES` 增枚举值（迁移 0015 合并或 0016）+ DESIGN-MODEL §4 状态图更新。语义：仅版主可从 `visible/pending/rejected/hidden` 打入（理由必填、通知作者）；**对非版主与作者均不可见**（同 hidden 读取口径）；作者不可编辑不可重提；版主不可恢复，只能 → `deleted` 彻底删除。同时给 `transitionContent` 立中央白名单（from→to 矩阵 + 谁可执行），把分散的约束收拢：
  ```
  pending→visible|rejected（版主）   visible→hidden|disabled（版主）
  rejected→pending（作者重提）       hidden→visible|deleted（版主）
  deleted→visible（版主恢复）        disabled→deleted（版主彻底删）
  ```
- **C. 锁定/置顶/精华补写入口**（前台帖子页版主操作区 + /admin/contents 行内）：锁定= `isLocked` toggle（审计 + 徽标即时生效，`thread.replyLocked` 豁免不变）；置顶= `pinLevel` 0/版块1/全站2 选择（按权限递减：版主限本版块，site.admin 全站）；精华= `isFeatured` toggle（版主）。
- **D. 前台 pending 帖就地过审**：帖子页版主对 `pending` 帖渲染「通过/驳回」（同后台 action）——版主看到待审内容不必跳后台。
- **E. 封禁用户的展示策略**（推荐维持现状 + 后台补标记）：公开页维持「内容照常显示、无标记」——避免公开羞辱（Reddit/Discourse 同口径）；**后台**内容管理/审核/举报队列给封禁中的作者加「已封禁」小徽标（版主决策上下文需要知道作者状态）。自助注销功能不在本批（展示逻辑已完备，功能本身另行立项）。
- **F. 举报小修**：举报按钮排除自己的帖子；其余不动。
