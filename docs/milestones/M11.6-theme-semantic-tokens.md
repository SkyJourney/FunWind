## 1. 问题

M11.1 §1.2 原定「qy2010 现有 qy2010.css 全部值数据化（语义色 15 项、阴影、radius、表面组、band 参数、宋体栈）」。实际引擎的包定义只有两块：

```
ThemePackDefinition = { surfaces: Record<SurfaceId, { light; dark? }>; pwa? }   // 三层 .strict()
```

所以 qy2010 只有 `surfaces` 与 `pwa` 进了数据库，**语义色、圆角、阴影、字体、板块卡参数一直留在 `qy2010.css`**。后果：

- 这个包无法在后台改色，也不能导出为完整的包；
- 引擎的「换主题不换 DOM」不变量在语义层不成立——同一个包的数据分在代码和数据库两处；
- 情怀包 primary 文字压在淡底上不足 4.5:1（M11.3.1 遗留），改它要改代码并发版。

### 2.2 渲染与注入

- 选择器：浅色 `:root[data-pack="id"]:not([data-mode="dark"])`，深色 `:root[data-pack="id"][data-mode="dark"]`（`surface-render.ts:199,205`）。变量键由代码模板与 `SurfaceId` 白名单生成，值只来自 zod 字段；透明度用 `color-mix(in srgb, #hex P%, transparent)`。
- 注入：`layout.tsx:101-108` 以 default 包兜底，把所有带定义的包拼成一个 `<style data-fw-theme-pack>`，放在 `<body>` 首位。`data-pack` = 预览 cookie → 用户偏好 → 站点默认 → default。`data-mode` 服务端不输出，由 next-themes 客户端写，缺省按浅色。目录缓存 30 秒（`globalThis`），`packs.ts` 写成功会失效，直接改库要等 30 秒。
- **只有浅色档的包**：深色模式下回退到 default 包的深色档（`surface-render.ts:139`）；语义色靠 `dark.css`，qy2010 的 `:not([data-mode="dark"])` 让位。**新方案沿用这个语义，qy2010 仍然仅浅色。**
- 特异性：包选择器 `(0,3,0)` 高于 `semantic.css` 的 `:root (0,1,0)` 与 `dark.css` 的 `[data-mode="dark"] (0,1,0)`，所以令牌覆盖不依赖书写顺序。

## 3. 设计

### 3.1 数据模型：新增可选顶层段 `tokens`

```ts
ThemePackDefinition = {
  surfaces: …;                         // 不变
  pwa?: …;                             // 不变
  tokens?: {                           // 新增，整段可选
    light?: TokenSet;                  // 浅色档（缺省 = 全部继承 default 包）
    dark?: TokenSet;                   // 深色档；缺省 = 本包仅浅色，深色模式回退 default 深色（与现状一致）
  };
}

TokenSet = {                           // 每一项都可选；缺省 = 继承基础层（semantic.css / dark.css）的值
  colors?: Partial<Record<ColorKey, "#RRGGBB">>;   // 22 个固定键，见下
  radius?: "none" | "sm" | "md" | "lg" | "xl";     // → --radius: var(--fw-radius-<x>)
  shadows?: { s1?: Shadow; s2?: Shadow; s3?: Shadow };
  displayFont?: "system" | "songti" | "serif";     // 系统字体栈枚举 → --fw-font-display
  brandGradient?: { angle: number; from: "#RRGGBB"; to: "#RRGGBB" };   // → --gradient-brand
  band?: { width: number; angle: number; fade: number; dim: number; mask: boolean; maskColor?: "#RRGGBB" };
};

Shadow = { x: number; y: number; blur: number; spread: number; color: "#RRGGBB"; alpha: number };
ColorKey = background | foreground | card | card-foreground | popover | popover-foreground |
           primary | primary-foreground | secondary | secondary-foreground | muted | muted-foreground |
           accent | accent-foreground | destructive | destructive-foreground | success | warning | info |
           border | input | ring
```

遵守引擎既有不变式：键集合由代码决定，包数据只填值；**不接受任何 CSS 函数或自由字符串**；透明度一律结构化 `alpha`；字体只枚举系统栈（不做字体文件上传，沿用 `THEME-AUTHORING.md` §8）；所有数值有范围（如阴影 `blur 0–80`、`alpha 0–1`、`band.width 0–16 rem`）。

qy2010 的 41 条声明落位：

| 声明 | 落位 |
|---|---|
| 22 个语义色 | `tokens.light.colors`；`card-foreground`、`popover-foreground` 解析为 `#33332f`，`success` 为 `#166534`，`info` 为 `#3b82f6` |
| `--radius: var(--fw-radius-sm)` | `radius: "sm"` |
| `--shadow-1..3` | `shadows`：`{0,1,2,0,#786428,0.10}`、`{0,4,12,0,#786428,0.14}`、`{0,12,32,0,#786428,0.20}`（`rgb(120 100 40)` 即 `#786428`；`color-mix(in srgb, #786428 10%, transparent)` 与 `rgb(120 100 40 / 0.1)` 在 sRGB 下等价） |
| `--fw-font-display` | `displayFont: "songti"` |
| `--gradient-brand` | `brandGradient: { angle: 120, from: "#9bcba5", to: "#efe9b5" }` |
| 6 个 `--band-*` | `band: { width: 8.5, angle: 90, fade: 0, dim: 1, mask: false }` |
| header / tabbar 的 5 条 | 已在 `surfaces`，直接删 |
| `--page-bg` | 底色由 `--background` 跟随；**纸纹见 §6 取舍 D1** |
| `--theme-name` | 无消费方，丢弃 |

### 3.2 渲染

扩展 `cssTextForPack`（两个注入出口都调它，**不用改调用点**）：为 `tokens.light` 追加到浅色块、`tokens.dark` 追加到深色块。键由代码里的固定映射表生成（`primary → --primary` 等）；阴影序列化成 `X Ypx Bpx Spx color-mix(in srgb, #hex P%, transparent)`；只输出提供了的键。新增 `scope` 参数，供编辑器的令牌预览把同一份变量限定在一个预览容器内，不污染编辑器自身。

### 3.3 校验

- zod 层：`.strict()`、`#RRGGBB`、枚举、数值范围；与 `surfaces` 同样先校验再注入，失败则 `definition = null`、不注入（退回 default 外观）。
- **对比度顾问**（纯函数，浏览器与服务端共用）：对一组固定配对计算对比度——`foreground/background`、`foreground/card`、`card-foreground/card`、`popover-foreground/popover`、`primary-foreground/primary`、`secondary-foreground/secondary`、`accent-foreground/accent`、`muted-foreground` 在两个底上、`destructive-foreground/destructive`，以及 primary / destructive / success / warning 文字在自己的 `/10` 淡底上（卡片底与页面底两种）。阈值文字 4.5:1。**只给警告，不阻止保存**（见 D2）。缺省的键用基础层的值参与计算。
- 内置包的达标由单测守住：`token-contrast.test.ts` 改为同时读取内置种子的定义（TS 数据），`default` 仍读 CSS。

### 3.4 内置包升级机制（此前没有）

种子是「按主键补缺」，已存在的行不会得到新字段。做两个小原语，均为一条幂等 SQL（`JSON_SET` / `JSON_EXTRACT`），放新文件，不动 `packs.ts`：

1. `backfillMissingSections(id)`：顶层段缺失才补（`tokens`、`pwa`），**永不覆盖已有段**；同条 UPDATE 里 `revision = revision + 1`（G-20，让已打开的编辑页能感知并发）。随 `bootstrapDb` 调用，所以重置库、安装向导、`db:bootstrap` 都走同一条路。
2. `swapIfUnchanged(id, jsonPath, oldValue, newValue)`：只有该路径上的值仍等于旧值才替换。用于品牌色微调这类**值变更**——站长改过的不会被覆盖，跳过并记日志。

后台再给内置包加 **「重置为内置定义」**（需确认，`revision + 1`）：站长想采纳升级时用。

### 3.5 删除静态条目

删除 `qy2010.css`、`globals.css:12` 的引入、`THEME_PACKS` 里的 qy2010 条目；`BUILTIN_THEME_COLORS` 里的 qy2010 色值保留（目录对缺 `pwa` 的行的兜底）。LOGO 联动改读一张极小的「内置包 id → public/logo 文件名」映射（§2.4）。

## 4. 边界（明确不做什么）

- 不做 qy2010 的深色版本（仍仅浅色）。
- 不做字体文件上传；不开放自由 CSS；不新增 surface。
- `default` 包的语义层仍在 `semantic.css` / `dark.css`——它是基础层，`tokens` 是覆盖层；不把基础层搬进数据库。
- 不自动更新站长编辑过的内置包。
- 不在本里程碑里调品牌色（见 §5 Step 6，迁移验证通过后单独做）。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 迁移悄悄改变了外观 | Step 0 的计算样式 fixture + 14 张视觉基线双重验收；先迁移、后换色 |
| 内置行缺 `pwa` 或与种子不一致，升级判断失准 | 补缺用「段缺失才写」而非整段相等；值变更用路径级 `swapIfUnchanged` |
| 开发库 / 线上直接改库后目录缓存 30 秒才刷新 | 文档注明；`packs.ts` 写入路径已失效缓存 |
| 数据库行校验失败 → 整包无样式 | 种子有效性单测；内置包不可删；失败时退回 default 外观而非报错 |
| `PackId` 联合收窄引发类型连锁 | 关键入口已用 `isKnownPackId`；其余由 `tsc` 暴露并逐个处理 |
| 编辑器单文件膨胀 | 令牌编辑器与 `ColorField` 全部新文件；`packs.ts` 零余量，新逻辑不进它 |
| 22 个字段的表单可用性 | 分组 + hex 输入 + 继承开关 + 逐字段错误 + 对比度面板；组件测试与六档矩阵覆盖 |

## 8. 测试规则

- 单测：schema 接受 / 拒绝矩阵（未知键、非法 hex、越界数值、非法枚举）；渲染黄金串；渲染输出里**不出现任何包内自由字符串**；对比度顾问（含 `#767676` 对白 4.54 这类公开基准值）；种子定义能通过校验。
- 集成（真实 MySQL）：补缺不覆盖、幂等、站长改过的被跳过、`revision` 递增、复制守卫、目录缓存失效。
- 组件：`ColorField`（合法 / 非法 hex、与取色块同步）、令牌编辑器（继承开关、浅深切换、对比度面板）、逐字段错误回显。
- E2E：沿用项目规范 G-15 / G-16 / G-19——每个提示参数有消费者、至少一条错误路径、保存失败不丢草稿、冲突保旧锁。
- 视觉：qy2010 的 14 张基线；布局矩阵新增编辑器场景。
- 每个新增测试做变异验证。
