## 1. 问题

M11.1 §1.2 原定「qy2010 现有 qy2010.css 全部值数据化（语义色 15 项、阴影、radius、表面组、band 参数、宋体栈）」。实际引擎的包定义只有两块：

```
ThemePackDefinition = { surfaces: Record<SurfaceId, { light; dark? }>; pwa? }   // 三层 .strict()
```

所以 qy2010 只有 `surfaces` 与 `pwa` 进了数据库，**语义色、圆角、阴影、字体、板块卡参数一直留在 `qy2010.css`**。后果：

- 这个包无法在后台改色，也不能导出为完整的包；
- 引擎的「换主题不换 DOM」不变量在语义层不成立——同一个包的数据分在代码和数据库两处；
- 情怀包 primary 文字压在淡底上不足 4.5:1（M11.3.1 遗留），改它要改代码并发版。

## 3. 设计

### 3.1 数据模型：新增可选顶层段 `tokens`

```ts
ThemePackDefinition = {
  surfaces: …;                         // 不变
  pwa?: …;                             // 不变
  tokens?: {                           // 新增，整段可选
    light?: TokenSet;                  // 浅色档（缺省 = 全部继承 default 包）
    dark?: TokenSet;                   // 深色档；缺省 = 本包仅浅色，深色模式回退 default 深色（与现状一致）
  };
}

TokenSet = {                           // 每一项都可选；缺省 = 继承基础层（semantic.css / dark.css）的值
  colors?: Partial<Record<ColorKey, "#RRGGBB">>;   // 22 个固定键，见下
  radius?: "none" | "sm" | "md" | "lg" | "xl";     // → --radius: var(--fw-radius-<x>)
  shadows?: { s1?: Shadow; s2?: Shadow; s3?: Shadow };
  displayFont?: "system" | "songti" | "serif";     // 系统字体栈枚举 → --fw-font-display
  brandGradient?: { angle: number; from: "#RRGGBB"; to: "#RRGGBB" };   // → --gradient-brand
  band?: { width: number; angle: number; fade: number; dim: number; mask: boolean; maskColor?: "#RRGGBB" };
};

Shadow = { x: number; y: number; blur: number; spread: number; color: "#RRGGBB"; alpha: number };
ColorKey = background | foreground | card | card-foreground | popover | popover-foreground |
           primary | primary-foreground | secondary | secondary-foreground | muted | muted-foreground |
           accent | accent-foreground | destructive | destructive-foreground | success | warning | info |
           border | input | ring
```

遵守引擎既有不变式：键集合由代码决定，包数据只填值；**不接受任何 CSS 函数或自由字符串**；透明度一律结构化 `alpha`；字体只枚举系统栈（不做字体文件上传，沿用 `THEME-AUTHORING.md` §8）；所有数值有范围（如阴影 `blur 0–80`、`alpha 0–1`、`band.width 0–16 rem`）。

qy2010 的 41 条声明落位：

| 声明 | 落位 |
|---|---|
| 22 个语义色 | `tokens.light.colors`；`card-foreground`、`popover-foreground` 解析为 `#33332f`，`success` 为 `#166534`，`info` 为 `#3b82f6` |
| `--radius: var(--fw-radius-sm)` | `radius: "sm"` |
| `--shadow-1..3` | `shadows`：`{0,1,2,0,#786428,0.10}`、`{0,4,12,0,#786428,0.14}`、`{0,12,32,0,#786428,0.20}`（`rgb(120 100 40)` 即 `#786428`；`color-mix(in srgb, #786428 10%, transparent)` 与 `rgb(120 100 40 / 0.1)` 在 sRGB 下等价） |
| `--fw-font-display` | `displayFont: "songti"` |
| `--gradient-brand` | `brandGradient: { angle: 120, from: "#9bcba5", to: "#efe9b5" }` |
| 6 个 `--band-*` | `band: { width: 8.5, angle: 90, fade: 0, dim: 1, mask: false }` |
| header / tabbar 的 5 条 | 已在 `surfaces`，直接删 |
| `--page-bg` | 底色由 `--background` 跟随；**纸纹见 §6 取舍 D1** |
| `--theme-name` | 无消费方，丢弃 |

### 3.2 渲染

令牌变量并入 `renderPackCssVars` 的 `root:light` / `root:dark`，`cssTextForPack` 与两个注入出口**不用改调用点**：`tokens.light` 进浅色块（`:root[data-pack=…]:not([data-mode="dark"])`），`tokens.dark` 进深色块。实现在 `lib/theme/token-render.ts`：

- 键由代码里的固定映射生成：颜色按 `COLOR_KEYS` 的顺序输出 `--primary` 等，不读包数据自己的键；只输出提供了的键，顺序固定；
- 阴影序列化成 `Xpx Ypx Bpx Spx rgb(r g b / a)`，**不用设计稿原写的 `color-mix`**：Chromium 把 `color-mix(…)` 的计算值写成 `color(srgb 0.47 0.39 0.16 / 0.1)`，与 Step 0 冻结的 `rgba(120, 100, 40, 0.1)` 对不上，而 `rgb(r g b / a)` 算出来就是 `rgba(…)`；
- 渐变显式写出 `0%` / `100%` 色标位置：省略时 Chromium 的计算值不带位置，与静态 CSS 的写法算出的值不相等；
- 渲染器对每个字段再检查一次类型与格式，不合格的整条跳过（不抛错、不输出），因为输出会被原样放进 `<style>`；
- 只渲染本包自己的令牌，**不继承** `fallbackDefinition.tokens`（基础层本来就在 CSS 里）；
- 设计稿里的 `scope` 参数**没有实现**：编辑器预览已经把 `renderPackCssVars` 的结果当内联 style 用，变量天然限定在预览容器内。Step 3 做令牌预览时再确认是否需要。

### 3.3 校验

- zod 层：`.strict()`、`#RRGGBB`、枚举、数值范围；与 `surfaces` 同样先校验再注入，失败则 `definition = null`、不注入（退回 default 外观）。
- **对比度顾问**（纯函数，浏览器与服务端共用）：对一组固定配对计算对比度——`foreground/background`、`foreground/card`、`card-foreground/card`、`popover-foreground/popover`、`primary-foreground/primary`、`secondary-foreground/secondary`、`accent-foreground/accent`、`muted-foreground` 在两个底上、`destructive-foreground/destructive`，以及 primary / destructive / success / warning 文字在自己的 `/10` 淡底上（卡片底与页面底两种）。阈值文字 4.5:1。**只给警告，不阻止保存**（见 D2）。缺省的键用基础层的值参与计算。
- 内置包的达标由单测守住：`token-contrast.test.ts` 改为同时读取内置种子的定义（TS 数据），`default` 仍读 CSS。

### 3.4 内置包升级机制（此前没有）

种子是「按主键补缺」，已存在的行不会得到新字段。三个原语放在 `packages/db/src/theme-pack-upgrade.ts`（`bootstrapDb` 在 `packages/db`，不能反向引用 `apps/web`），第一个参数是 `db`，值与 JSON 路径全部走绑定参数。每个原语一条 UPDATE，同条里 `revision + 1` 并刷新 `updated_at`（G-20：已打开的编辑页下次提交能感知并发）：

1. `backfillMissingSections(db, id, sections)`：`JSON_INSERT` 只在顶层段缺失时插入，**永不覆盖已有段**；多个段里有一个缺失就更新，且只插缺的；全部已存在时不写库，`revision` 不变。段名限定为字母开头的字母数字。
2. `swapIfUnchanged(db, id, path, oldValue, newValue)`：`path` 是段名数组（每段限定字母数字、`_`、`-`）；路径上的值仍等于旧值才 `JSON_REPLACE`，路径不存在或站长改过则跳过。用于品牌色微调这类**值变更**。
3. `resetToBuiltin(db, id)`：把 `definition` 恢复为种子里的版本，只作用于 `is_builtin = 1` 的种子包；名称、说明、启停与素材清单不动。

写入 JSON 对象必须 `CAST(? AS JSON)`。在 MySQL 8.4 上实测：`JSON_SET(…, path, ?)` 传字符串参数会存成字符串标量（`JSON_TYPE` 为 `STRING`），用字符串参数做 `=` 比较永远不匹配；直接赋值给 JSON 列（`SET definition = ?`）则会按 JSON 解析。

审计、被跳过时的日志、目录缓存失效、权限判定与确认弹窗由调用方负责。调用方现状：`resetToBuiltin` 已由后台「重置为内置定义」调用（Step 3f，`lib/theme/pack-reset.ts`）；`backfillMissingSections` 已由 `seedSystemData` 调用（Step 4，`packages/db/src/bootstrap.ts`；`bootstrapDb`、重置库、安装向导、`db:bootstrap` 走同一条路）；`swapIfUnchanged` 尚无调用方，Step 6 微调品牌色时使用。

**回车键**：主题编辑器是一个大表单，保存按钮是默认提交按钮，浏览器的隐式提交规则是「文本框里按回车 = 点默认提交按钮」。在 jsdom 里对 4 个输入框实测（令牌颜色框、令牌数字框、浏览器主题色、主题名称），回车都会触发一次表单动作。名称框本来就这样，是预期行为；但 3a 把原生取色块换成文本框后，颜色框也有了这个行为，3c 又加了最多 47 个文本框。作者只想确认这一格，却会把整个主题包提交并升版本。站长同意现在改：`ColorField` 与 `NumberField` 的文本框接 `blockEnterSubmit`，按回车时 `preventDefault`。两种框每次合法输入都已立即生效，回车没有额外的「确认」可做；名称、说明框不接，在那里按回车保存仍是预期行为。组件测试里都放了对照：同一表单里的普通文本框按回车照常提交；表单级用例固定「令牌框与浏览器主题色按回车不触发保存，名称框按回车触发一次」。

**接线与已知陷阱**：

- 定义由「基础定义 + 编辑后的定义」合成。只做展开合并时，清空的令牌会从基础定义里复活，所以统一用 `withTokens` 写回：传 `undefined` 会删掉 `tokens` 键。
- 所有更新走函数形式（`onChange(previous => …)`），回调读最新状态，紧挨着的两次编辑不会互相覆盖。
- 切换浅 / 深档时内层容器换 key，上一档没写完的文本不会留到另一档。
- 保存草稿（G-19）：`pack-save-draft.ts` 在解析草稿时用 `tokensSchema` 校验 `tokens`，不合法就整份按损坏处理，不恢复半份草稿。编辑器写出的草稿里令牌一定合法，通不过只可能是存储被改坏或 schema 收紧过。

6. 写审计 `theme.pack.reset`：`before` = `{ revision, definition }`（重置前的完整旧定义），`after` = `{ revision }`。
