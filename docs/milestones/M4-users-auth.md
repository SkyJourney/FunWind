# M4 · 用户与认证

- 阶段：一·骨架 ｜ 覆盖模块：M02 ｜ 依赖：M3
- 状态：✅ 完成（2026-10-23）

## 目标

账号体系：注册（邀请制起步、开放制可切换）、登录会话、邮件密码重置（旧用户无密码的召回主路径）、
资料页、头像、封禁。

## 范围（做什么）

1. 会话：Cookie 会话（argon2id 密码哈希；`HttpOnly+Secure+SameSite=Lax`）；服务端 `getCurrentUser()` 贯穿 RSC。
2. 注册：`register.mode = invite | open` 配置化（两套都实现）；
   邀请码表与签发/核销；开放模式带邮箱验证 + 注册频控（IP/设备）。
3. 登录/登出；登录失败频控；**旧用户认领**：用户无 `password_hash` 时走「邮箱验证→设置密码」流程
   （邮件召回 M13 依赖此流程）。
4. 邮件：SMTP 抽象 + 邮件模板（重置/验证/邀请三类），本地 MailHog 捕获。
5. 资料页（读取 users 迁移数据：签名/等级/积分展示占位）+ 头像（旧算法 `attachment/avatar/{3位}/{2位}/` 读取，
   新上传仅占位接口）。
6. 封禁：`user_ban` 生效（登录拦截 + 全站只读提示），M5 接入角色。

## 边界（明确不做什么）

- 不做第三方 OAuth；不做手机号/短信；不做双因素。
- 权限体系（角色/权限点）属于 M5——本期仅「登录/未登录」与「封禁」两态。
- 注册反垃圾只做频控+邮箱验证，人机验证服务（Turnstile 等）留接口不实现。

## 测试规则

- 单测：argon2id 哈希校验、邀请码生成/核销幂等、频控窗口算法（≥90% 覆盖）。
- E2E：邀请注册→登录→登出；密码重置全流程（MailHog 收信→设新密码→旧会话失效）；
  旧用户认领流程；封禁用户登录被拒。
- 安全检查单：会话固定（登录后重置会话 ID）、用户枚举（注册/重置响应一致性）、Cookie 属性断言。
