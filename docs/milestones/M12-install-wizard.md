# M12 · 安装向导与零数据部署

- 阶段：三·完善 ｜ 覆盖模块：数据层基建 ｜ 依赖：M4（管理员账号体系）+ M5.5（schema v2）+ M9（站点配置基础）；前置：M1 的 bootstrap/seed
- 状态：⬜ 未开始

## 目标

让 FunWind 作为**可复用的论坛产品**独立部署：零数据从零安装即可运行；
「从青翼 phpwind 导入」只是可选路径（由 `migration/` 工具承担），不是项目运行的前提。

## 范围（做什么）

1. **Web 安装向导 `/install`**（分步）：
   环境自检（Node 版本 / 端口 / 磁盘权限）→ 数据库连接（表单填写或读环境变量，连接测试）→
   执行 schema 迁移（Drizzle 管线）→ 站点基础设置（站名 / 描述 / 默认主题 / 注册模式 invite|open）→
   创建超级管理员 → 写入 `install.lock` → 跳转后台。
2. **CLI 等价物**：`pnpm db:bootstrap`（读配置文件，无头/自动化部署用），与向导共用同一安装管线。
   安装种子（M5.5 定义）：三内置角色 + 权限词汇表 + `site_settings` 默认值（积分显示名、注册模式、积分规则初值）。
3. **安装管线事务化**：步骤状态机；失败可重试、中断不留半成品（重跑幂等完成或显式回滚）。
4. **安全**：`install.lock` 存在后 `/install` 全路由拒绝；重装需 CLI 显式 `bootstrap --unlock`（交互确认）；
   安装日志不落敏感信息。
5. **零数据运行保障**：空库站点全页面可访问、空态引导（「创建首个版块 / 发首个帖子」指引）——与 M3 空态用例同一套标准。
6. **可选导入指引**：安装完成页提供「从 phpwind 导入存量论坛」文档入口（指向 `migration/`），
   向导内不实现导入本体。

## 边界（明确不做什么）

- 不做 Docker 官方镜像发布/应用市场分发（M13 只做自部署 compose；镜像发布视需求另立）。
- 不做多站点/SaaS 化。
- 不做「导入预演/差异预览」等迁移增强（migration/ 已有的能力为准）。

## 测试规则

- E2E（临时空库容器）：走完整向导→管理员登录→空态首页→创建首个版块与帖子；
  同一流程 CLI 路径再跑一遍（两入口同一管线断言）。
- 防重装：lock 后访问 `/install` 各步全部拒绝；`--unlock` 后可重装（含管理员账号被替换的语义验证）。
- 中断恢复：安装中途 kill 进程→重跑安装成功完成，无脏表残留。
- 单测：安装步骤状态机、lock 校验、配置校验，覆盖率 ≥90%。
