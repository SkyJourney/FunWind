## 目标

1. 站长在本地 MCP 客户端配置一个 MCP server，凭按工具需求签发的最小域权限 Access Token 执行获准的后台操作。
2. **薄壳原则**：MCP 只做「工具定义 → API 调用 → 结果透传」的翻译，零业务逻辑、不直连数据库；
   权限、限流、审计全部由管理 REST API 层承担。

## 2. 范围要点（开工时细化）

1. 新 workspace 包（落点待 D3，建议 `apps/mcp-admin`）：stdio 传输；Node 24 + TS 严格模式；
   env：`FUNWIND_BASE_URL` + `FUNWIND_ACCESS_TOKEN`（不入库、不进代码）。
2. 建议首批读工具对齐已上线的 REST：站点统计、用户查询（资料/角色/限制/会话）、内容查询
   （列表/搜索/审核队列）、审计日志检索、推送/邮件日志查询。`whoami` 可用于连接诊断，仅在令牌授予 `identity:read` 时可用。
3. 写类工具仅可从已发布 REST 端点中选，逐个确认工具白名单及人工确认策略；不得将 REST 权限目录整表自动映射为工具。
4. 工具描述与参数说明用中文；输出做面向 LLM 的摘要化裁剪（大列表截断 + 分页提示，不在工具里藏重试逻辑）。

## 3. 边界（明确不做什么）

- **不做远程/对外 MCP 暴露**：仅 stdio 本地进程，不开 HTTP 服务。
- **不做多用户多租户**：单站长本地使用，token 是管理员个人凭证。
- **不绕过 API**：MCP 不 import @funwind/db、不写业务逻辑——越权/审计语义只在 API 层。
- 限流 429 直接透传给客户端，不做自动重试风暴类「贴心」逻辑。

## 5. 门禁基线

包内单测（工具→API 映射、错误透传、截断逻辑）；真实站点连通冒烟（站长本地 + 真 token）；
不动 web 侧门禁；使用说明（README）与本文档执行记录回写。

## 6. 风险

- **token 泄漏面**：本地 env 明文——文档明示仅站长本机使用；泄漏应急 = 后台一键吊销（M20）。
- **LLM 误操作**：写工具逐个开放、高危写永不进 MCP；审计 via:"api" 可追责。
- **API 演进失配**：MCP 依赖面收敛于 docs/MANAGE-API.md 契约，改端点须同步 MCP 包测试。
