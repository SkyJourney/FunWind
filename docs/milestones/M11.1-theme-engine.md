## 0. 核心抽象：区域表面 Surface

**不再按页面位置零散定义插槽。** 每个可定制区域 = 一个 Surface 实例，共享同一组可选能力；区域差异只体现在"启用了哪些能力 + 默认值"。渲染语义与主题定制语义统一。

### 0.1 Surface 能力模型（字段级）

```
SurfaceDefinition {
  id: SurfaceId                      // 枚举，见 0.2
  label: string                      // 后台显示名
  capabilities: {
    fill?:    SurfaceFill            // 背景填充
    overlay?: SurfaceOverlay         // 覆盖遮罩层（渐变透明度渐变在此表达）
    border?:  { color: Color; width: 0|1|2|3; style: "solid"|"dashed" }
    text?:    { primary: Color; muted: Color; link: Color }      // 可选
    blur?:    number                 // 0–24 px 整数
  }
  contentSlot?: ContentSlotSpec      // 区域自有内容（可选：logo/站名/横幅图/挂件）
}

ThemePackDefinition {
  pwa?: { themeColor: Color; backgroundColor: Color } // manifest / viewport / PWA 图标背景
  surfaces: Record<SurfaceId, SurfaceEntry>
}
```

**填充 Fill（`type` 判别联合）：**
- `{ type: "solid", color }`
- `{ type: "linear", angle: 0–359, stops: [{ color, alpha 0–1, position 0–100 }] }`（≥2 色标）
- `{ type: "radial", shape: "circle"|"ellipse", stops: 同上 }`
- `{ type: "image", asset: AssetRef, position: 九宫格枚举或百分比对（默认"50% 50%"）, size: "cover"|"contain"|"auto"|百分数, repeat: "no-repeat"|"repeat"|"repeat-x"|"repeat-y", blend: "normal"|"multiply"|"screen"|"overlay"|"soft-light"|"luminosity", opacity: 0–1 }`

**遮罩 Overlay（画在 fill 之上的第二层）：** 与 Fill 同构（solid/linear/radial/image），另加整层 `opacity 0–1`。板块卡"右向渐隐"、纯色遮罩、图片底纹（位置/尺寸/混合/不透明度）都是 Overlay 实例。

**AssetRef：** `{ poolFile }`——必须引用 decor 素材池内文件；**禁止 URL、相对路径、data URI**。

**Color：** `#RRGGBB` 严格格式；透明度由结构化 alpha 表达，输入不接受 rgba()/css 函数。

新增区域 = 注册 Surface 实例（能力集+默认值），组件挂 `data-surface="<id>"` 消费——**渲染语义与主题定制语义统一**。

### 0.3 渲染契约（不变式）

- 每个启用的 Surface 渲染为**固定 CSS 变量组** `--sf-<area>-*`：fill→多层 background 简写；overlay→独立变量组（::before/::after 或叠加层）；border/text/blur 各自变量。
- 变量键集合是**代码内白名单**（纯函数渲染器：包定义 → 变量键值对），**禁止把包内字符串拼进 CSS 选择器/属性名**；值只允许上述结构化类型的合法序列化。
- 回退链：包值 → default 包 → 内置 CSS 默认。包未声明某能力 = 用默认。
- 内置包保留静态 CSS + `data-pack`（零成本）；数据驱动值由 SSR layout 注入 `<style>`（首帧无闪烁），数据值优先级更高。两轨共存。

## 1. 包数据模型

### 1.1 `theme_packages` 表（schema v2.7，Drizzle 迁移 0021）

| 列 | 类型 | 说明 |
|---|---|---|
| id | varchar(32) PK | slug `^[a-z0-9][a-z0-9_-]{1,31}$`；保留字 `default/dark/system`；创建后不可改 |
| name | varchar(60) | 后台显示名 |
| description | varchar(200) | 可空 |
| schema_version | smallint | 包定义格式版本（当前 1） |
| definition | JSON | Surface 定义集（strict 校验后写入） |
| assets | JSON | 引用的素材池文件清单 `[{ kind: "decor"|"logo", poolFile, sha256?, bytes? }]`；definition 的 decor 引用同步生成，导入时重验文件并 remap |
| enabled | boolean NOT NULL default true | `default` 包强制 true 且不可改 |
| is_builtin | boolean NOT NULL | 内置包可编辑 definition、不可删除；导入同名包拒绝并提示 |
| revision | int unsigned NOT NULL | 乐观锁；每次写 +1 |
| created_at / updated_at | DATETIME | |

索引：PK(id)；`idx_theme_packages_enabled (enabled)`。用户偏好 `user_profiles.theme_pack`（varchar32）与站点默认 `site.theme.pack` 只存 ID；回退链：用户 → 站点默认 → `default`。

### 1.2 内置包种子（bootstrap 幂等只补缺）

- `default`：全部 Surface 用内置默认值（现 default.css 语义），`is_builtin=true, enabled=true`；**不可删除/停用**，definition 可编辑。
- `qy2010`：现有 qy2010.css 全部值数据化（语义色 15 项、阴影、radius、表面组、band 参数、宋体栈、themeColor `#116a92`，M11.6 Step 6 加深）；`is_builtin=true`。M11.6 Step 5c 删除静态 CSS，改为完全数据驱动；Step 6b 加深品牌色与次要文字色，并引入存量库升级机制。
- 种子 `INSERT IGNORE` 语义（补缺不覆盖）；站长编辑过的包升级/重跑后保持原样。

### 1.3 包导入/导出格式（完整包 = 配置 + 资源）

- 导出：`<id>.funwind-theme.zip`；根目录 `theme.json` 为 `{format:"funwind-theme-pack",formatVersion:1,package:{id,name,description,schemaVersion,definition,assets}}`，图片位于 `assets/{decor,logo}/<poolFile>`。资产清单含 kind、SHA-256 与字节数；内置 qy2010 的静态 LOGO 也会连同资源导出。
- 导入要求站长填写一个新的包 id（不覆盖现有包），总 ZIP ≤20MB、最多 32 个资源；拒绝 ZIP64/加密/data descriptor/非法或重复路径/未声明文件/CRC 或 SHA 不匹配。Definition 经 strict schema 与 capability 白名单校验；所有 PNG 再走魔数 + sharp 管线，成功入池后将旧文件名映射到新文件名再保存。
- **导入失败的清理语义（尽力而为补偿）**：新素材登记与包创建不是跨系统单事务（文件系统 vs 数据库）。导入素材通过 `preserveActive` 非激活入池，不切换 active，也不恢复旧 active 快照。包创建失败时逐项清理新增素材；若新素材已被并发设为 active 或被其他包引用，则拒绝删除并保留素材，清理异常或被拒会记录并告警（`warn=import-cleanup`）。**已知边界**：并发操作可能遗留未被任何包引用的孤儿素材，可通过定期运行 `pnpm db:gc-files --dry-run` 巡检并清理。设计权衡：完全原子性需要分布式事务或 saga 模式，复杂度显著增加；当前设计在 99% 场景下无副作用。素材池审计与 `theme.pack.create` 审计保留。Definition 编辑草稿仅在点击保存后入库；预览不持久化。

## 3. 测试规则（M11.1）

- **纯函数**：surface-schema/surface-render 合法/非法矩阵（每字段：合法值、边界值、非法值各≥1）；渲染输出只含白名单变量键。
- **集成**（临时库+临时 STORAGE_DIR）：包 CRUD、revision 冲突、种子幂等（bootstrap 重跑不覆盖）、decor 池全链路、回退链（停用→站点默认→default）、审计 before/after/revision。
- **E2E**：权限 404；建包→编辑→预览不落库→保存→前台生效；导入导出往返（含图片资产）；停用已选包回退；`default` 删除/停用被拒；恶意包（`url(`/`expression`/未知字段/超大）被拒且无残留。
- **视觉**：visual suite 扩 Surface 矩阵——`header/hero-brand/banner-announce/forum-band` × default/qy2010/自定义包（浅色）；数据包暗色回退 default-dark。
- **回归不变式**：换肤不换 DOM（结构与文本恒等）扩展到数据包；`prefers-reduced-motion` 下无新增动画；无 JS 时后台表单可保存（渐进增强）。

## 5. 边界（明确不做什么）

- 不做版块级换肤、用户自定义 CSS、任意 CSS/JS 注入、远程主题源（URL 拉取）。
- 不做 JS 动效挂件引擎（M11.2 装扮方案里静态图挂件起步）。
- 网页字体文件管线（@font-face 上传）暂缓：v1 展示字体只允许系统栈枚举；如需字体文件另立决策。
- 不做装扮方案按用户群差异化。

### 方向性决策（2026-11-01 站长实测 qy2010 后拍板）

- qy2010 **色调正确，但缺少旧站的图形化设计**（板块图、装饰图等）。这个缺口正是本引擎的动机：
  图片底纹/装饰资源在 M11.1 成为包的一等资产后，站长可在编辑器里把旧站图元素配置进任意包，无需改代码。
- **M13 正式上线不再迁就怀旧主题**：直接按新主题体系（本引擎）制作完整的新主题作为站点默认；
  qy2010 降级为可选情怀包保留。M13 的部署/迁移范围描述同步此决策（届时站点默认主题由站长在
  `/admin/themes` 用引擎创建，迁移器不预设站点默认主题）。
