# M10 · 投票与私信

- 阶段：三·完善 ｜ 覆盖模块：M08 / M09 ｜ 依赖：M6（发帖）+ M4 + M8（通知中心）；投票数据由 M5.5 迁入，**私信不迁移**
- 状态：⬜ 未开始

## 目标

补齐两个旧站功能的**交互层**：投票（147 个旧投票已迁入 `polls`）与私信（会话模型从空开始，旧私信留在旧库归档，不迁移）。

## 范围（做什么）

1. **投票**：帖子详情页投票块（渲染已迁数据，旧票只读）；新建投票帖（`threads.kind = poll`；单选/多选/截止时间/投票后可见结果）；
   投票动作 + 防重复（`poll_votes` 复合主键）+ 结果视图。投票作为帖子内的结构化块，创作入口并入 M6 编辑器的块机制
   （与门控同属 `:::` 容器指令家族，具体语法 M10 开工时定）。
2. **私信**（会话模型：`conversations` / `conversation_members` / `messages`）：会话列表 + 对话页；
   新私信发送（权限点 `pm.send` + 旧 `message_allow_send` / `message_max_send` 语义转 ABAC）。
   **接入通知中心**：发送发 `message.sent`，由 M8 管线写 `pm.received` 指针通知（`conv:{id}:pm` 聚合）；未读状态唯一来源为 `conversation_members.last_read_message_id`，打开会话联动已读。
   **系统消息不进私信**，统一走通知中心。
3. 两者按 `defineModule` 实现（poll/pm 模块，注册槽位与权限点）。

## 边界（明确不做什么）

- 不做图片选项投票（旧无实数据）；不做私信群发/附件/群聊。
- 不做聊天室（新需求，另立项）。

## 测试规则

- 组件测试：投票块（单/多选/截止态/结果态）。
- E2E：新建投票→投票→截止→结果；重复投票被拒（并发双击用例）；
  私信发送→对方未读→已读；无 `pm.send` 权限用户发送被拒；超量限频提示。
- 数据：旧投票渲染抽样 10 票与旧站对照。
