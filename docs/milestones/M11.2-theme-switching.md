## 1. 目标

在 M11.1 已交付的动态目录/SSR 注入/即时切换/回退链之上，补齐**运营调度**能力：
装扮方案（节日主题 + LOGO + 横幅一次配置）按时间窗自动生效与到期回退，无需 cron；
顶栏挂件位从静态 contentSlot 扩展为可调度的挂件集合。

## 2. 已随 M11.1 交付（不再列入验收）

- 双轨渲染：内置包静态 CSS + 数据包 SSR `--sf-*` `<style>` 注入 + `data-pack`/`data-surface` 消费。
- 切换服务：动态目录（30s TTL + invalidate）、用户偏好 → 站点默认 → default 回退链、
  外观页 / ThemeMenu / PATCH API 全部走动态目录；停用已选包前台即时回退（E2E 覆盖）。
- PWA：manifest 两色与图标底色读站点默认包 `pwa` 元数据（definition 校验字段，去硬编码）。

## 3. 范围与 Step 分解

> **2026-11-02 设计修订（站长拍板）**：原「`site.decor.plan` 单键 JSON」改为**通用运营排期引擎**。
> 理由：「某段时间内临时改变某处生效值」是一类共性需求（节日装扮、限时开注册、活动期发码额度……），
> 单键 JSON 只能服务装扮。表结构一次到位，本期只注册视觉类 effect；后续只加注册项，不改表。
> 冲突语义：按 effect 分区、分区内 `priority` 大者生效；边界接受 ≤30 秒缓存延迟。
> **顶栏挂件集合移出本期**：它与排期正交，捆在一起会让两件不相干的事互相拖累，另立小步。

**Step 1 · 数据模型**
- 新表 `campaigns`（迁移 0023，schema v2.9）：`effect` + `config`(json) + `starts_at`/`ends_at` + `enabled` + `priority` + `revision`。
- 时间窗左闭右开，`ends_at` 为空 = 长期；请求侧惰性判定（同公告横幅口径），无 cron。

**Step 2 · effect 注册表与读服务**
- `lib/campaigns/effects.ts`：`theme.pack` / `site.logo` / `site.hero`，配置 `.strict()`；未知 effect 与坏配置读写两侧都拒绝或忽略。
- `lib/campaigns/service.ts`：SQL 只做时间过滤，同 effect 选优是零 IO 纯函数。

**Step 3 · 读取链合成**
- `getSiteChrome()` 合成排期值，引用失效逐项回退常态；覆盖的是站点默认，不改用户偏好。
- 新增 `chrome.logoUrl` / `chrome.heroUrl`（`/brand/*` 不带 `?file=` 只读池当前项）；PWA 图标同步跟随。

**Step 4 · 写服务与后台 `/admin/campaigns`**
- 新建/编辑/启停/删除，同事务审计，所有写路径 revision+1；失败回显草稿，冲突禁保存（G-19/G-20）。

**Step 5 · 收口**
- 六档宽度布局矩阵、文档与 CHANGELOG 回写、全量门禁。

## 4. 测试规则

- 调度单测：窗口内/外/边界时刻生效与回退；无 schedule 立即生效；过期方案不残留。
- 集成：方案启用时 chrome 读取链联动（主题/LOGO/Hero），过期回退不残留；与用户自选优先级明确。
- E2E：装扮方案全链路与挂件位；视觉：节日包 × Surface 矩阵入 baseline。

## 6. 边界（明确不做什么）

- 不做按用户群/版块差异化排期；不做 JS 动效挂件引擎；不做远程主题源；Web Push 仍在 M13 后视需求。
- 不做顶栏挂件集合（见上方设计修订）；不做公告横幅图排期（公告自带时间窗与受众，两套叠加会互相打架）。
- 不做邀请码/积分的 effect 实现：本期只保证表结构与注册表能容纳。
- 不做「到点产生副作用」的排期（如活动结束发奖）：那需要 pending 行 + 批处理 + 幂等键，不属于读取覆盖。
