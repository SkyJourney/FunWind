## 1. 目标

让主题包从「后台可维护的数据」变成「运行时实时生效的站点外观」：动态包目录驱动 SSR 渲染与客户端即时切换，用户偏好/站点默认/停用回退全链路安全；并承接原 M11.1 的节日装扮时间窗调度与顶栏挂件位。

## 2. 范围与 Step 分解

**Step 1 · 双轨渲染接线**
- 内置包维持静态 CSS + `data-pack`；数据包由 SSR layout 注入每区域 `--sf-*` 变量 `<style>`（首帧无闪烁）+ `data-pack` 标记；组件统一 `data-surface` 消费。
- 交付物：集成测试（数据包变量注入正确、内置包不受影响）；`换肤不换 DOM` 断言扩展到数据包。

**Step 2 · 切换服务**
- `resolveEffectivePack`（用户 → 站点默认 → default；停用/删除安全回退）；目录缓存失效（保存/启停/删除 → invalidate + revalidate layout）；用户外观页 / ThemeMenu / PackOptionsRow / PATCH API 全部改读动态目录并即时切换（dataset + PATCH，失败回滚）。
- 交付物：集成测试（缓存失效、回退链、暗色回退）；E2E（用户切换→刷新保持→站点默认联动）。

**Step 3 · 装扮方案调度（承接原 M11.1 设计）**
- `site.decor.plan`：`{ name, pack, logo?, hero?, banner?, schedule?: { startsAt, endsAt } }`；请求侧惰性判定（同公告横幅口径 `startsAt <= NOW() < endsAt`），无 cron。
- 顶栏挂件位（header Surface 的 contentSlot 装饰项）：静态图、`aria-hidden`、尊重 `prefers-reduced-motion`；素材走 decor 池。
- 后台「装扮」管理页：方案卡片（日常/节日），启停/时间窗编辑，无 JS 回退与确认保护。
- 交付物：调度单测（窗口内/外/边界）；集成（启用→chrome 键联动、过期回退不残留）；E2E（建方案→生效→窗口边界→到期回退）。

**Step 4 · PWA 与文档收口**
- manifest `theme_color/background_color` 与 PWA 图标底色从站点默认包 Surface 值读取（去 qy2010 if/else 硬编码）；个人主题不影响全站安装图标。
- THEME-SYSTEM.md 切换引擎章节、CHANGELOG、visual baseline（动态包 × Surface 矩阵）收口。

## 3. 测试规则

- 调度单测：窗口内/外/边界时刻生效与回退；无 schedule 立即生效；过期方案不残留 chrome 键。
- 集成：目录缓存失效跨请求生效；用户偏好/站点默认/停用包三级回退；切换引擎输出的变量键与包 definition 一致（白名单断言）。
- E2E：动态包全链路（建包→启→设默认→前台生效→用户自选→停用回退）；挂件位渲染与无障碍；装扮方案到期回退。
- 视觉：动态包 × Surface 矩阵入 baseline；数据包暗色回退 default-dark 断言。

## 4. 门禁标准

| 层级 | 标准 |
|---|---|
| 提交前 | 同 M11.1 §4（lint/typecheck/单测） |
| Step 收口 | `pnpm verify:all` 全绿；新增集成/E2E 全绿；jscpd ≤ 基线 |
| 里程碑收口 | 全量 `pnpm test:e2e`、`pnpm test:visual`（含动态包矩阵）、`pnpm pwa:lighthouse` 100/100、站长目视验收（切换即时性/到期回退） |
| 分支纪律 | 独立分支 → PR → CI 双作业通过合并 main；不 force push |

## 5. 边界（明确不做什么）

- 不做按用户群/版块差异化装扮；不做 JS 动效挂件引擎；不做远程主题源；Web Push 仍在 M13 后视需求。
