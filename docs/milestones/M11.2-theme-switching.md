## 1. 目标

在 M11.1 已交付的动态目录/SSR 注入/即时切换/回退链之上，补齐**运营调度**能力：
装扮方案（节日主题 + LOGO + 横幅一次配置）按时间窗自动生效与到期回退，无需 cron；
顶栏挂件位从静态 contentSlot 扩展为可调度的挂件集合。

## 2. 已随 M11.1 交付（不再列入验收）

- 双轨渲染：内置包静态 CSS + 数据包 SSR `--sf-*` `<style>` 注入 + `data-pack`/`data-surface` 消费。
- 切换服务：动态目录（30s TTL + invalidate）、用户偏好 → 站点默认 → default 回退链、
  外观页 / ThemeMenu / PATCH API 全部走动态目录；停用已选包前台即时回退（E2E 覆盖）。
- PWA：manifest 两色与图标底色读站点默认包 `pwa` 元数据（definition 校验字段，去硬编码）。

## 3. 范围与 Step 分解

**Step 1 · 装扮方案数据与调度**
- `site.decor.plan`：`{ name, pack, logo?, hero?, banner?, schedule?: { startsAt, endsAt } }`；
  请求侧惰性判定（同公告横幅口径 `startsAt <= NOW() < endsAt`），无 cron。
- 生效时覆盖站点默认包/LOGO/Hero 的读取链（仅读取侧合成，不改用户偏好数据）；到期自动回日常。

**Step 2 · 后台装扮管理**
- 「主题管理」下的装扮页签：方案卡片（日常/节日），启停/时间窗编辑，无 JS 回退与确认保护。
- 挂件集合管理：header contentSlot 之上的多挂件位（静态图、`aria-hidden`、尊重 `prefers-reduced-motion`；素材走 decor 池）。

**Step 3 · 收口**
- E2E（建方案→生效→窗口边界→到期回退→挂件渲染与无障碍）；THEME-SYSTEM/CHANGELOG/visual baseline。

## 4. 测试规则

- 调度单测：窗口内/外/边界时刻生效与回退；无 schedule 立即生效；过期方案不残留。
- 集成：方案启用时 chrome 读取链联动（主题/LOGO/Hero），过期回退不残留；与用户自选优先级明确。
- E2E：装扮方案全链路与挂件位；视觉：节日包 × Surface 矩阵入 baseline。

## 5. 门禁标准

| 层级 | 标准 |
|---|---|
| Step 收口 | `pnpm verify:all` 全绿；新增集成/E2E 全绿；jscpd ≤ 基线 |
| 里程碑收口 | 全量 `pnpm test:e2e`、`pnpm test:visual`、`pnpm pwa:lighthouse` 100/100、站长目视验收（到期回退） |
| 分支纪律 | 独立分支 → PR → CI 双作业通过合并 main；不 force push |

## 6. 边界（明确不做什么）

- 不做按用户群/版块差异化装扮；不做 JS 动效挂件引擎；不做远程主题源；Web Push 仍在 M13 后视需求。
