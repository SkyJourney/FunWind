## 1. 现状审查（读源码得出，Step 1 再逐项实机复现）

| 现象 | 根因 |
|---|---|
| 所见即所得区没有边框 | `.fw-rich-editor` 在 `globals.css` 没有任何样式，编辑器没有容器外框与聚焦态 |
| 表格是无边框白框、删不掉、不能增删行列 | 只装了 `TableKit`，编辑器内没有表格样式；工具栏只有「插入」，没有表格上下文操作 |
| 工具只有原生 `title` 提示、有的点了没反应 | 原生提示有延迟且触屏不可见；「换行」序列化为单个 `\n`、「分隔线」在空文档里几乎无可见变化 |
| 没有插入图片工具 | `ImagePicker` 在编辑器外面，不是工具栏项 |
| 图片与附件不联动 | 内联图片 `purpose:"inline"` 不进附件面板；删附件不清正文引用，反之亦然 |
| 没有表情入口 | 旧表情已在迁移期展开为 `![表情](/emoji/{id}.gif)` 静态图，运行时**没有表情表**（DESIGN-MODEL「运行时无表情表」、BLUEPRINT 决策 15、M6.3「不做 emoji 面板」）；新写正文无处选表情 |
| 代码块没有语法高亮 | 渲染管线只透传 `language-xxx` class（`lib/sanitize.ts` 为高亮预留），**没有高亮步骤**；编辑器里的代码块也没有语言选择 |
| 回复只有页面底部表单 | 没有移动端的回复入口 |

### 1.1 Step 1 实测基线（2026-10-28，Chromium + jsdom，临时用例已删除）

逐个点击 13 个工具栏按钮（输入「测试文字」后全选再点击），并读取隐藏字段 Markdown 与编辑区 DOM：

| 结论 | 证据 |
|---|---|

| 编辑区与容器边框均为 `0px` | `.fw-rich-editor` 与其父元素计算边框都是 0 |
| 表格 `td/th` 边框 `0px`、背景透明 | 站长截图描述属实；工具栏之外**没有任何**表格操作按钮（插入后页面上的按钮清单里只有原有 13 项） |

| 「换行」点击后只多一个空行，文本里看不出变化 | 序列化为单个 `\n`，且位于选区替换后的空段落 |
| 门控块节点视图已有「类型」下拉与价格输入，标题条写着「🔒 门控」 | DOM：`fw-gate-head` 内含 `select` 与输入框；本里程碑把文案改为「锁定内容」并目录驱动 |
| 编辑区上方每次进入都会出现「发现一份未发送的草稿」提示（测试里同一会话重复进入所致，非缺陷） | 草稿机制正常 |

**§2.3 待证问题：已核实，服务端无需改动。** `registerPostFiles`（`lib/gates/attachments.ts`）本来就**从正文引用派生 `inline` 行**（先删后插、幂等），并且 **M10.6d 已规定「被正文引用的文件不再作为下载附件」**（提交里同一 `fileId` 既在附件列表又被正文引用时，只保留 inline 行）；归属校验（`file_uploads` 属主）对两种登记同一套。所以「已上传的图片附件 → 插入正文」在服务端天然成立，不需要改用途；前端只要把该条目从下载组挪到内嵌组展示即可。门控块里的图片引用也有对应的 `gateRefs`（带 `gateId` 的 inline 行），与「锁定内容」联动无额外工作。

**§2.7 待证问题：风险低。** 迁移 `verify:render` 与语法契约对代码块的断言是不带语言的 `<pre><code>`（`syntax-contract.ts`），而高亮只作用于带 `language-` 的代码块、**不做自动探测**，所以旧帖渲染形状不变；高亮对帖子页耗时的影响留到 Step 5 用大帖样本实测。

**§2.8 行内图片往返（jsdom）：** 行内表情 / 行首表情 / 两表情连写 / 文字夹图 / 带语言与无语言代码围栏 / Unicode emoji（含肤色修饰符）**全部逐字往返相同**。尚未验证的是编辑区 DOM 中图片节点是否与文字同一行（Image 扩展默认 `inline:false`），留到 Step 7 在真实浏览器里确认并按需 `inline:true`。

## 2. 设计

### 2.1 工具栏（Markdown 主流能力补全）

**能力边界取决于站点渲染器**：渲染管线是精简 GFM（只有表格与删除线，见 CLAUDE.md 硬约定 6），所以**不做任务列表、不做自动链接**；工具栏只放「渲染得出来」的语法。

| 分组 | 项 | 说明 |
|---|---|---|
| 文本 | 标题（H1–H3 下拉）· 加粗 · 斜体 · 删除线 · 行内代码 · 链接 · 清除格式 | 链接用小弹层（地址 + 文本），选中文字时直接套链接 |
| 块 | 无序列表 · 有序列表 · 引用 · 代码块（带语言选择，§2.7）· 分隔线 | 列表支持 Tab 缩进 / Shift+Tab 反缩进 |
| 插入 | **图片**（§2.3）· **表情**（§2.8）· 表格 · **锁定内容**（§2.4） | |
| 历史 | 撤销 · 重做 | |
| 右侧 | 切换源码 · 预览 | 与现有外壳按钮合并进工具栏同一行 |

交互规范：
- 全部按钮图标化（`lucide-react`），**即时 Tooltip**（桌面 hover / 聚焦，触屏长按），内容含名称与快捷键（⌘B / ⌘I / ⌘K …）；沿用 `ui/` 已有的 hover 组件，不引新库。
- 移动端：工具栏单行**横向滚动**（不换行占三行），触控目标 ≥ 44px；分组间用细分隔线。
- 去掉「换行」按钮（Shift+Enter 即硬换行，按钮既无反馈又易误解）。
- 无选区时不适用的按钮置灰而不是点了没反应。
- 往返保护不变：序列化仍经现有 `@tiptap/markdown` + 自定义规则；**不新增会改写原文的节点**。

### 2.2 编辑器外观与表格

- 编辑区：`rounded-lg border` + 聚焦环（`focus-within`），工具栏吸附在容器顶部（长文时 `sticky`），最小高度保持。
- 内容排版直接复用 `.content-md` 的同一套样式（标题 / 引用 / 代码 / 表格 / 列表），所见即所得名副其实。
- **表格**：边框与表头底色；光标在表格内时出现**浮动操作条**（上插行 / 下插行 / 左插列 / 右插列 / 删行 / 删列 / 切表头 / 删除表格）；Tab 跳格、末格 Tab 自动加行。

### 2.3 图片插入与附件联动

**核心原则：正文是唯一事实来源，附件面板里的「内嵌图片」是从正文派生出来的视图**，不另存状态，所以不存在「两边不同步」。

```mermaid
flowchart LR
  A[工具栏图片按钮 / 粘贴 / 拖入] --> B[选图 / 可选裁剪]
  B --> C[上传 purpose=inline]
  C --> D[编辑区插入图片节点 ![](/files/key)]
  D -->|派生| E[附件面板「内嵌图片」组: 缩略图 + 文件名]
  E -->|删除条目| F[移除正文中所有该 URL 的图片节点]
  D -->|用户在编辑区删图| G[条目随之消失]
  H[附件面板里已上传的图片附件] -->|「插入正文」| D
```

- 附件面板分两组：**内嵌图片**（派生，缩略图，可删除 / 可「在正文中定位」）与**下载附件**（现有逻辑不变，门控归属下拉保留）。
- 派生只认 `/files/…` 引用；`/emoji/…` 表情**不进**附件面板。
- 删除内嵌图片 = 删正文引用；文件本身由现有孤儿巡检 `db:gc-files` 回收，**不新增删文件路径**。
- 「已上传的图片附件 → 插入正文」：**待 Step 1 核实**服务端 `registerSourceFiles` / `resolveFileGrant` 能否让同一文件既是下载附件又被正文内联引用（图片可见性按引用它的帖子鉴权）。若不能，则「插入正文」= 把该条目从下载组转为内嵌组（同一文件、改登记用途），UI 上对用户表现一致。
- 源码模式同样适用：派生视图从 Markdown 文本解析图片引用，不依赖富文本节点。
- 上传中状态：工具栏图片按钮显示进度，提交按钮禁用的现有机制保留。

### 2.4 锁定内容（原「门控」）与可扩展的解锁条件

**更名（站长已定）**：用户界面里一律叫**「锁定内容」**。**边界**：存储语法 `:::gate{…}`、`getGateContent`、`hidden-md-guard`、迁移转换器、数据库表名、已有帖子**全部不变**；「门控」只保留为内部 / 文档术语。改动只在文案层（工具栏提示、节点视图标题、附件归属下拉、预览占位、锁卡片、设置与通知文案），Step 5 先出全站检索清单；由守卫测试断言「用户可见字符串不再含『门控』」（注释与标识符除外）。

**解锁条件做成「目录驱动」**（站长要求：可设置不同解锁条件，后续可扩展自定义条件）：
- 现状：条件固定为内置 `points` / `reply`（GATES.md §3，M6.1 站长定：新增条件应是**有设计、有测试的核心改动**，不是模块随手声明）——**这个约束不变**。
- 本里程碑只做**前端数据驱动化**：`packages/content` 的 `ConditionSpec` 增加面向编辑器的描述（显示名、说明、参数字段 `[{name,label,kind:number|text|select,min,max,…}]`），块视图与创作侧表单**按目录渲染**，不再写死「积分 / 回复」两个分支。
- 效果：以后新增一种条件（例如「关注作者」「积分达到 N」「用户组」）= ① `packages/content` 注册规格 ② `lib/gates/evaluate.ts` 判定 ③ 创作权限点 ④ 测试；**编辑器 UI 不用再改**。
- 块的节点视图：标题条「🔒 锁定内容」+ 解锁方式分段选择（**回复解锁 / 积分解锁 / …目录里有几种显示几种**）+ 该条件的参数输入；整体虚线边框 + 浅底色；内部可继续写任意块（含图片、表格）。
- **不在本里程碑**：新增具体条件类型；多条件组合（`all` / `any`）——数据模型支持，但存储语法 `unlock="…"` 只有单条件，组合需要语法扩展，另立设计（见 §5）。

### 2.5 移动端回复悬浮按钮（原「快速回复固定条」，站长实测后改）

- 帖子页 `<md` 才出现：右下角、底部 Tab 栏上方的 **48px 圆形按钮**，**没有背景层**（站长实测：整行固定条的背景层遮挡浏览，且点击后仍要跳到底部，名不副实）。不是第二个编辑器。
- 点击：瞬时跳到页面底部 `#reply` 区并立即聚焦编辑器（站长拍板：平滑滚动与聚焦不可兼得；全页只有一个编辑器实例，草稿 / 附件 / 上传状态零冲突）。
- **与底部回复区互斥**（站长要求）：`IntersectionObserver` 观察 `#reply` 区，进入视口 → 按钮缩小淡出；离开视口 → 回来。`transform + opacity`，时长走时长令牌，`prefers-reduced-motion` 下无动画（直接显隐）。
- 不可回复的状态（未登录 / 锁帖 / 无权限）：不渲染（与 `replyEntry.mode` 同源判定）。
- 键盘弹起时（`visualViewport`）按钮收起，避免遮挡输入。
- 就地输入的「真快速回复」（底部抽屉放完整编辑器）已评估并否决：会出现第二个编辑器实例，草稿 / 附件 / 上传状态要迁移，复杂度和风险高；如日后需要另立设计。

### 2.6 回复区与发帖编辑器布局

- 回复区、发帖页、编辑页三处共用同一套 `EditorShell`：统一外框、工具栏吸附、附件区折叠（默认折叠成「附件（N）」一行，展开才见列表），减少首屏被附件占去的高度。
- 「预览」与「切换源码」并入头部右侧（图标按钮，见 Step 9 实现）；预览结果以内联面板显示（保持现有 `/api/preview`）。

### 2.7 代码块语言选择与语法高亮

- **渲染侧**：新增一个 rehype 步骤，放在 `rehypeSanitize` **之后**、`rehypeHarden` 之前——高亮产物（`<span class="hljs-…">`）由我们自己生成，**不放宽 sanitize 白名单**（白名单仍只放行 `language-*`，作者无法注入任何自定义 class，P2-8 的防线不变）。库选 `lowlight`（highlight.js 的 AST 版，纯 JS、无 WASM、服务端渲染友好）+ `common` 语言集（约 37 种：js / ts / json / html / css / bash / python / java / c / cpp / csharp / go / rust / sql / yaml / markdown / diff / ini / xml / php / ruby / kotlin / swift …），再按需补站点相关的少数几种；**无语言标记的围栏不做自动探测**（保持纯文本，避免误着色旧帖里的 `[code]`）。
- **配色**：两套令牌（亮 / 暗）写进 `globals.css`，与站点主题一致，不引外部 CSS。
- **编辑侧**：代码块节点视图右上角加**语言下拉**（含「纯文本」），序列化为 ```` ```lang ````；编辑区内同样高亮（`@tiptap/extension-code-block-lowlight`，与渲染侧同一语言集，共用 `lowlight` 实例），源码模式不变。
- **风险点（Step 1 核实）**：迁移硬门禁 `verify:render`（渲染形状）与转换器⇄渲染器语法契约会因高亮后 HTML 变化而需要同步；高亮只作用于带 `language-` 的 `<code>`，旧帖无语言标记的围栏不受影响。渲染耗时对帖子页首字节的影响需实测（`perf:lcp` 与大帖样本）。

### 2.8 表情体系

**与既有决策的关系（需要站长确认推翻）**：BLUEPRINT 决策 15 / DESIGN-MODEL「运行时无表情表」/ M6.3「不做 emoji 面板」是 M5.5–M6 阶段的取舍；站长现在要求「旧表情复原 + 后台维护 + 现代 emoji 选择器」，等于**推翻**这几条。依据 CLAUDE.md 硬约定 2/2a，`emoji_id`（120–169）属于「URL 必须稳定的旧主键」，保留是合规的；新表是运行时能力，不含任何 `legacy_*` 列。

**三层结构**（一个面板、两个页签）：

| 层 | 内容 | 来源与维护 | 正文里的写法 |
|---|---|---|---|
| ① Unicode emoji（默认，永远存在） | **精选**约 300–500 个社区公认的主流 emoji，分类：笑脸 / 手势 / 爱心 / 动物 / 食物 / 活动 / 物件 / 符号；带中文关键词搜索、「最近使用」、肤色修饰符（仅手势类） | 仓库内静态数据（`lib/emoji/curated.ts`），**不进库、后台不可改**；随版本演进由开发维护 | 直接写入 Unicode 字符（utf8mb4 已支持，渲染为系统字体 emoji） |
| ② 旧版表情集（复原） | 旧站 50 枚（`emotion_id` 120–169，7 个分类） | 迁移时导入新表（旧库只读），静态图保持 `/emoji/{id}.gif` | `![表情](/emoji/{id}.gif)`（与迁移后旧帖完全一致） |
| ③ 站长自定义表情集 | 后台上传的新表情，可建分组 | 后台管理 | `![表情](/emoji/{id}.{ext})` |

**新表（schema v2.2，约 +2 表，由 M10.9 落地）**：`emoji_groups`（id、名称、排序、启停）、`emojis`（id、group_id、名称 / 关键词、`storage_key` 或静态文件名、格式、宽高、排序、启停）。旧 120–169 保持原 id，使 `/emoji/{id}.gif` 不变。

**后台表情管理**（`/admin/emojis`，门禁 `site.admin`，写 `audit_log`）：分组增删改排序、上传（复用上传管线：嗅探、重编码、GIF 保留动画、尺寸上限，如 ≤ 128×128 / ≤ 200KB）、改名 / 关键词、**停用（不物理删除）**——已发布正文里的引用永远不碎；只是从面板里消失。与板块管理「有内容仅归档」同一原则。

**编辑器侧**：
- 工具栏「表情」打开面板（桌面 Popover，移动端底部 Sheet；沿用 `ui/` 组件与弹层时长令牌）；搜索框 + 分类页签；点击即插入并保持面板（Shift 点击或选择后可连续插）。
- 需要让图片节点支持**行内**（`Image.configure({ inline: true })`），表情才能和文字同一行；该改动要过往返保护（`roundtrip-check`）并补用例。

   - **站长实测缺陷与取舍（2026-10-29）**：最初实现是「平滑滚动 + 立即聚焦」，站长实测**第一次点击不是滑过去的，是一步切换过去**。真实浏览器逐帧采样复现（第一次点击 `scrollY` 1 帧内 0→8499，第二次点击有 89 个中间位置），隔离实验：只滚动 = 平滑；只聚焦（`focus({ preventScroll: true })`）、先聚焦再滚动、先滚动再聚焦 = 全部 1 帧跳到底。结论：**编辑器的 `focus()` 即使带 `preventScroll` 也会把页面一步跳到它的位置并取消进行中的平滑滚动**；第二次点击平滑只因为编辑器已有焦点、`focus()` 成了空操作。可选方案：A 平滑滚动 + 滚动结束后再聚焦（已实现并验证过，但 iOS 上滚动结束后的聚焦不在用户手势内，多半唤不起软键盘）；B 瞬时跳转 + 立即聚焦（仍在手势内，可唤起键盘）。**站长选 B**，A 的 `scrollend` 等待逻辑已删除。这个坑已写进 `CLAUDE.md` 的「已知坑」。

## 3.1 增删改查审计（2026-10-29，站长要求：每个工具产生的内容都要把增删改查验证一遍）

**起因**：锁定内容「删不掉」「能嵌套」两个缺陷，都是只验证了「增」（能插进去）而漏掉「删」与「语法约束」。站长要求对**每个工具产出的内容**系统地验证 **增 / 查 / 改 / 删**。

**方法**：真实浏览器（Chromium，真实选区与键盘）里按工具逐项跑，分两层——
- **编辑器内**（`e2e/editor-crud.spec.ts`，17 个用例）：增 = 工具栏插入后隐藏字段出现预期语法；查 = 切源码再切回 Markdown 不变（往返稳定）+ 预览面板渲染；改 = 改级别 / 地址 / 语言 / 单元格 / 价格 / 解锁方式；删 = 再点取消 / 专用删除入口 / 键盘删除。
- **落库之后**（`e2e/editor-crud-publish.spec.ts`，6 个用例，串行）：增 = 发布一个含所有工具产出的帖子（含工具栏上传的图片）；查 = 发布后渲染（作者视角、访客视角）+ 重新打开编辑页完整读回、未编辑时提交原文；改 = 编辑页改后保存并看渲染与库里的条件；删 = 编辑页删后保存，**并断言库里的锁定内容行与正文图片引用被清理**。
- 两份 E2E 都加了**页面未捕获异常护栏**（`e2e/support/page-errors.ts`）：任何 `pageerror` 都让用例失败。

| 工具 | 增 | 查 | 改 | 删 |
|---|---|---|---|---|
| 加粗 / 斜体 / 删除线 / 行内代码 | 工具栏 → `**x**` 等 | 往返稳定；发布后 strong / em / del / code | 格式内继续输入 | 再点取消（**行内代码此前取消不了，见缺陷 3**） |
| 标题 H1–H3 | 下拉选级别 | 往返；预览 / 发布后 h2（**此前发布后是纯文本，缺陷 4**） | 换级别 | 选「正文」 |
| 链接 | 弹层，无协议补 https | 发布后 a[href] | ⌘K 带出原地址改新地址 | 「移除链接」 |
| 无序 / 有序列表、缩进 | 工具栏 | 往返；发布后 ul / ol | 互相切换、增减缩进 | 再点取消 |
| 引用 | 工具栏 | 往返；预览 / 发布后 blockquote | 块内续写 | 光标在引用里再点（选区越过末尾补的空段落时走「整体包裹」，Tiptap 标准语义） |
| 代码块 | 工具栏 | 往返；高亮与语言 class | 语言下拉 | 再点取消 |
| 表格 | 工具栏 | 往返；发布后 th / td | 改格、增行、增列 | 「删除整个表格」 |
| 分隔线 | 工具栏 | 往返；发布后 hr | — | 点选后退格 / 光标移入后退格 |
| 表情（Unicode） | 面板 | 往返；发布后文字 | 带肤色再插 | 退格删整个字符（含肤色） |
| 图片 | 工具栏上传 | 面板「正文图片」派生；发布后 img（**含独占一行的图片载入，缺陷 5**） | — | 键盘退格 / 面板「移除」；库里 inline 行清理 |
| 锁定内容 | 工具栏 | 往返；访客只见锁卡片；预览只见占位 | 价格、解锁方式 | **头部「删除」按钮 + 空块退格（此前删不掉，缺陷 1）**；库里锁定内容行清理 |
| 锁定内容的位置 | 总是插在最外层 | — | — | **套引用 / 列表 / 再插一个都被拒绝（此前能嵌套，缺陷 2）** |

**这一轮抓到的真实缺陷（5 个，均已修复并带回归；前 2 个是站长实测提出的）**
1. **锁定内容删不掉**：空块里 Backspace 无效（`isolating` 阻止退格合并出去），头部是不可编辑区，没有任何删除入口。修：头部「删除」按钮（可撤销）+ 空块里 Backspace / Delete 删除整块。
2. **锁定内容能嵌套**：块内再插、插进引用 / 列表、给含它的内容套引用，4 条路径都能生成语法不允许的结构（连 `::::` 长围栏都会生成）。修：工具栏总是插在光标所在**最外层块**之后（当前最外层块是空段落则替换）；`filterTransaction` 拒绝任何**新增**的非最外层锁定内容（粘贴 / 套引用 / 套列表），并提示；已有违规（旧数据）不阻塞其它编辑。
3. **行内代码取消不了**：加粗 / 斜体 / 删除线 / 行内代码共用一个禁用判断，光标在行内代码里时（代码标记排斥其它标记）连「行内代码」按钮自己也被置灰。修：每个按钮用自己的可用性判断，已激活时一律可点。
4. **发布后标题被剥成纯文本**：净化白名单没有 h1–h6，`## 章节标题` 发布后渲染成「章节标题」+ 换行。修：放行 h1–h6（**不放行任何属性**）；旧帖不受影响——转换器已把行首 `#` 转义，**`verify:render` 新增 `headingAppeared` 探测器（棘轮 0），31456 篇迁移帖 + 369 段隐藏正文渲染后 0 篇出现标题标签**；补 h4–h6 样式。
5. **（Step 7 引入的回归）独占一行的图片让编辑器损坏**：`Image.configure({ inline: true })` 后，Tiptap 段落解析会把「只含一张图的段落」拆成**顶层**的行内图片节点，文档不合法；编辑页里**点任何地方都抛 `contentMatchAt on a node with invalid content`、编辑器不再响应**。这类帖子（旧帖、新帖里图片独占一行）极其常见。当时的往返测试只比较 Markdown 文本、E2E 只看元素在不在，全绿而漏过。修：覆盖段落的 Markdown 解析，不拆「只含图片的段落」（新增显式依赖 `@tiptap/extension-paragraph`）；新增 `doc-validity.test`（22 种代表性 Markdown 逐个断言 `doc.check()` + 序列化一致 + 载入后继续编辑不抛异常；去掉修复后 8 项变红）。

**测试脚本节奏的坑（不是产品缺陷，已写进 CLAUDE.md）**：ProseMirror 的选区同步是异步的，脚本点击后紧跟按键会在旧选区上生效；Radix 弹层 / 菜单关闭时用 `setTimeout(0)` 延后把焦点还给触发按钮，紧接着重开会被关掉；撤销历史把 500ms 内相邻的编辑合并成一组；`TrailingNode` 会在文档末尾自动补空段落（点编辑区空白处会落进去、全选会包含它）；会员每日上传额度 20 次，反复重跑会耗尽（图片用例改用不限额的管理员）。
