# M11.1 · 节日装扮与自动切换（M11 子里程碑）

- 阶段：三·完善 ｜ 依赖：M11（插槽体系与素材位全部就位后开工）
- 状态：⬜ 未开始（2026-10-31 站长定稿：自动切换排本子里程碑，M11 先交付插槽设计/管理/配置引擎地基）

## 目标

运营一次节日装扮（圣诞 / 新年 / 动漫联动…）= 一键启用一个「装扮方案」，到期自动恢复日常——
不用 cron、不用发版，节前节后各点一次甚至零操作。

## 范围（做什么）

1. **装扮方案（Decor Plan）**：`site.decor.plan`（site_settings JSON）：
   `{ name, pack, logo?, hero?, banner?, schedule?: { startsAt, endsAt } }`。
   一份方案打包：主题包（→站点默认主题，含 §联动 自动切自带 LOGO）+ LOGO 池指定项 +
   Hero 图 + 顶栏纯图横幅（插槽 ① 扩展）。
2. **时间窗调度**：带 `schedule` 的方案在窗口内自动生效、过期自动回退「日常方案」——
   请求侧惰性判断（site-chrome 读取时比较 NOW() 与窗口），无 cron、无状态机；
   判定口径与公告横幅 `bannerAnnouncement` 相同（`startsAt <= NOW() < endsAt`）。
3. **顶栏挂件位（插槽 ④）落地**：顶栏右侧固定的小装饰位（图片，不可交互、`aria-hidden`、
   尊重 `prefers-reduced-motion`——v1 只放静态图，动效挂件另议）；素材走 brand-pool 同款管理。
4. **节日主题包**（按需）：如「圣诞青翼」`themes/xmas.css`，自带节日 LOGO 走 M11 §5 同一联动；
   LOGO 池已有节日概念素材（LOGO-POOL.md：圣诞/中国新年 ×5）可直接入池。
5. **后台「装扮」管理页**：方案卡片网格（日常方案 + 节日方案），启用/停用/时间窗编辑，
   复刻 LOGO 池管理形态（含无 JS 回退与确认保护）。

## 边界（明确不做什么）

- 不做按用户群/版块差异化的装扮（全站统一）。
- 不做 JS 动效挂件引擎（飘雪脚本等）；静态图挂件起步。
- 不做装扮历史版本管理与回滚（方案本身可随时改回）。

## 测试规则

- 调度单测：窗口内/外/边界时刻的生效与回退；无 schedule 方案立即生效。
- 集成测试：启用方案→chrome 键联动正确（theme/logo/hero/banner）；过期回退不残留。
- E2E：后台建方案（含时间窗）→ 前台生效 → 改系统时间不可行则以窗口边界时刻构造 → 到期回退。
