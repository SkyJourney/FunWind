## 二、通知镜像类（站内事件 → 邮件，本次切片主体）

原则：**低频高价值实时发；高频互动走每日汇总（digest），不实时刷屏**。全部走
`notification_preferences(channel=email)`，用户偏好默认关（与数据模型注释一致：站内全开、其它渠道默认关）。

### 第一期：安全强制类（mandatory，偏好不可关闭——对齐 NOTIFICATIONS.md §3）

| #   | 场景              | 触发源（事件/动作点）                                                   | 收件人                | 优先级理由                           |
| --- | ----------------- | ----------------------------------------------------------------------- | --------------------- | ------------------------------------ |
| S1  | 密码被修改通知    | updatePassword / reset / claim / 双轨换密成功点                         | 当事人旧+新邮箱       | 账号安全标配：不是本人操作即刻知情   |
| S2  | 邮箱被换绑通知    | updateEmailAction 成功点                                                | 旧邮箱 + 新邮箱各一封 | 防盗号：旧邮箱被抢占时原主能察觉     |
| S3  | 账号被限制 / 解除 | createRestriction / liftRestriction（已有站内 account.restricted 类型） | 当事人                | 处罚送达义务；站内已有类型，镜像即可 |

（S1 与 S2 有轻微重叠——改密≠换绑，两封各有意义；reset/claim 已有对应邮件，不再叠加 S1，避免一动作两封。）

### 第二期：实时高价值类（偏好可关）

| #   | 场景         | 站内类型                                              | 频控                                                      |
| --- | ------------ | ----------------------------------------------------- | --------------------------------------------------------- |
| S4  | 收到私信     | pm.received                                           | 每会话每小时最多 1 封（聚合）；有未读且 30 分钟未上线才发 |
| S5  | 内容售出收益 | gate.sold                                             | 实时；同日同买家合并                                      |
| S6  | 审核结果     | content.approved / rejected（新增 rejected 站内类型） | 实时                                                      |

### 第三期：每日汇总 digest（召回主力，偏好可关）

| #   | 场景                     | 内容                                                        | 时机                                                                                     |
| --- | ------------------------ | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| S7  | 每日一封「你的社区动态」 | 未读私信数 + 新回复/提及/关注者摘要（各取前几条）+ 热帖 1–2 | 每天固定时刻（后台可配发送时刻，默认 20:00）；**24h 内有过登录则跳过**（不骚扰活跃用户） |
| S8  | 长期未登录召回           | N 天未登录 + 上次动态摘要                                   | 与 S7 共用管线；M13 召回动作可直接复用（老用户召回邮件=手动触发的 S8 变体）              |

### 明确不做（实时邮件）

点赞、关注、@提及（高频低价值——@提及并入 S7 摘要）、签到提醒、公告广播（important 公告已有站内横幅+铃铛，
邮件广播易触垃圾邮件机制；若未来需要走 S8 管线的手动批量）。

## 三、管线设计要点

1. **挂载点**：notify()（lib/notifications/notify.ts）站内写入后按 `notification_preferences(channel=email)`
   行决定是否投递；mandatory 类型（S1–S3）跳过偏好直接发。
2. **频控**：按用户+场景桶（rateLimit 既有设施）；S4 的 30 分钟未上线判定用 users.last_login_at（已有列）
   - sessions 最近活跃；S7/S8 由 cron 任务扫描（node-cron 或系统 crontab，M13 部署时定）。
3. **模板**：复用 mailer layout（站名/站点地址已注入）；每场景一个纯函数模板（单测向量）。
4. **退订**：List-Unsubscribe 头 + 邮件底部「通知偏好」深链（/settings/notifications）；
   /settings/notifications 增 email 列开关（第二/三期场景）。
5. **失败降级**：发送失败记录发送结果与服务器日志，不反噬已提交的主流程（defer/after 或隔离邮件副作用）；不静默吞错，也不据此承诺持久重试。
6. **配置**：后台站点配置「邮件」组增：digest 发送时刻、（可选）全局邮件通知总开关（管线上线后才有意义，
   随第三期一起加，避免死开关）。

## 五、圈阅结果与实施状态（2026-10-28）

站长裁决：三期都做；S4–S8 做每人个性化开关；S1–S3 由后台统一控制。**三期已全部实施**：

- 管线基建 `lib/notifications/email.ts`（安全开关/用户偏好/尽力而为发送/S4 双闸/活跃判定）；
- P1 三场景挂载（改密 S1、换绑 S2 双邮、限制事件 S3，后台「站点配置→邮件」有统一开关，默认开）；
- P2 三场景挂载（私信 S4 双闸频控、售出 S5、审核通过 S6）+ /settings/notifications 双渠道开关
  （站内默认开、邮件默认关，逐场景独立）；
- P3 digest（迁移 0011 `users.last_email_digest_at` + cron 脚本 `apps/web/scripts/digest-cron.mts`
  每小时运行比对后台配置时刻 [email.digest.hour，默认 20 点] + /settings/notifications 汇总开关行）；
- 测试：mailer 模板 12 项单测、email 渠道 int 4 项、digest 管线 int 4 项、

## 六、统一模板、发送记录与后台管理（2026-10-31 邮件专项 / 审查批次 0）

模板层从 `lib/auth/mailer.ts` 迁出为独立域 **`lib/mail/`**（auth 域不再持有私信/汇总等模板）：

| 文件           | 职责                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| `types.ts`     | MailKind 五类（verify/security/notice/digest/system）、MailBrand、MailMessage（HTML+纯文本双版本）        |
| `brand.ts`     | `getMailBrand()`：站名/标语/URL 取站点身份配置，主题色取全站默认主题包的 PWA themeColor；任何失败回退兜底 |
| `layout.ts`    | `renderMail()` 纯函数：统一视觉 + 四类页脚 + 纯文本版                                                     |
| `templates.ts` | 15 个模板纯函数（文案见下）                                                                               |
| `transport.ts` | `sendMail`（失败先记录再抛出）/ `trySendMail`（尽力而为）；email_log 记录与 90 天保留清理                 |
| `log-query.ts` | 后台发送记录查询（筛选/分页/24h 概览）                                                                    |
| `previews.ts`  | 全部模板的预览样例（后台预览页与守卫共用）                                                                |

**统一视觉**：品牌条（站名 + 标语，不用图片——邮件客户端默认拦截远程图）→ 白卡片（主题色顶边 / 标题 / 正文 / 字段表 / 引用块 / 列表 / 主按钮 + **按钮下方备用链接** / 提示框）→ 分类页脚。安全强制类顶边用琥珀色 `#b45309` 区分。

**四类页脚**：verify「不是你发起可忽略，账号不会变化」；security「不受通知偏好控制」（模板补充行动指引）；notice/digest 说明触发原因与频控，并自动追加「设置 → 通知」管理入口。

**文案约定**：第二人称「你」；按钮动词开头；不堆感叹号；主题「标题 · 站名」；正文支持 `**粗体**` 轻标记（先转义再加标签）。逐模板的文案基线锚定在 `lib/mail/templates.test.ts`（换文案须同步改测试）。

**发送可靠性（审查 F-05 等）**：注册验证邮件走 `after()` 不阻塞注册（失败可在「设置 → 邮箱」重发）；换绑/重发验证邮件失败跳 `verification=failed` 并在页面提示重试；全部静默 `.catch(() => {})` 改为经 transport 记录（email_log + 日志）。

**本轮复审补正**：换绑后的旧邮箱安全通知不再引导使用已解绑邮箱找回，而指向实际可用的安全路径。注销邮箱流程的签发与发送移至 `after()`，先返回中性响应，不再按是否存在 challenge 分别等待/不等待 SMTP。PM 站内通知提交后的邮件偏好读取/发送故障已隔离，避免附带邮件失败使该事件重放；但通知提交与 outbox dispatched 标记之间仍无持久消费回执，崩溃窗口重放仍可能增加聚合 count，不宣称 exactly-once 或持久重试。证据与后续幂等边界见 [深度复审 R-02](reviews/2026-10-31-deep-responsive-review.md)。

**发送记录（schema v2.8 / 迁移 0022）**：`email_log` 表——kind/scene/收件人/用户 id/主题/状态/错误/Message-ID/耗时；**不存正文**（验证链接含一次性令牌）；保留 90 天（发送侧 1% 概率小批量清理）。

**后台**：`/admin/mail`（admin.logs，与审计日志同档）——状态/类别/收件人或 uid 筛选 + 分页 + 24 小时成败概览；`/admin/mail/preview`——全部模板用样例数据渲染（iframe sandbox 零脚本）+ 纯文本对照，改样式不用真发信。

**固定规范（守卫 `lib/mail/mail-guard.test.ts`）**：① nodemailer 只许 `lib/mail/transport.ts` 引入；② 业务代码发信只许 `import "@/lib/mail"`；③ 新模板必须经 `renderMail` 渲染并在 `previews.ts` 登记样例。
