# M10.5 · S1 核心布局规格（✅ 站长已拍板）

> M10.5 五步流程：**S1 核心布局（本文）→ S2 页面线稿 → S3 色彩与主题 → S4 视觉语言与动效 → S5 全站落地**。
> 本文是 S1 的定稿记录：已实现的壳 + 后续步骤必须遵守的布局约束。
> 前置背景见 `docs/FRONTEND-DESIGN.md`（视觉方向/三层令牌/组件策略，仍然有效）。

## 1. 已锁定决策（2026-10-27）

| 决策点 | 结论 |
|---|---|
| 移动端前台导航（<768px） | **底部 Tab 栏**：首页 / 版块 / 发帖（中央凸起主按钮）/ 消息 / 我的；低频入口（积分、设置、管理、退出、主题切换）收进顶栏用户菜单与「我的」目标页；适配 iOS safe-area |
| 桌面端前台骨架（≥1024px） | **内容主列 + 右信息栏**：首页与版块页在 xl（≥1280）出现右栏（签到/最新主题/统计，也是模块槽位），lg 以下折叠；帖子阅读页全断点单列、限宽 68ch，无侧栏 |
| 管理后台布局 | **分组侧栏**：桌面 md+ 左侧粘性侧栏，按 总览/内容/用户/系统 四组；移动端收进汉堡抽屉；内容区高密度 |
| 首页信息架构 | **内容流优先（现代式）**：弱化「版块目录即首页」的旧论坛范式，首页直接堆最新主题内容流，版块作为卡片的隐含元数据（版块徽标可点）+ 流顶筛选 chips；版块目录退到 `/boards`（底部 Tab「版块」）。*落地在 S2 首页线稿评审后实施，当前首页为过渡态* |

## 2. 断点与容器规范

断点沿用 Tailwind 默认：`sm 640 / md 768 / lg 1024 / xl 1280`。分界语义：

- **<768px（移动）**：底部 Tab 生效；顶栏精简（品牌/搜索/铃铛/头像）；单列内容。
- **≥768px（平板/桌面）**：底部 Tab 隐藏；顶栏出现主导航与主题切换。
- **≥1024px（桌面）**：后台侧栏出现；前台可双列。
- **≥1280px（宽桌）**：前台右栏出现。

容器宽度（S2 起逐页对齐，不再 max-w-3xl/4xl/5xl 混用）：

| 场景 | 容器 |
|---|---|
| 顶栏 / 页脚 / 后台 | `max-w-6xl` 居中 |
| 信息流页（首页、版块、关注动态） | `max-w-6xl`：主列自适应 + 右栏 `w-72`（xl 起） |
| 阅读页（主题/帖子） | 单列 `max-w-3xl`（≈68ch 正文行长） |
| 表单/对话页（发帖、编辑、私信、auth 组） | `max-w-3xl` |
| 目录/列表页（版块目录、搜索结果、通知） | `max-w-5xl` |

## 3. 前台壳（已实现）

```
AnnouncementBanner（不粘性，滚走）
SiteHeader（sticky top-0 z-40 + bg-background/80 backdrop-blur）
  ├ 品牌：Wind 图标方块 + 「青翼字幕组」（<sm 只显示图标）
  ├ MainNav（md+）：首页 / 版块 / 动态 / [site_settings 可配导航]；当前页高亮（aria-current，路径段匹配）
  └ 工具区：搜索图标（全端）｜NotificationBell｜ThemeMenu（sm+）｜UserMenu
      UserMenu（客户端岛）：个人主页/积分/关注动态/私信/头像设置/[管理后台(按权限)]/主题行/退出
{children}（各页面自带 <main>，容器宽度按 §2）
底部 Tab 占位（h-16 md:hidden，防固定栏遮挡）
Footer（site_settings 友链/页脚文字）
BottomTabBar（fixed md:hidden；usePathname 当前态；未读角标=unreadPmTotal 服务端初值）
```

要点：

- **发帖 Tab → `/submit`**（S1 新增）：按权限列出可发帖版块（复用 `loadComposeAccess` 口径），选中进 `/f/[fid]/new`；`/f/\d+/new` 也算发帖态高亮。游客 Tab 降级为 首页/版块/搜索/登录。
- **「我的」Tab 过渡目标 = 本人 `/u/[uid]`**；S2 线稿时评审是否需要独立的「我的」聚合页（设置/积分/关注/管理的入口中枢）。
- **消息 Tab 角标**：服务端渲染时的 `unreadPmTotal` 初值（与 conversationList 未读口径一致），跨页导航不实时刷新——实时化（轮询或随铃铛接口合并）留 S5 增强。
- **模块装卸语义保持**：notifications/pm 停用时不渲染铃铛/消息 Tab。
- 管理后台入口此前全站缺失，现在按「site.admin 或任一版主」出现在用户菜单（与 `/admin` 布局门禁同口径）。

## 4. 后台壳（已实现）

- `admin/layout.tsx` 只做门禁与按权限过滤菜单；布局渲染在 `components/admin/admin-shell.tsx`（客户端，负责当前态/抽屉）。
- 桌面：`max-w-6xl` 容器内左侧 `w-48` 粘性侧栏（top-20，让出全局顶栏），四组：总览（看板）/ 内容（审核/举报/投票/私信）/ 用户（用户/授权）/ 系统（公告/积分/徽章/日志）。
- 移动：「后台菜单」按钮 → 左滑 Sheet（`ui/sheet.tsx`，Radix Dialog 侧滑形态，tw-animate-css 动效）。
- 门禁行为不变：游客 redirect `/login`，无权 `notFound()`；每页仍须自身 `requireAdmin` 二次拦截。
- 密度：S1 未动（内容区仍是各页现有样式）；密度 token（紧凑/舒适）按 FRONTEND-DESIGN §2 在 S3 落地。

## 5. 主题地基修复（S1 顺带）

- `globals.css` 补 `@custom-variant dark (&:is([data-theme="dark"] *))`——修复 ui 组件内 12 处 `dark:` 工具类与 `data-theme` 双轨脱节（此前手动切暗色不生效）。
- ThemeSwitcher 有了正式入口：顶栏 ThemeMenu（sm+）+ 用户菜单主题行（移动端）；`/design` 演示页保留。
- `viewport` 导出 `viewportFit: "cover"` + 底部 Tab `pb-[env(safe-area-inset-bottom)]` 适配全面屏。

## 6. S2 线稿定稿记录（2026-10-27 站长拍板）

- ⟦D1⟧ 首页内容流 = **列表流**（瀑布流存档对照，不适合站点内容倾向）
- ⟦D2⟧ 首页「加载更多」追加 + 版块页数字分页
- ⟦D3⟧ 楼层 = 作者行在顶，正文全宽 68ch，移动/桌面同构
- ⟦D4⟧ **新建「我的」聚合页**（内容为主的中枢：我的主题/回复、关注动态、积分、私信、设置与管理入口；底部 Tab 直达）——`/u/[uid]` 保留为「个人公开页」语义。S1 底部 Tab 的过渡指向（本人 /u/[uid]）在聚合页落地后切换。
- ⟦D5⟧ 迁移存量裸 HTML 清洗：不原样迁移，图片链接视效果取舍（附件化/移除）、font/颜色丢弃、锚点转纯文本，清洗实施时逐类看效果决定。
- **私信发起模型（B2 定稿修订）**：无通讯录概念下不设独立「发起私信」入口，私信一律从内容与关系上下文发起（作者行菜单 / 桌面悬浮名片 / 个人公开页按钮），`/messages?to=uid` 为统一落点。
- **私信权限（站长功能补全）**：用户可设接受范围 = 所有人（默认）/ 仅我关注的人 / 关闭私信；策略随用户资料存储，判定在 pm 服务端，UI（公开页按钮三态、我的页偏好行）只做前置提示；默认值保持现网行为不变。

## 7. S4 动效需求输入（站长 2026-10-27，M10.5 全程有效）

> 总原则：**所有交互（点击/滑动/切换）都有动效**，整体气质「活跃、流畅、现代」；动效服务于空间记忆与层级表达，不得阻塞操作（全部响应 `prefers-reduced-motion` 降级）。

| 模式 | 站长原语 | S4 需定义 | 技术候选（S4 验证后定） |
|---|---|---|---|
| 页面级方向性过渡 | 「左切进入、右切返回」 | 前进=新页自右推入，返回=自右滑出（iOS push/pop 语汇）；移动端联动边缘右滑手势返回；桌面用轻量淡入+微位移（克制） | View Transitions API（same-document，方向可判）；Next `template.tsx` 仅能做进场，退场需 VT API 或接受不对称 |
| 触点扩散打开 | 「从标题中心扩散打开」 | 卡片→详情的 container transform / circular reveal，变换原点=点击坐标（需在 pointer 事件记录 origin 传入过渡） | View Transitions API `::view-transition-new` + clip-path 圆形扩展；降级=缩放淡入 |
| 内容块进场 | 「加速度切入 + 滑动过一点弹回来」 | spring 曲线（过冲回弹），列表首屏 stagger 错落（40–60ms 步进） | 纯 CSS：`cubic-bezier(0.34, 1.56, 0.64, 1)` 系 ease-out-back + `@starting-style`/animation-delay 错落；复杂联动再评估 motion 库 |
| 微交互 | 「所有的交互都有动效」 | 按压态（scale 0.97）、hover 抬升、开关/勾选弹跳、Tab 滑动指示器、点赞飞出等原子动效；统一时长/曲线令牌（fast 150ms / base 250ms / spring 450ms） | CSS 变量令牌 + tw-animate-css；组件基类统一挂 |

落地纪律：动效令牌进 primitives 层（--fw-ease-spring 等），业务只许用令牌；S4 交付=动效规范文档 + 一个可玩的动效演示页（挂在 /design 下）。

## 8. 对后续步骤的约束

- **S2 线稿**必须按 §2 容器表画；每个页面线稿须包含四态（加载骨架/空状态/错误/权限门控）。
- **S3/S4** 分别按 §7 的令牌纪律与动效需求执行，不得另行发明体系。
- **S3 色彩**落令牌层（primitives/semantic/themes），壳组件只允许语义类（bg-background 等），不得引入原子色。
- **S4 动效**基线已埋：壳的 transition-colors、Sheet slide 动效、右栏/列表进场待规范；技术选型倾向纯 CSS + tw-animate-css + Next View Transitions（S4 再定稿）。
- 改壳不得破坏的既有测试锚点：`auth.spec`（用户菜单按钮可达名含用户名、退出在菜单内）、`content.spec`（首页 h1=青翼字幕组 + 「最新动态」）、`mobile-posting.spec`（375px 无横向滚动、控件不越界）。
