## 2. 动效令牌（已落 primitives.css 尾部；Tailwind 工具类映射见 globals @theme inline）

| 令牌             | 值                             | 用途                                     |
| ---------------- | ------------------------------ | ---------------------------------------- |
| --fw-dur-fast    | 150ms                          | L1 微交互（按压/开关/色变）              |
| --fw-dur-base    | 250ms                          | L2 常规淡入位移、弹层                    |
| --fw-dur-slow    | 400ms                          | L2 页面级方向性过渡                      |
| --fw-dur-spring  | 500ms                          | L3 过冲回弹、扩散打开                    |
| --fw-ease-out    | cubic-bezier(0.22,1,0.36,1)    | 进场：加速度切入缓停                     |
| --fw-ease-inout  | cubic-bezier(0.65,0,0.35,1)    | 对称位移                                 |
| --fw-ease-spring | cubic-bezier(0.34,1.56,0.64,1) | 刹车过冲回弹（站长「滑动过一点弹回来」） |
| --fw-ease-exit   | cubic-bezier(0.4,0,1,1)        | 退场加速离场                             |

工具类：`ease-out-soft / ease-spring / ease-exit / ease-inout`；列表首屏错落已由 `<MotionList>` 声明式挂类（`list.enter` 预设类 + 令牌步长延迟），替代原 8 处 `.fw-enter` + 内联 `animationDelay`；位移、进度条、float-up 与 stagger 步长等魔法数已升格 `primitives.css` 令牌（含桌面断点覆写，M15 Step 3 落地）；清单见 motion-spec §1.2。
**纪律**：页面/组件不得裸写 `cubic-bezier|ms`——一律引令牌；只动 `transform/opacity/clip-path`；`will-change` 仅限进行中的过渡。裸写守卫 `motion-bare-write-guard.test.ts` 已上线：业务 TS/TSX 与非令牌 CSS 的裸写时长/曲线会被拦截（纯令牌引用豁免）；预设关键帧内部小位移属 sanctioned 预设区，不在禁令范围。新增页面首屏错落用 `MotionList`，不再裸写 `animationDelay`。

## 3. 四级动效体系

### 3.1 L1 微交互（fast 150ms）

按压 scale 0.97（Button 基类已生效）；hover 抬升（可点卡片行）；开关/勾选弹跳（spring）；Tab 指示器滑动；
点赞飞出/数字滚动（M10.7 已落地；M15 Step 3 已把 pop/float-up 预设定义收编入引擎 `MOTION_ELEMENT_PRESETS`，点赞/关注组件继续消费 fw-* 预设类，行为零变化）。原则：**反馈即时、位移 ≤2px、不抢内容**。

### 3.2 L2 页面级方向性过渡（slow 400ms）

- **视觉语义不变**：前进 = push，新页自右切入（透明度 0.6→1）；返回 = pop，自左切入——站长「左切进入、右切返回」。`--fw-page-shift`（M15 Step 3 升格为 primitives.css 令牌）仍为移动 28px、桌面 14px（减半克制）；新旧快照分别进退场，顶栏/底部 Tab 等布局内容保持静止，页面内容从下面滑过。
- **当前接线（M15 Step 4 全站收敛，本地灰度）**：根 `template.tsx` 只走 `SiteMotionBoundary → MotionPage`，由 `MotionPage` 承担唯一根 React `<ViewTransition>` 和全宽 `[data-fw-page]` 盒子，不再外套或在普通业务页重复嵌套 VT。provider/引擎实例留在稳定 layout，RSC 页面仍为 children 插槽。`isMotionPilot` 灰度门已移除，所有路由（除同 pathname 查询串变化）都建引擎会话。
- **全站边界与共享 layout 下沉**：非共享路由根边界 pathname-key（组内/跨页都进退场）；共享路由（admin/settings）根边界 key/pageKey=`root-shared`、enter=`none`（跨组进入不双进场）、exit 默认（跨组退出旧页正常淡出），动画交壳内下沉的 `PageMotionBoundary`（pathname-key MotionPage，`admin-shell` 与 `settings/layout` 包 children）——组内 fade 微动、侧栏/头部静止不重挂，每会话恰一个边界认领；query/hash 不入 key。admin 注册表 preset 改 `"admin"`（resolver 层默认 fade，显式 direction hint 仍可覆盖，保持克制）。全站 pathname-key 收敛给原本无动画的组内导航新增 fade（收敛目标，非删减）。
- **方向桥（注册表单一事实源，Step 4 退役完成）**：意图阶段由宿主业务注册表（`motion-routes.ts`）提供层级、Tab 顺序和目标预设，引擎定稿后经 `nav-direction.ts` 写 `<html data-motion-direction>`（CSS `:root[data-motion-direction]` 选动画，同名 keyframes 不动），`MotionLink` / `useMotionRouter` 仍透传主动 Link/push/replace 的 `transitionTypes` 作原生类型层，`useMotionLifecycle` 提供页面生命周期挂点。旧 `nav-kind.ts`（rank/TAB_ORDER/kindBetween）与 `<html data-nav>` CSS 已退役删除，新增页面只需登记注册表（自动纳入方向矩阵），不再维护两套，不在目标页晚 effect 中重写已定稿的整次导航。
- **历史与流式边界**：浏览器返回键/手势与 forward 按 history 诚实跳过，不伪装 push。持久页面边界显式 `update="none" default="none"`，避免同 key 内容就绪重复整页动画/导航会话；不承诺独立子 VT 或空原生 start 恒不存在。宿主请求 epoch 与内核动效 id 分别隔离 URL/进度和 ready/finish/cleanup，详细契约见 motion-spec §6.2。
- **历史路径**：M10.7 已用 React VT 取代「手动 `withViewTransition` 包导航 + template 内联进场」。M15 Step 2 在该路线内做单根宿主灰度，并非另加第二套页面 VT；`html[data-vt="push"/"pop"]` 演示选型不能当作当前页面接入 API，其规则与关键帧已在 Step 3 作为死代码删除（状态级选型收敛 fade/expand）。

### 3.3 L3 触点扩散打开 / 返回收起（M10.7 Step 4c 落地，500ms / 400ms）

内容卡片（`data-vt-expand`：FeedCard / ThreadRow）点进**主题页**：新页以点击点为圆心圆形展开（`clip-path: circle`），旧页静止垫底；
随后用站内链接回到打开它的列表页，详情页以同一圆心缩回（旧页盖在上层）。技术要点（站长实机反馈「遮罩没生效」后沉淀）：

- 半径 = 触点到视口最远角的距离（`--vt-r`），**不能用百分比**（相对快照盒子，长页会使圆瞬间盖满）；缓动用对称的 `--fw-ease-inout`，
  前快后慢的 expo 曲线会让圆在 ~100ms 内走完、肉眼只剩淡入；
- 圆心相对被命名元素的盒子：当前由 **`MotionPage`** 提供唯一全宽 `[data-fw-page]` 包装，保证左边为 0、顶部 = 顶栏高度；不是在 template 外再加一个包装/VT；
- 包装自带不透明背景（`--page-bg`，快照不含 body 背景）；进退场用不同类名，收起时只抬高退场组的 z-index；
- 触点与几何由 `nav-geometry.ts` 在点击拦截时定稿（expand/collapse，至多调用一次；base 方向接注册表 `siteMotionDirection`），引擎在导航 transition 之外经 `nav-direction.ts` 写方向属性与圆心；来源卡片在第一屏之外时，按 M10.7 后续修复缩向视口底部中心，不再沿用早期「必退化为普通 pop」的描述。reduce / 不支持 VT → 内容直接切换。
  状态级演示仍见 `/design/motion`；M15 页面导航的 pilot E2E 改由测试专用 `motion-test-harness` 承载（仅 E2E 置 `window.__fwMotionTest` 激活，生产渲染 null），原 `/motion-lab` 与实验面板已在 Step 4 删除。

### 3.4 L4 进场编排（base 250ms × stagger 50ms）

列表**首屏**错落切入（M15 Step 3 已落地：`<MotionList>` 的 `list.enter` 预设挂 `.fw-enter` + `calc(var(--fw-stagger-step) × 序号)`，步长 50ms、封顶 10 项，`animate=false` 原样渲染）；翻页/触底追加的新项**无延迟淡入**（`list.append`：`.fw-fade-in`，不错落、不位移；M10.7 站长裁定，覆盖原「不重播」）；
弹层内容组 stagger 可选。原则：编排只服务首印象，不做持续动画。

## 4. 无障碍与降级（硬性）

- `prefers-reduced-motion: reduce`：`.fw-enter` 与页面 VT 动画归零，页面生命周期按 reduced-motion 通知跳过，内容仍正常提交；加载期间偏好变化在参与者就绪时再次核对。状态级助手（引擎 `playStateTransition`；旧 `withViewTransition` facade 已于 Step 4 删除）在 reduce 下直接执行更新；L1 即时状态反馈保留，但 pop/roll/switch 动画与 float-up 按现行 CSS 禁用，不因「保留反馈」重新开启运动效果。
- 兼容性以 API、类型和过渡类的实际能力检测为准，不再将支持面写成「仅 Chromium/Safari」。具体浏览器版本与未实测边界见 M15 §10；不支持时不因动效阻塞业务更新，状态级助手直接调用 update。
- 弹层/抽屉（Radix + tw-animate-css）继续沿用已对齐令牌的动效，不换库；M15 不重写该体系。reduce 的三处既有策略已在 Step 3 收编为引擎对齐的单一策略：CSS reduce 仍是稳健机制（无 JS 也生效），引擎拥有预设定义，守卫钉住元素预设覆盖；页面导航 reduce 由引擎驱动（Step 2），本步未把 CSS reduce 迁成 JS。

## 5. 技术路线（原决策保留，M15 Step 2/3/4 更新接线）

1. **不引第三方 motion 库**：CSS 令牌 + tw-animate-css + 框架公开 React VT 延续零依赖路线。状态级驱动已在 M15 Step 3 收编入引擎 `engine/native.ts`（`playStateTransition`）；`src/lib/motion/view-transition.ts` 薄兼容 facade 及其单测已于 Step 4 随旧链删除（等价覆盖在 `native.test`），状态级过渡一律走引擎，不再另包路由导航。
2. **不再等待 Next experimental 配置**：项目声明 React/React DOM 19.3.1、Next 16.4.2，公开 `<ViewTransition>` 已可用且无需 experimental 开关。但 Next 浏览器别名实际使用 bundled React `19.3.0-canary-278794d7-20261002`，不能据 package.json 宣称运行时纯 stable；能力以框架内置实现与生产构建实测为准。
3. **当前分工（Step 4 全站收敛，本地灰度）**：根 `MotionPage` 管快照/页面作用域（非共享路由 pathname-key，共享路由 root-shared + 壳内 `PageMotionBoundary` 下沉）；宿主注册表（`motion-routes.ts`）是方向单一事实源，在意图阶段给出层级、Tab 顺序与目标预设，引擎经 `nav-direction.ts` 写 `html[data-motion-direction]`；站点 Link/router 适配器负责 Next 的主动类型透传；业务只在客户端岛接生命周期 hook，不迁 RSC 取数。元素层由 `MotionList` 与引擎元素预设（`MOTION_ELEMENT_PRESETS`）声明式挂类，微交互组件继续消费 fw-* 类、行为零变化。旧 rank / `data-nav` CSS 与 view-transition facade 已退役删除，expand/collapse 几何迁 `nav-geometry.ts`，口径以 motion-spec §5/§6.2 为准。
4. **实验结论不扩大**：Step 0 的旧“跨段”用例实际仍在同一 `/motion-lab` 第一段，不能作为真实跨根证明；一次原生 start 也不等于只有一个快照组。晚 effect 覆写只证明新层 CSS 可变化，不保证首帧、旧 fiber 退场属性或快照几何可延迟。当前真实跨根/共享段的参与者断言与勘误以 M15 §12 为准。
5. **历史落地映射与当前待办分开**：M10.5 S5 的 hover、圆角、弹层令牌及空态/错误态图例属于原视觉计划；M10.7 已落地页面方向、触点扩散和列表进场，并删除了会推迟真内容的 `/boards`、`/search` 流式骨架，不恢复原“骨架复用布局”待办。M15 Step 3 已收编元素/`MotionList`/8 处 stagger/手动助手与魔法数；Step 4 已完成全站接管、旧链（rank/data-nav/view-transition facade）退役与 motion-lab/实验面板删除（本地灰度），pilot E2E 改由测试专用 `motion-test-harness` 承载。剩余待办为 Step 4.5 独立审查与 Step 5 PR/CI/部署（均已完成，M15 已收口上线公测）。

## 6. 验收口径（设计目标，不等同 M15 收口）

- `/design/motion` 保留四级视觉与 reduce 演示（Step 3 起 StaggerDemo 用 `MotionList`、DirectionalDemo 用 `MOTION_DIRECTIONS` 方向预设、ExpandDemo 用 `playStateTransition` 显式圆心）；M15 页面导航的 pilot E2E 由测试专用 `motion-test-harness` 验证真实 Link/router（仅 E2E 置 `window.__fwMotionTest` 激活，生产渲染 null）。原 `/motion-lab` 与实验面板已在 Step 4 删除，不再是「仅本地可达」的实验资产；
- 全站无裸写时长/曲线是验收目标：魔法数清单已清账、裸写守卫已上线（motion-spec §1.2/§7），业务 TS/TSX 与非令牌 CSS 的裸写时长/曲线被拦截；预设关键帧内部小位移属 sanctioned 预设区，不在禁令范围；
- 动效不引入新依赖、不阻塞交互（点击响应 ≤100ms 内有视觉反馈）；静态视觉基线不得因引擎接入而更新；
- M15 已收口（2026-11-12 部署公测，PR #13 CI 双绿合并 main；独立审查无 P0 见 [reviews](reviews/2026-11-11-m15-code-review.md)）。Firefox 仍未本机实测（站长暂缓，VT 能力按 API/类型实际检测降级，红线「不支持环境同步可用」已由引擎保障）。各步门禁与生产部署核对见 M15 §12–§16。
