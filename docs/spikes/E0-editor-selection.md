# E0 · 编辑器选型记录（M6）

> 日期：2026-10-24 ｜ 结论：**Tiptap v3（所见即所得）+ CodeMirror 6（源码模式）+ react-image-crop（裁剪）**
> 做法：在仓库外搭三套原型放进同一个测试页，用真实迁移帖做往返保真测试，用站长的手机做输入法与门控编辑的真机验证。
> 原型源码存档在 [`e0-editor/`](e0-editor/)（不含语料：语料含真实帖子内容，用 `export-corpus.mts` 从迁移库重新导出）。

## 1. 要回答的问题

[GATES.md](../GATES.md) §9 的评审维度：能否把 `:::gate` 渲染成可视块（价格输入、锁图标）、Markdown 往返是否无损、移动端体验。
站长另定两条：**所见即所得为默认，可一键切到 Markdown 源码**；**上传图片要有裁剪工具**。

## 2. 候选与测试方法

| 候选 | 版本 | 角色 |
|---|---|---|
| Milkdown Crepe | 7.22.3 | 所见即所得（remark / ProseMirror，自带工具栏与斜杠菜单） |
| Tiptap + `@tiptap/markdown` | 3.32.0 | 所见即所得（ProseMirror，无头；官方 Markdown 基于 marked） |
| CodeMirror 6 | 6.0.2 | 源码模式 / 基线 |
| react-easy-crop / react-image-crop | 6.2.4 / 11.1.2 | 裁剪 |

**语料 244 条**：15 条手工结构用例（标题 / 嵌套列表 / 引用 / 代码围栏 / 表格 / 删除线与波浪线 / 内嵌 HTML / 转义 / 5 种门控形态）、
19 篇表格帖、130 篇随机帖、20 篇含删除线、20 篇含引用、40 篇带门控的帖（用 `assembleSource` 还原成编辑旧帖时编辑器真正拿到的**完整源码**）。邮箱与手机号已脱敏。

**判定**：「载入 → 不改 → 取回」后用站点真实渲染器（`renderMarkdown` + `splitSource`）比较——公开部分渲染相同，且每个门控的条件 / key / match / 隐藏正文渲染相同，即为**渲染等价**；
另统计**逐字相同**（编辑器有没有静默改写源码）。CodeMirror 作基线，用来证明批量框架与判定本身没问题。

## 3. 结果

### 3.1 往返保真（渲染等价，共 244 条）

| 编辑器 | 默认配置 | 针对性修正后 | 报错 |
|---|---|---|---|
| CodeMirror 6（基线） | 244 | 244（逐字 244） | 0 |
| Milkdown Crepe | 162 | **229（93.9%）** | 65 → 0 |
| Tiptap v3 | 211 | **234（95.9%）** | 0 |

分类（修正后，渲染等价 / 条数）：

| 类别 | Milkdown | Tiptap |
|---|---|---|
| 结构用例 | 15/15 | 14/15 |
| 表格帖 | 8/19 | 16/19 |
| 随机帖 | 130/130 | 129/130 |
| 删除线帖 | 20/20 | 20/20 |
| 引用帖 | 20/20 | 20/20 |
| 带门控的完整源码 | 36/40 | 35/40 |

剩余的不等价主要是：聊天记录式的怪表格、转义反斜杠、`_(:з」∠)_` 的强调解析差异、内嵌 HTML 被剥掉。
按计划，**往返不等价的旧帖在所见即所得里强制进源码模式**，因此不是阻塞项。

### 3.2 默认配置下暴露的问题（以及是否可修）

| 问题 | 影响面（迁移库实测） | 两个编辑器 | 修法（spike 里已验证） |
|---|---|---|---|
| **单个 `~` 被改写成 `~~`** | **1136 篇**含单波浪线语气词，如「握爪~我也是今年5月份~好在图书馆」 | 都有 | Tiptap：覆盖 marked 的 `del` 分词器，只放行 `~~`；Milkdown：`singleTilde:false` |
| 文本 / 叶子指令抛错 | **336 篇**含「冒号+字母」（`:D`、`(:з」∠)`） | Milkdown：`remark-directive` 把它们当指令，不认识就抛 `Cannot match target parser` | remark 插件把非 gate 指令还原成原文 |
| 一次异常使编辑器状态损坏并级联 | — | Milkdown（首轮的 65 个报错大多是级联） | 批量框架在报错后重建编辑器；生产里同理，载入失败要降级到源码模式 |
| 图片 alt 被改成 `1.00` | — | Milkdown 的 ImageBlock 特性把 alt 当比例存 | 关闭 ImageBlock 特性 |
| 门控内段落与列表被拼成一行 | — | Tiptap（自写序列化） | `renderChildren(content, "\n\n")` |
| 内嵌 HTML（`<sup>/<u>` 等）被剥掉 | 仅 51 / 31468 篇（0.16%） | 都有 | 这些帖强制源码模式，可忽略 |
| Crepe 默认主题内边距是桌面宽屏设计，手机上正文只剩窄窄一列 | 截图可见 | Milkdown | 必须自己重做主题 |

### 3.3 体积（gzip，各自独立部分，排除共享的 React 与渲染器；均为动态加载，不影响阅读页）

| 编辑器 | JS | CSS |
|---|---|---|
| Tiptap v3 | 156 kB | — |
| CodeMirror 6 | 208 kB | — |
| Milkdown Crepe | 458 kB | 15 kB |

### 3.4 输入法与移动端

- **桌面自动化**（Chromium CDP 模拟拼音组合 `z→zi→zim→zimu` 后上屏「字幕」）：两个所见即所得编辑器在 6 个位置（段落末 / 段落中 / 门控块内 / 表格单元格 / 引用 / 列表项）**全部通过**。这只是理想化模拟，不能代替真机。
- **真机（站长，2026-10-24）**：整体打字没有明显问题；门控块的编辑（下拉切换类型、改价格、在块内打字）很顺畅。
- **裁剪**：站长偏好 **react-image-crop**。

### 3.5 门控可视块

两者都用约 60 行实现了带「付费 / 回复可见」下拉与价格输入的节点视图，序列化回 `:::gate{key="…" unlock="…" price="…"}`。
Milkdown 借 `remark-directive` 天然支持容器指令；Tiptap 要自写 marked 分词器（正则匹配同长度围栏 `:::{3,}gate{…}` … 同长度闭合），
语法的**权威仍是服务端 `splitSource`**，客户端分词器只是编辑体验。

## 4. 决定

**Tiptap v3 + CodeMirror 6 + react-image-crop。**

| 理由 | 说明 |
|---|---|
| 真机体验 | 站长实测打字与门控编辑顺畅，个人倾向 Tiptap + CodeMirror |
| 体积 | 156 kB，是 Milkdown 的三分之一；源码模式的 CodeMirror 仅在切换时才加载 |
| 保真 | 往返等价率两者里最高（95.9%）；表格帖明显好于 Milkdown（16/19 对 8/19） |
| 界面可控 | Tiptap 无头，工具栏 / 菜单直接用我们的设计令牌与 shadcn；Crepe 的整套主题要重做 |
| 风险已知 | 下面第 5 节列出了选择它要付出的代价与对策 |

未选 Milkdown 的主要原因是体积（3 倍）与主题重做成本；它的优势（解析语义与站点渲染器同属 remark 生态）由第 5 节第 1 条的对策补偿。

## 5. 选型带来的设计约束（写入 M6.3 / M6.4）

1. **Tiptap 用 marked 解析，语义与站点渲染器（remark / micromark）不完全一致**（实测 `生态学_(:з」∠)_` 被当斜体）。对策：
   - **预览走服务端 Server Action**，用站点真实渲染器渲染，作者看到的是发布后的真实样子；
   - 编辑面板在界面上标明是「近似预览」；
   - M6.3 加一条测试：作者在编辑器里能产出的典型文档，序列化后经站点渲染，结构要与编辑器显示一致；
   - 旧帖往返不等价 → 强制进源码模式；**未编辑不重新序列化**（保存时若内容没改，原样保留源码）。
2. **裁剪**：`react-image-crop` 没有旋转与缩放手势，**首版不做旋转**。浏览器按 EXIF 方向显示图片，服务端 **先自动旋转（auto-orient）再 `extract`**，裁剪坐标就是用户在屏幕上看到的那张图的像素坐标。
   请求只带 `{x, y, width, height}`（原图自然像素坐标，由 `displayed → natural` 的比例换算），服务端严格校验后用 sharp 裁剪。以后要旋转再加。
3. **marked 的 `del` 分词器必须覆盖**（只放行 `~~`），否则 1136 篇语气词会被改成删除线；门控内容序列化要用 `"\n\n"` 作块分隔。
4. **自写的 `:::gate` 分词器只服务编辑体验**；保存一律以服务端 `splitSource` 的结果为准，客户端用 `validateGates` 做实时提示。含内嵌指令的门控（外层围栏 ≥ 4 个冒号）的编辑体验在 spike 里有一条边角问题，M6.3 要补用例。
5. 内嵌 HTML 极少（0.16%），不做节点支持；这类帖进源码模式。
