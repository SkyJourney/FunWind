# 门控（Gate）规范

> 状态：M5.5 设计定稿；实现分布于 M5.5（存储/只读渲染/解锁服务）→ M6（创作与购买交互）。
> 对应旧站：`[sell]`（付费）、`[post]`（回复可见）、`[hide=N]`（积分可见）三种 UBB 隐藏块。
> 设计要点：**门控 = 内容容器 + 解锁条件（内置 `points` / `reply`）**；隐藏内容在保存时拆出，从构造上杜绝泄露。

## 1. 语法：`:::` 容器指令

采用 remark-directive 的通用指令提案（`:::name{attrs}` … `:::`），**不使用 ``` 代码围栏**：
门控内是 Markdown，需容纳代码块、列表、图片，代码围栏会把内容当字面量。

```md
:::gate{unlock="points" price="50"}
付费可见的 **Markdown** 内容，可含代码块、图片。
:::

:::gate{unlock="reply"}
回复后可见
:::
```

- `unlock`：解锁条件类型（见 §3）；其余属性为该条件的参数，由条件注册项的 schema 校验。
- `key`：门控在帖内的稳定身份（短字符串，如 `a1`）。**作者新写的门控不带 key**，保存时由服务端分配；编辑已有门控时 key 原样保留。
- 价格 `price` 为非负整数；`0` 表示「登录后免费解锁」（旧站 `[sell=0,]` 语义，占旧购买记录的 91%）。
- **只允许顶层块**：不得嵌套，不得出现在列表/引用/表格内。编辑器同步强制，保存时再校验。
- 一个 post 可含多个门控；`seq` 按出现顺序编号。

## 2. 存储契约（核心安全决策）

保存时由 `packages/content` 把门控**拆出**：

| 位置 | 内容 |
|------|------|
| `posts.body_md` | 仅公开部分；门控处只留空占位 `:::gate{key="a1"}\n:::` |
| `post_gates` | `id`（自增）, `post_id`, **`gate_key`**（帖内唯一，`(post_id, gate_key)` 唯一）, `conditions`(JSON 数组), `match_mode`(`all`\|`any`, 默认 `all`), `hidden_md`, `unlock_count`, `created_at`, `updated_at` |
| `gate_unlocks` | `(gate_id, user_id)` 主键, `price_paid`, `author_income`, `ledger_id`, `unlocked_at` |
| `posts.has_gate` | 布尔位，无门控的帖子跳过全部门控查询 |

**效果**：搜索、RSS、OG 摘要、通知预览、导出等任何只读 `body_md` 的路径都读不到隐藏内容。
隐藏正文只通过 `getGateContent(gateId, viewer)` 一个出口读取，该出口内置全部可见性判定。

`conditions` 示例：`[{"type":"points","price":50}]`；组合条件（如回复且关注）为多元素数组 + `match`，现阶段只用单条件。

**作者编辑**：作者/版主打开编辑时，`assembleSource(body_md, gates)` 把门控按 id 合并回完整源码；保存时 `splitSource()` 再拆。
门控 `key` 在往返中保持稳定，解锁记录因此不丢。有购买记录的门控**不可删除**，只能改内容；改价不退款，只影响之后的购买。

**写入器（M6.1，`lib/gates/write.ts`）**：保存时把拆出的门控草稿与库里该帖已有的门控按 `gate_key` 对账（新增 / 更新 / 删除），事务内先对该帖门控行加排他锁（与 `unlockGate` 同一把锁，所以"删除门控"与"购买"互斥，不会出现门控没了、钱却扣了），校验后一次落库：
- **权限**：新增门控、或改了条件的门控，需作者持有对应创建权限（`points` → `gate.points`，`reply` → `gate.reply`）；**没改条件的既有门控不要求**，权限被收回后作者仍能编辑帖子里的其他内容。
- **已有解锁记录的门控**：不可删除；条件只允许改价格（仍是单个 `points` 条件、匹配模式不变），不可换解锁方式；隐藏正文可改。
- **名下还挂着附件**（`attachments.gate_id`）的门控不可删除，须先重新指派附件，不得让附件悄悄变公开（M6.4 提供交互）。
- 只写不读：隐藏正文只有 `service.ts` 能读；`write.ts` 在 `hidden-md-guard` 白名单里，但查询一律显式列字段、结果与错误信息不含隐藏文本（守卫测试断言）。`updated_at` 仅在条件或隐藏正文真的变了时推进（隐藏正文按 `BINARY` 比较，只改大小写也算变化）（原生 SQL，见该文件注释：MySQL 的 UPDATE 从左到右求值，drizzle 会重排 SET 顺序）。

## 3. 解锁条件（内置 `points` / `reply`，固定两种）

> **M6.1 修订（站长 2026-10-24 定）**：原设计把条件做成模块内核的第八类注册边界（`gateConditions`：`paramsSchema` / `kind` / `check` / `prompt` / `createPermission`）。
> 实现里求值器一直是写死的 `switch`，只认 `points` / `reply`，注册边界没有任何消费者，只是名义上的"可插拔"，已**删除**（类型、注册校验、保留项、测试都已移除；模块内核由十类边界变为九类）。
> 将来真要新增一种条件，应当是一次**有设计、有测试的核心改动**（改 `packages/content` 的条件规格、`lib/gates/evaluate.ts` 与创作侧校验），而不是模块随手声明。

| 条件 | 判定 | 创建所需权限点 |
|------|------|----------------|
| `points` | 存在 `gate_unlocks` 记录；价格 0 也写记录（登录后点击解锁）；购买走 `unlockGate`（单事务，见 §6） | `gate.points` |
| `reply` | viewer 在该主题下有一条可见回帖（不含首帖） | `gate.reply` |

- 条件的参数解析与校验在 `packages/content`（`ConditionSpec`，纯函数）；运行时判定在 `lib/gates/evaluate.ts`（纯函数，`KNOWN_CONDITION_TYPES` 列出认识的类型）。
- **未知条件类型 = 脏数据，一律 fail-closed**：
  · 读取：求值为"暂不可用"，普通观众锁定且拿不到隐藏文本（正文、单门控出口 `getGateContent`、附件放行 `openGateIds` 三条链路一致）；作者与版主仍可见（便于排查）；
  · 购买：`unlockGate` 对"只有未知条件"以及"`all` 模式下混有未知条件"的门控返回 `unavailable`，**不扣费**（后者付款后也永远开不了门，否则就是白扣钱）；`any` 模式下积分条件足以开门，未知条件被忽略，照常可购买。
- 预留设想（**不实现**，仅作将来需要时的参考）：`login`、`follow`、`time`（定时开放）、`badge`。

**永远可见的人**：作者本人；持有 `forum.moderate`（该 post 所在版块作用域）的版主；admin。其余人按条件判定。

## 4. 渲染（SSR，用户相关内容不进缓存）

```
body_md → remark(+指令) → sanitize → 公开 HTML 片段（与用户无关，可缓存）
              ↓ 在 gate 占位处切分
        [html 段] [GateBlock] [html 段] …
```

- `fw-gate` 作为唯一新增的白名单元素，仅允许 `data-id` 属性；其余沿用既有 sanitize 保证。
- 切分结果交给服务端组件渲染：HTML 段直出，`GateBlock` 按状态渲染。
- 一个页面的全部门控**一次批量查询**（元数据 + 当前用户解锁态 + 回复态），无 N+1。
- `GateBlock` 状态：

| 状态 | 展示 |
|------|------|
| 未登录 | 条件说明 + 登录入口 |
| 未满足 | 锁卡片：「付费内容 · 50 积分」+ 购买按钮 / 「回复后可见」+ 跳转回复框 |
| 已购买（或已满足） | 隐藏内容（同一套净化）+ **「已购买」标签**（购买时间可选） |
| 作者 | 「你的付费内容 · N 人购买 · 收益 X」+ 内容 |
| 版主/admin | 「管理员可见」标签 + 内容 |

- 购买后通过 Server Action 重新渲染；**不提供任何会返回隐藏内容的 JSON 接口**。
- 页面已为动态渲染（含会话），无额外缓存失效负担。

### 4.1 实现要点（M5.5 S4-4，读取侧）

- **唯一读取点**：`apps/web/src/lib/gates/service.ts`（`loadGateViews` 页面批量 / `getGateContent` 单门控）。读取分两步——先只读元数据（不含隐藏正文）
  与观众事实，由纯函数 `evaluateGate` 判定；**只有判定为开放的门控才会去取 `hidden_md`**。守卫测试 `hidden-md-guard.test.ts` 断言其他源文件不得引用该列。
- **判定顺序**：作者 → 版主/admin（`forum.moderate`）→ 未登录（一律引导登录）→ 逐条件（`all`/`any`）。失败即封闭：未知条件类型、空条件、非法价格都锁定，
  普通观众看到“该内容暂不可用”，作者与版主仍可见（便于排查）。
- **`reply` 条件只计观众在该主题下 `visible` 的回帖（不含首帖）**；待审核/已隐藏的不算，免得一条垃圾回帖即解锁。
- **价格 0 仍需解锁记录**（登录后点击解锁），不是自动放行。购买按钮提交 Server Action `unlockGateAction`（S4-5），余额不足时禁用。
- `getGateContent` 先确认门控所在的帖子与主题对观众可见（版块可读 + 状态矩阵），不可见一律 `null`——知道门控 id 也读不到。
- 渲染：`PostBody` 按占位切分（`packages/content` 的 `splitByGatePlaceholders`），`GateBlock` 渲染五种状态；占位在 `post_gates` 里查不到对应行时显示“门控数据异常”。

### 4.2 界面提示（M6.5a：只携带时间与计数，不携带正文）

- **「内容更新于」**：`post_gates.content_updated_at` 只在隐藏正文真的变化时推进（写入器的 `UPDATE` 用 `IF(hidden_md <=> 新值, content_updated_at, NOW())`，同一条语句内比较旧值）。改价、改解锁条件不推进；从未变过（NULL）不回填，界面不显示。
  它只是一个时间点，**不含新旧正文、不含差异**。显示规则（`lib/gates/update-note.ts`，纯函数）：作者与版主不显示；已解锁且解锁时间不早于最近更新的读者不显示；其它情况显示，包括未解锁的访客，以及以回复等条件开放、没有解锁时间的读者（无法判断是否看到了最新版本，保守地显示）。
- **改价提示**：编辑页对已有购买记录的门控显示「已有 N 人解锁：改价只影响之后的购买，已购买者不退差价；不能改变解锁方式或删除该门控。」（`edit-composer.tsx`，`role="note"`）。解锁人数经 `unlockCountsByGateKey` 按门控 key 计数，只读计数，不取正文。
- **「回复可见」的去回复引导**：未满足条件的读者在锁卡片上看到「回复本帖后可见 · 去回复」，链接指向 `#reply`。它只是导航，不改变判定（仍按 `reply` 条件计算）。

## 5. 解锁事务（`unlockGate`）

`points` 条件的购买在**单个数据库事务**内完成：

1. 锁读者 `point_accounts` 行（`SELECT … FOR UPDATE`）。
2. 校验：门控存在且未被删除；读者非作者/版主；未解锁（`gate_unlocks` 主键保证幂等）；余额 ≥ 价格。
3. 写 `gate_unlocks`；台账 `spend.gate_unlock`（读者 −price）；台账 `earn.gate_sale`（作者 +price−手续费）。
4. 更新两个账户余额；`unlock_count++`；提交后派发事件 `gate.unlocked`（`{gateId, userId, authorId, price}`）。

- 幂等键：`gate_unlock:{gateId}:{userId}`（读者）、`gate_sale:{gateId}:{userId}`（作者）。
- 价格 0：只写解锁记录，不动台账。
- 手续费：`points.gate_fee_rate`，默认 0（作者收全额）。
- 作者账号已不存在（历史孤儿作者）：收益直接销毁，不写台账。
- 并发双击只扣一次（单测与集成测试覆盖）。

### 5.1 实现要点（M5.5 S4-5，`apps/web/src/lib/gates/unlock.ts`）

- **加锁顺序固定为「门控行 → 账户行（user_id 升序）」，且门控行一开始就拿排他锁。** 早期实现先对门控行 `FOR SHARE`、最后更新 `unlock_count` 时再升级，
  同一门控的多个购买者会互相等待升级而死锁；账户行同理不能用 `INSERT … ON DUPLICATE KEY UPDATE` 当“确保存在 + 加锁”（先共享锁后升级，热门作者账户上必现死锁），
  改为 `SELECT … FOR UPDATE`，不存在才 `INSERT IGNORE` 再加锁（`lib/points/account.ts`）。仍遇死锁则整体重试（最多 3 次）。
- **先拿账户锁，再查是否已解锁**：并发双击的第二个请求阻塞在读者账户锁上，等第一个提交后在锁内读到解锁记录，直接返回“已解锁”不扣费。价格 0 不动账户，靠解锁记录主键兜底。
- **持锁前复核（2026-10-25 审查整改）**：定位通过后、加锁前，事务内先对主题加共享锁，再复核帖子与主题仍然可见，不可见返回 `not_found`、不扣费。锁序「主题 → 门控行 → 账户行」与编辑、状态迁移一致；共享锁会等待进行中的状态迁移（它持有主题排他锁）。
- **事务内不借第二条连接**：渠道解析、权限检查、可见性定位、手续费率全部在事务外完成，否则并发事务占满连接池后互相等待（连接池饥饿，测试里真实复现过）。
- **价格核对**：表单带「买家看到的价格」`expectedPrice`，事务内锁住门控行后与当前价比对，不符返回 `price_changed`、不扣费、不记账；扣款金额因此永远是买家确认过的金额。已解锁者不受影响（不扣费、不报错）。缺失或畸形的 `expectedPrice`（旧页面缓存、手工构造请求）按「价格不符」处理，回到原帖重新确认；`unlockGate` 省略该参数表示不核对，仅限内部调用。M6 的改价功能上线前这一条必须在位。
- **结果为固定错误码**（`login` / `not_found` / `own_content` / `insufficient` / `unavailable` / `price_changed`），页面据此映射文案；返回地址由服务端按门控→帖子→主题→页码算出，不接受表单传入。
- **手续费** = `floor(价格 × 费率)`，作者得其余；费率取 `points.gate_fee_rate`，不在 [0,1) 内一律按 0。作者账号已注销时收益销毁，`author_income` 记 0、不写作者台账。
- **购买不要求其他条件先满足**：`all` 模式下同时要求回复的门控，读者可以先买、之后回复再看全文。作者与版主点购买得到 `own_content`（本来就能看），不写免费解锁记录。

## 5a. 门控附件

附件与隐藏正文**同权**：`attachments.gate_id` 非空的附件，只有该门控对观众开放（作者、版主、已解锁 / 已回复 / 满足条件者）才能看到、才能经 `/files` 取到；
判定复用本文的 `evaluateGate`（`openGateIds`），不另起一套。锁定项在类型上没有文件名、存储键、大小，页面只显示「本帖有 N 个附件需解锁后下载」；
所有引用都绑定了门控的图片同样要过门控，响应 `private, no-store`。读取只经 `lib/gates/attachments.ts`（硬约定 3d）。
完整设计、迁移映射（R1~R5）与测试计划见 [ATTACHMENT-GATES.md](ATTACHMENT-GATES.md)。

### 7.1 实现要点与真实数据验证（M5.5 S3-A）

`packages/content`（`@funwind/content`）已实现 `splitSource` / `assembleSource` / `validateGates`（门控语法）与 `body-segments`（正文按门控占位切段）；**UBB 转换器 `ubbToMarkdown`（v2）在 `migration/src/transform/ubb.ts`**——它只服务一次性导入，运行时不需要，所以不在这个包里。两者的接口契约由 `packages/content/src/syntax-contract.ts` 的语法契约连接（转换器产出什么 Markdown、渲染器必须渲染出什么 HTML）。

- **门控身份用 `gate_key`**（首轮 v2 曾用 `post_id × 16 + seq` 这类 id 公式，已在 v2.1 废除：运行时不应理解迁移用的 id 公式）。
  迁移按帖内出现顺序生成 `a1 a2 …`；单帖门控上限 15 个，超限抛 `RangeError`。迁移的可重复性靠「清空后按确定顺序重导」。
- **位置规则**：门控只在文档顶层生效。包在样式标签（`[color]`/`[align]` 等）、未知标签或**未闭合**标签里的门控被提升为顶层块，两侧文本各自保留样式；
  位于**真正闭合**的 `[quote]`/`[list]`/`[table]` 内的门控内容**丢弃并留提示**（那是别人对原文的引用，宁可丢也不放进公开正文）。
- **失败即封闭**：门控标签缺少闭合（`[sell=5,]` 之后没有 `[/sell]`）时，从该标签到所在容器末尾的内容都归入隐藏内容，
  **绝不把子节点渲染进公开输出**。旧库实证：tid 2023 的未闭合 `[sell]` 有 22 条购买记录，说明旧站确实把它当付费帖处理；仍记 `gate-unclosed` 告警供站长复核。
- **泄露不变量**（性质测试，400 组随机嵌套，约四分之一的门控故意不写闭合标签）：被拆出的隐藏内容绝不出现在公开 `md` 中。
- **门控优先（交叉嵌套）**：非门控的闭合标签不得越过尚未闭合的门控。旧帖里 `[color][sell]…[/color]…[/sell]` 这类交叉写法，
  若按普通标签处理会把门控弹出栈，其后本该隐藏的内容落到公开区；现在把该闭合标签当字面量留在隐藏内容里，门控边界不变。
  没有对应开标签的 `[/sell]`/`[/post]`/`[/hide]` 直接丢弃，不在正文里露出。
- **表格与门控**：表格对门控位置透明，单元格里的门控占位**提升到表格之后**，内容不丢（旧帖常把「下载链接」放进未闭合的表格里）。
  同时修复了表格被渲染两次导致门控重复/孤立的缺陷。
- **真实旧库验证**（36,715 条正文，迁移 v2 全量导入后的最终数字）：零异常；门控 664 个（积分 311，回复可见 353）；
  汉字/假名保留率 101.43%；仅 2 处嵌套门控被丢弃（发帖模板里的空 `[hide]` 示例）；遗留表情码删除 197 处；价格 ≥ 9999 重置为免费 58 处。
- **v1 转换器的数据丢失缺陷（已在 v2 修复）**：`[attachment=N]` 等无闭合标签会把其后全部正文吞成子节点并丢弃
  （`"[attachment=7] 后文"` 只剩附件链接）。v1 迁移的开发库 `content_md` 因此存在截断；已在 M5.5 S3-B 全量重导后消除，之后又在 M5.6 S1b-3 再次重导（见下）。
- **M5.6 S1b-3 对转换器的补充**（数字见 CHANGELOG 与 `verify:render` / `verify:fidelity`）：普通文本里的 Markdown 特殊字符现在会转义（`5*3=15`、`~~心情~~`、行首 `#`/`>`/`-` 不再被解析成强调 / 删除线 / 标题 / 引用 / 列表）；引用 / 列表 / 表格前后留空行；未知且未闭合的方括号词（`[QYsub]`）字面保留；强调内容以标点开头或结尾时输出 `<strong>` / `<em>` / `<del>`。上面「真实旧库验证」的数字是 M5.5 时的快照，门控数量与位置规则不受这些补充影响（`verify:migration` 110 项对账仍全过）。

## 9. 编辑器契约（M6 选型）

M5.5 固定三样契约：**围栏语法、存储拆分、`packages/content` 接口**。无论编辑器怎么变，序列化一律经 `packages/content`，保证线上保存与迁移同一套语法。

**选型已定（E0 spike，2026-10-24，记录见 [spikes/E0-editor-selection.md](spikes/E0-editor-selection.md)）：Tiptap v3（所见即所得，默认）+ CodeMirror 6（源码模式，一键切换）**。要点：
- 门控在所见即所得里是带「付费 / 回复可见」下拉与价格输入的可视块；序列化为 `:::gate{key="…" unlock="…" price="…"}`。编辑器端的 marked 分词器只服务编辑体验，**保存时以服务端 `splitSource` 为准**。
- Tiptap 官方 Markdown 基于 marked，与站点渲染器（remark / micromark）语义不完全一致，所以：**预览走服务端渲染**（用站点真实渲染器），往返不等价的旧帖**强制进源码模式**，未编辑不重新序列化。
- 必须覆盖 marked 的 `del` 分词器（只放行 `~~`）：迁移库有 1136 篇用单个 `~` 表语气。
